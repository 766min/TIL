# PART 1. 함수의 정의, 실행 과정 및 고급 함수 기법

### | 함수의 구성 요소 |

```javascript
// square 함수 정의
function square(x) {
    return x * x; // 전달받은 매개변수 x를 제곱하여 결과를 반환합니다.
}

// square 함수 호출
square(5); // 인수 5를 전달하며 함수를 실행합니다.
```

- **함수 이름** : `square`. 정의된 함수를 식별하고 호출할 때 쓰는 이름.
- **매개변수(Parameter)** : `x`. 함수 외부에서 내부로 데이터를 전달받기 위해 함수 정의 시 선언해두는 임시 변수.
- **함수 바디(Function Body)** : `{ return x * x; }` 영역. 실제로 수행할 연산 로직.
- **반환값(Return Value)** : `return` 뒤에 오는 `x * x`. 함수 실행을 끝마치고 호출처로 돌려주는 결과 데이터.
- **인수(Argument)** : 호출 시 넣은 `5`. 함수를 실제로 호출할 때 매개변수 자리에 넣어주는 실제 값.

- 매개변수와 인수를 계속 헷갈렸는데, "함수를 정의할 때 자리만 잡아둔 상자"가 매개변수, "그 상자에 실제로 담기는 물건"이 인수라고 구분하니 명확해졌다.

##### | 함수 호출과 제어 흐름 |

- 함수를 실행하려면 함수 이름 뒤에 호출 연산자 `()`를 붙여야 한다. **호출 연산자가 없으면 함수를 실행하는 게 아니라 함수 객체 자체를 가리키게 된다.**

```javascript
console.log("1. 함수 호출 전");

const message = getGreeting("이용교");

console.log("4. 함수 호출 완료 및 결과 출력:", message);

function getGreeting(name) {
    console.log("2. 함수 실행 시작");
    const result = `안녕하세요, ${name}님.`;
    console.log("3. 함수 실행 종료 및 반환");
    return result; // 호출부로 결과값을 반환하며 복귀
}
```

- 함수가 호출되면 프로그램의 실행 제어권이 호출부에서 함수 정의부로 넘어갔다가, 반환값을 들고 다시 호출부로 복귀한다. 콘솔 로그 순서가 1 → 2 → 3 → 4로 찍히는 게 이 흐름을 그대로 보여준다.

##### | 인수의 유연성 — 기본값과 가변 매개변수 |

- 자바스크립트는 매개변수 개수와 인수 개수가 정확히 안 맞아도 에러 없이 유연하게 동작한다.

```javascript
// 매개변수 기본값 (b에 값이 안 오면 기본값 1 적용)
function multiply(a, b = 1) {
    return a * b;
}
console.log(multiply(5, 3)); // 15
console.log(multiply(5));    // 5 (b는 기본값 1)

// 나머지 매개변수(Rest Parameter) — 가변 개수의 인수를 진짜 배열로 묶음
function sumAll(...numbers) {
    let total = 0;
    for (let i = 0; i < numbers.length; i++) {
        total += numbers[i];
    }
    return total;
}
console.log(sumAll(1, 2, 3, 4, 5)); // 15
```

- `arguments` 객체 : 함수 호출 시 전달된 모든 인수가 자동으로 담기는 유사 배열 객체. 과거에 주로 쓰였다.
- `...numbers`(나머지 매개변수) : `arguments`의 현대적 대체. 매개변수 이름 앞에 점 3개를 붙이면 들어오는 인수들을 **진짜 배열**로 묶어준다. `arguments`는 유사 배열이라 배열 메서드(map, filter 등)를 바로 못 쓰지만, 나머지 매개변수는 진짜 배열이라 바로 쓸 수 있다는 차이가 있다.

### | 함수 정의 방식 — 선언문 vs 표현식 |

- 자바스크립트는 함수를 만드는 방식이 두 가지로 나뉘고, **호이스팅 여부가 다르다는 게 핵심 차이**다.

##### | 함수 선언문 — 호이스팅 됨 |

```javascript
// getArea 함수를 선언부보다 윗줄에서 먼저 호출
console.log("선언문 호출 결과:", getArea(5, 10)); // 50

function getArea(width, height) {
    return width * height;
}
```

- 엔진이 스크립트를 실행하기 전 "평가 단계"에서 함수 선언 자체를 메모리에 먼저 통째로 등록해두기 때문에, 실제 코드 위치보다 윗줄에서 호출해도 정상 동작한다.

##### | 함수 표현식(함수 리터럴) — 호이스팅 제한됨 |

```javascript
try {
    console.log(getVolume(5, 10, 2)); // 할당 전 호출 시도
} catch (error) {
    console.log("할당 전 호출 에러:", error.message);
    // "Cannot access 'getVolume' before initialization"
}

const getVolume = function(width, height, depth) {
    return width * height * depth;
};

console.log(getVolume(5, 10, 2)); // 100 — 할당 후엔 정상 호출
```

- 익명 함수를 만들어서 변수에 할당하는 방식. 변수 선언 자체는 인지되지만, **실제 함수 할당은 런타임(실행 단계)에서야 순차적으로 일어난다.** 그래서 할당 코드 이전에 호출하면 ReferenceError가 난다.
- 정리하면: 함수 선언문은 "정의 전체"가 미리 등록되지만, 함수 표현식은 "변수 이름표"만 미리 만들어질 뿐 안의 함수는 그 줄에 도달해야 채워진다.

### | 값으로서의 함수 — 일급 객체(First-Class Object) |

- 자바스크립트에서 함수는 단순한 "특수 제어 명령"이 아니라, 숫자나 문자열처럼 메모리에 기록되고 자유롭게 전달될 수 있는 일반 데이터와 동등한 **값(Value)**으로 취급된다. 이를 **일급 객체(일급 시민)**라고 부른다.

##### | 용어의 유래 |

- "일급 시민"은 식민지 시대·인권 운동 등에서 쓰이던 "이등 시민(Second-class citizen)"과 대비되는 사회학적 개념이다. 이등 시민이 권리를 제한받는 존재라면, 일급 시민은 아무런 차별 없이 모든 권리를 동등하게 누리는 존재다.
- 전통적인 언어(C, 과거의 Java 등)에서 함수는 "이름을 불러서 실행"하는 제한된 권리만 가진 이등 시민에 가까웠다. 영국의 컴퓨터 과학자 크리스토퍼 스트레이치가 정의한 것처럼, 자바스크립트의 함수는 일반 값과 완전히 동등한 권리를 갖는다.

##### | 일급 객체의 3대 권리 |

| 일반 값 (숫자 10) | 권리 | 자바스크립트 함수 |
| --- | --- | --- |
| `const num = 10;` | 1. 변수에 담기 | `const myFunc = function() {};` |
| `console.log(10);` | 2. 다른 함수의 인자로 넘기기 | `calculator(10, 20, add);` — **콜백 함수** |
| `return 10;` | 3. 함수에서 리턴하기 | `return function() {};` |

- 인수로 전달되어 다른 함수 내부에서 호출되는 함수를 **콜백 함수(Callback Function)**라고 부른다. `map`, `filter`, `setTimeout`에 넘기는 함수들이 전부 콜백이다.

### | 화살표 함수(Arrow Function) |

- `function` 대신 `=>`를 써서 함수를 간결하게 쓰는 단축 문법. 주로 일회성 콜백을 짧게 쓸 때 쓴다.

```javascript
// 표준 형태
const add = (a, b) => {
    return a + b;
};

// 매개변수가 1개면 소괄호 생략 가능
const square2 = x => {
    return x * x;
};

// 한 줄 return이면 중괄호+return 동시 생략
const multiply = (a, b) => a * b;

// 둘 다 적용
const double = x => x * 2;

// 매개변수가 없을 땐 소괄호를 생략할 수 없다
const sayHello = () => "안녕하세요";
```

##### | 화살표 함수가 못 하는 것 3가지 |

- **생성자 함수 사용 불가** : 자체 `prototype` 객체가 없어서 `new`로 인스턴스를 만들 수 없다.
- **`arguments` 객체 미지원** : 유사 배열 `arguments`가 없다. 여러 인수를 받으려면 나머지 매개변수(`...args`)를 대신 써야 한다.
- **`yield` 사용 불가** : 제너레이터 함수로 만들 수 없다.

##### | 일반 함수 vs 화살표 함수 — this 바인딩의 결정적 차이 |

```javascript
const user = {
    name: "이용교",
    regularGreet: function() {
        console.log("일반 메서드 this.name:", this.name); // user 참조

        const innerFunc = function() {
            console.log("중첩 일반 함수 this:", this); // 전역(window/global) 참조
        };
        innerFunc();
    },
    arrowGreet: function() {
        const innerArrow = () => {
            console.log("중첩 화살표 함수 this.name:", this.name);
            // arrowGreet의 this(=user)를 그대로 물려받음
        };
        innerArrow();
    }
};

user.regularGreet();
user.arrowGreet();
```

출력:
```
일반 메서드 this.name: 이용교
중첩 일반 함수 this: <ref *1> Object [global] { ... }
중첩 화살표 함수 this.name: 이용교
```

- `this`는 "함수를 호출한 주체(객체)"를 가리키는 특별한 키워드다.
- **일반 함수** : 호출되는 방식에 따라 `this`가 동적으로 바뀐다. 특히 안에서 일반 함수로 한 번 더 감싸면(`innerFunc`), 그 함수는 객체의 메서드로 호출된 게 아니라 그냥 단독 호출된 것이라 `this`가 전역을 가리켜버린다 — 이게 일반 함수 콜백에서 자주 나는 버그 원인이다.
- **화살표 함수** : 스스로 `this`를 결정하지 않는다. 함수가 **작성된 시점의 상위 스코프**의 `this`를 그대로 가져와 고정해서 쓴다. 그래서 `innerArrow`는 자신을 감싼 `arrowGreet`의 `this`(=user)를 그대로 쓴다.

### | 자바스크립트 실행 평가 과정과 클로저 |

##### | 엔진의 2단계 처리 |

1. **평가 단계(Creation Phase)** : 코드를 한 줄씩 바로 실행하지 않고 전체 구조를 먼저 훑는다. 이 과정에서 변수 선언과 함수 식별자를 메모리에 미리 매핑해둔다 — 이게 **호이스팅**의 정체다.
2. **실행 단계(Execution Phase)** : 평가가 끝나야 첫 줄부터 순차 실행하며 변수에 실제 값을 채우고 함수를 호출한다.

##### | 호출 스택(Call Stack) — 후입선출(LIFO) |

- **선입선출(FIFO)** : 먼저 들어간 게 먼저 나온다. 카페 줄 서기와 같은 구조.
- **후입선출(LIFO)** : 나중에 들어간 게 먼저 나온다. 프링글스 통에 쌓아 넣은 과자를 꺼낼 때 맨 위(가장 나중에 넣은 것)부터 나오는 것과 같은 구조.
- 자바스크립트의 호출 스택은 LIFO로 동작한다. 함수가 호출되면 실행 정보를 스택 맨 위에 쌓고(**Push**), 함수가 끝나 값을 반환하면 스택 맨 위에서 제거되며(**Pop**) 바로 아래 있던 함수로 실행이 복귀한다.

```javascript
function first() {
    console.log("2. first 함수 시작");
    second(); // second를 스택에 Push
    console.log("4. first 함수 종료");
}

function second() {
    console.log("3. second 함수 실행 및 종료");
    // 종료와 동시에 스택에서 Pop, first로 복귀
}

console.log("1. 전역 실행 시작");
first(); // first를 스택에 Push
console.log("5. 전역 실행 종료");
```

##### | 클로저(Closure) |

- 함수가 호출 스택에서 제거(Pop)되면 그 안의 지역 변수는 원칙적으로 소멸한다. **그런데** 외부 함수가 끝나 소멸하더라도, 그 안에서 반환된 내부 함수가 외부 함수의 지역 변수를 계속 참조하고 있다면, 그 변수 공간은 메모리에서 해제되지 않고 유지된다. 이 현상을 **클로저**라고 한다.

```javascript
function createSecureStorage() {
    let secureValue = "보안용 내부 데이터"; // 외부에서 직접 접근 불가능한 지역 변수

    return {
        getData: function() {
            return secureValue; // 클로저 덕분에 외부 함수 소멸 후에도 추적 가능
        },
        setData: function(newValue) {
            secureValue = newValue;
        }
    };
}

const myStorage = createSecureStorage();

console.log(myStorage.getData()); // "보안용 내부 데이터"
myStorage.setData("수정된 보안 데이터");
console.log(myStorage.getData()); // "수정된 보안 데이터"

try {
    console.log(secureValue); // 바깥에서 직접 접근 시도 → 에러
} catch (e) {
    console.log("직접 접근 실패:", e.message); // "secureValue is not defined"
}
```

- `getData`/`setData`라는 통로로만 `secureValue`에 접근할 수 있고, 바깥에서 변수 이름으로 직접 건드릴 수는 없다. 정보 은닉을 구현하는 대표적인 패턴이다.

### | 명시적 this 바인딩 — call, apply, bind |

- 함수 내부의 `this` 주체를 런타임에 인위적으로 결정하고 싶을 때 쓰는 3가지 내장 메서드.

| 메서드 | 즉시 실행? | 인수 전달 방식 |
| --- | --- | --- |
| `call` | O | 두 번째 인수부터 하나씩, 쉼표로 나열 |
| `apply` | O | 두 번째 인수에 배열 하나로 묶어서 전달 |
| `bind` | X (새 함수를 반환) | `call`처럼 하나씩 나열 |

```javascript
function introduce(greeting, symbol) {
    console.log(`${greeting}${symbol} 저는 ${this.name}입니다.`);
}

const personA = { name: "이용교" };

// call — 즉시 실행, 인수를 개별로
introduce.call(personA, "안녕하세요", "!"); // 안녕하세요! 저는 이용교입니다.

// apply — 즉시 실행, 인수를 배열로
introduce.apply(personA, ["반갑습니다", "."]); // 반갑습니다. 저는 이용교입니다.

// bind — 즉시 실행 X, this가 고정된 새 함수를 반환
const bindOnlyThis = introduce.bind(personA);
bindOnlyThis("안녕하세요", "!"); // 안녕하세요! 저는 이용교입니다.

// bind는 일부 매개변수까지 미리 고정해둘 수 있다
const bindWithGreeting = introduce.bind(personA, "안녕하십니까");
bindWithGreeting("?"); // 안녕하십니까? 저는 이용교입니다.
```

- `call`/`apply`는 이름은 다르지만 "즉시 실행 + this 고정"이라는 점은 같고, 인수를 나열하는지(call) 배열로 묶는지(apply)만 다르다. `bind`는 실행이 아니라 **this가 영구히 박제된 복제 함수를 만드는 것**이라 나머지 둘과 성격이 다르다.

# PART 2. 프로토타입 기반 상속 및 클래스 모델링

### | 객체를 만드는 세 가지 방법 |

- 표현 방식은 다르지만 내부적으로는 전부 같은 상속 시스템(프로토타입) 위에서 동작한다.

```javascript
// ① 객체 리터럴 — 중괄호로 즉석에서 하나 만들기
const cardLiteral = { suit: "하트", rank: "A" };

// ② 생성자 함수 — 규격을 정의하고 new로 동일 구조 여러 개 생성
function Card(suit, rank) {
  this.suit = suit;
  this.rank = rank;
}
const cardConstructor = new Card("클로버", "7");

// ③ Object.create() — 부모 객체를 직접 지정해서 상속 관계 명시
const parentPrototype = {
  describe() { return `이 카드는 ${this.suit} ${this.rank}입니다.`; }
};
const cardCreate = Object.create(parentPrototype);
cardCreate.suit = "다이아몬드";
cardCreate.rank = "K";
console.log(cardCreate.describe()); // "이 카드는 다이아몬드 K입니다."
```

### | 메서드를 어디에 정의할 것인가 — 프로토타입과 class 문법의 등장 배경 |

##### | 문제: 생성자 함수 안에 메서드를 직접 정의하면? |

```javascript
function Circle(center, radius) {
  this.center = center;
  this.radius = radius;
  this.area = function() { return Math.PI * this.radius * this.radius; };
}

const bad1 = new Circle({x: 0, y: 0}, 2.0);
const bad2 = new Circle({x: 0, y: 1}, 3.0);

console.log(bad1.area === bad2.area); // false
```

- `new`로 인스턴스를 만들 때마다 `area` 함수가 **매번 새 메모리에 새로 생성**된다. 동일한 기능인데 인스턴스 개수만큼 중복 생성되는 메모리 낭비다.

##### | 해결: 공통 메서드는 prototype에 딱 한 번만 등록 |

```javascript
function Circle(center, radius) {
  this.center = center;
  this.radius = radius;
}

// 공통 메서드는 생성자 함수의 prototype 공간에 딱 한 번만 등록
Circle.prototype.area = function() {
  return Math.PI * this.radius * this.radius;
};

const circle1 = new Circle({x: 0, y: 0}, 2.0);
const circle2 = new Circle({x: 0, y: 1}, 3.0);

// 개별 데이터는 다르지만 메서드는 원형(prototype) 하나를 공유
console.log(circle1.area === circle2.area); // true
```

- 모든 인스턴스가 `__proto__`라는 프로토타입 링크를 통해 **단 하나의 함수**를 공유하게 만들어 메모리를 아낀다.

##### | class 문법 — 가독성을 위한 포장 |

```javascript
class Circle {
  constructor(center, radius) {
    this.center = center;
    this.radius = radius;
  }

  // 클래스 블록 안의 메서드는 엔진이 자동으로 Circle.prototype.area로 등록해줌
  area() {
    return Math.PI * this.radius * this.radius;
  }
}

const modern1 = new Circle({x: 0, y: 0}, 2.0);
const modern2 = new Circle({x: 0, y: 1}, 3.0);

console.log(modern1.area === modern2.area); // true — 프로토타입 이점 그대로 유지
console.log(typeof Circle); // "function" — 클래스의 본질은 결국 함수다
```

- 기존 프로토타입 방식은 효율적이지만 생성자 함수 정의와 `prototype` 등록 코드가 따로 떨어져 있어 구조를 한눈에 보기 어려웠다. `class`는 메서드를 블록 안에 모아 쓰기만 하면 엔진이 알아서 `prototype`에 등록해주는 **문법적 편의(Syntactic Sugar)**다 — 내부 동작은 그대로고 겉모습만 깔끔해진 것.

##### | class 대응 관계 & 생성자 함수와의 차이 |

- `class Circle` ↔ `function Circle` (식별자 선언부)
- `constructor(...)` ↔ 생성자 함수의 본문 (속성 초기화 로직)
- `area() {...}` ↔ `Circle.prototype.area = ...` (프로토타입 등록)
- 메서드 축약 표기법 : `area: function() {}`이 아니라 `area() {}`처럼 `function`과 콜론을 생략해서 쓴다.

| 구분 | 생성자 함수 | class |
| --- | --- | --- |
| `new` 없이 호출 | 에러 없이 조용히 전역 객체를 오염시킴 (디버깅 어려움) | `TypeError` 발생 — 오동작을 원천 차단 |
| 호이스팅 | 함수 선언문이라 최상단에서도 호출 가능 | 선언 전 호출 시 `ReferenceError` |

### | 프로토타입과 프로토타입 체인 |

- 자바스크립트의 모든 객체는 상위 객체를 가리키는 내부 링크를 갖고 있고, 자신에게 없는 속성에 접근하면 이 링크를 따라 상위로 검색해 올라간다.

##### | `[[Prototype]]`과 `__proto__` |

- **`[[Prototype]]`** : 객체가 생성될 때 부여되는 내부 슬롯. 자신에게 자원을 물려준 상위 프로토타입 객체의 주소를 가진다. 생성자 함수도 객체이므로 자신만의 `prototype` 객체를 갖고, 이를 통해 인스턴스들과 연결된다.
- **`__proto__`** : 그 내부 프로퍼티에 접근할 수 있게 노출된 접근자. 실무에서 직접 조작하는 건 권장되지 않고, 대신 `Object.getPrototypeOf()`를 쓰는 게 표준이다.

```javascript
const emptyObj = {};
console.log(Object.getPrototypeOf(emptyObj) === Object.prototype); // true
```

##### | 프로토타입 체인을 통한 탐색 |

```javascript
const person1 = {
  name: "Tom",
  sayHello() { console.log("Hello! " + this.name); }
};

const person2 = {
  name: "Huck"
};

person2.__proto__ = person1; // 학습 목적의 직접 연결

// person2엔 sayHello가 없지만, 상위 프로토타입인 person1에서 찾아 실행
person2.sayHello(); // "Hello! Huck"
```

##### | `new` 연산자 호출 시 내부에서 일어나는 4단계 |

1. **빈 객체 생성** — `const newObj = {};`
2. **프로토타입 링크 연결** — `newObj.__proto__ = 생성자.prototype;`
3. **this 바인딩 및 함수 실행** — `생성자.apply(newObj, arguments);`
4. **인스턴스 반환** — `return newObj;`

- `new Card(...)`를 실행하는 순간 이 4단계가 자동으로 일어나서, 새로 만든 객체가 자동으로 `Card.prototype`과 연결되는 것이다.

### | 상속 구현 — 생성자 함수 vs class |

##### | 생성자 함수 기반 상속 |

```javascript
// 부모 생성자
function Ellipse(a, b) {
  this.a = a; // 장축 반지름
  this.b = b; // 단축 반지름
}
Ellipse.prototype.getArea = function() {
  return Math.PI * this.a * this.b;
};

// 자식 생성자
function Circle(r) {
  // 부모 생성자를 호출해 a, b를 r로 초기화 ("생성자 빌려오기")
  Ellipse.call(this, r, r);
}

// 자식의 prototype을 부모의 prototype과 체인으로 연결
Circle.prototype = Object.create(Ellipse.prototype, {
  constructor: {
    value: Circle, // 프로토타입 교체 시 끊어지는 생성자 연동 복원
    writable: true,
    enumerable: true,
    configurable: true
  }
});

const c = new Circle(5);
console.log(c.getArea());
```

- **생성자 빌려오기(`Ellipse.call(this, r, r)`)** : 부모 생성자의 속성 초기화 로직을 자식 안에서 재사용.
- **프로토타입 명시적 연결(`Object.create`)** : 자식의 `prototype`에 부모의 `prototype`을 참조하는 새 객체를 할당해 체인에 등록.

##### | class 기반 상속 — 훨씬 직관적 |

```javascript
class Ellipse {
  constructor(a, b) {
    this.a = a;
    this.b = b;
  }

  getArea() {
    return Math.PI * this.a * this.b;
  }
}

class Circle extends Ellipse {
  constructor(r) {
    super(r, r); // 부모 생성자 호출 — a, b를 r로 초기화
  }

  getArea() {
    const area = super.getArea(); // 부모 메서드 재사용
    console.log(`반지름이 ${this.a}인 원의 넓이를 클래스로 계산합니다.`);
    return area;
  }
}

const c = new Circle(5);
console.log(c.getArea());
```

- **`extends`** : `class 자식 extends 부모` 형태로 프로토타입 체인을 선언적으로 구성.
- **`super()`** : 자식의 `constructor` 안에서는 `this`에 접근하기 전에 반드시 먼저 호출해야 한다. 부모 생성자를 실행하는 역할.
- **`super.메서드()`** : 부모 메서드를 자식에서 재정의(오버라이딩)하면서도, 그 안에서 부모의 원래 기능을 가져와 재사용할 수 있다.
- 생성자 함수 방식과 비교하면 `Ellipse.call(this, ...)` + `Object.create(...)` 두 단계가 `extends` + `super()`로 압축된 셈이다.

### | 프로퍼티 속성 제어와 객체 잠금 |

##### | 데이터 프로퍼티 vs 접근자 프로퍼티 |

- **데이터 프로퍼티** : 키에 실제 값이 직접 연결된 일반적인 프로퍼티.
- **접근자 프로퍼티** : 자체 값이 없고, 읽고 쓸 때 각각 실행되는 게터(getter)·세터(setter) 함수로 구성된 프로퍼티.

##### | 디스크립터 조회 — `Object.getOwnPropertyDescriptor` |

```javascript
const userProfile = { nickname: "Alice" };

const descriptor = Object.getOwnPropertyDescriptor(userProfile, "nickname");
console.log(descriptor);
```

##### | 프로퍼티 3대 속성과 `Object.defineProperty` |

| 내부 속성 | 설명 | false일 때 |
| --- | --- | --- |
| `writable` | true일 때만 값 수정 가능 | 값 변경 불가 |
| `enumerable` | true일 때만 `for...in`, `Object.keys()` 등에서 열거됨 | 루프 탐색에서 제외 |
| `configurable` | true일 때만 삭제·속성 재설정 가능 | 삭제 및 재설정 불가 |

```javascript
const bankAccount = {};
Object.defineProperty(bankAccount, "balance", {
  value: 70000,
  writable: false,
  enumerable: true,
  configurable: false
});

bankAccount.balance = 10;   // 변경 무시
delete bankAccount.balance; // 삭제 무시
console.log(bankAccount.balance); // 70000 유지
```

##### | 객체 잠금 3단계 |

```javascript
// ① 확장 방지 — 속성 "추가"만 막음
const character = { job: "마법사" };
Object.preventExtensions(character);
character.level = 99;      // 무시됨
character.job = "흑마법사"; // 수정은 가능
delete character.job;      // 삭제도 가능

// ② 밀봉(seal) — 추가 + 삭제 막음, 값 수정은 허용
const response = { status: 200 };
Object.seal(response);
response.data = "OK";       // 추가 불가
delete response.status;     // 삭제 불가
response.status = 500;      // 수정은 가능

// ③ 동결(freeze) — 추가 + 삭제 + 수정 전부 막음
const systemConfig = { host: "localhost" };
Object.freeze(systemConfig);
systemConfig.host = "192.168.0.1"; // 수정 불가
systemConfig.port = 3000;          // 추가 불가
delete systemConfig.host;          // 삭제 불가
console.log(systemConfig.host); // "localhost" 그대로
```

- 강도 순서 : `preventExtensions`(추가만 막음) < `seal`(추가+삭제 막음) < `freeze`(전부 막음).

### | 데이터 직렬화와 JSON을 활용한 깊은 복사 |

##### | JSON.stringify / JSON.parse |

```javascript
const developer = {
  nick: "Neo",
  age: 30,
  isLeader: false,
  coding() { console.log("Coding..."); } // 직렬화 대상에서 제외됨
};

const jsonString = JSON.stringify(developer);
const restoredObj = JSON.parse(jsonString);
console.log(restoredObj.nick); // "Neo"
```

- JSON 표기 규칙 : 프로퍼티 이름(Key)은 반드시 큰따옴표로 감싸야 한다. **함수와 `undefined`는 직렬화 대상에서 제외된다.**

##### | 얕은 복사의 함정과 JSON을 이용한 깊은 복사 |

```javascript
const stageInfo = {
  stageName: "용암지대",
  monsters: { elite: "드래곤", normal: "슬라임" } // 중첩 객체
};

// JSON 문자열로 변환했다가 다시 파싱 → 참조가 끊긴 독립적 복사본
const deepCloneStage = JSON.parse(JSON.stringify(stageInfo));

deepCloneStage.monsters.elite = "오우거";

console.log(stageInfo.monsters.elite);     // "드래곤" — 원본 유지
console.log(deepCloneStage.monsters.elite); // "오우거" — 복사본만 변경
```

- 중첩된 객체를 `const copy = original`처럼 단순 대입하면 참조 주소만 복사되는 **얕은 복사**가 일어나 복사본을 고치면 원본까지 같이 바뀐다. `JSON.stringify` → `JSON.parse`를 거치면 참조를 완전히 끊은 **깊은 복사**본을 만들 수 있다. (다만 함수·undefined가 있는 객체는 이 방법으로 못 옮긴다는 점은 유의)

Q4. 자식 클래스의 `constructor` 내부에서 부모 클래스의 속성을 초기화하고 `this`에 정상적으로 접근하기 위해 반드시 먼저 호출해야 하는 구문은 무엇입니까?

a. `extends`

b. `super()`

c. `Object.create()`

d. `Object.getPrototypeOf()`

내 제출 답안 : a. (오답 ❌)

-> 자식 클래스의 `constructor` 내부에서는 `this`를 사용하기 전에 반드시 `super()`를 호출하여 부모 생성자의 초기화 로직을 먼저 실행해야 한다. `extends`는 상속 관계를 선언하는 키워드일 뿐이며, 나머지 선지는 클래스 상속에서 필수 호출 구문이 아니다.

Q5. 객체 내부에 중첩된 객체가 있을 때, `JSON.stringify`와 `JSON.parse`를 연속으로 적용하여 참조 주소를 공유하지 않는 완전히 독립적인 복사본을 만드는 기법을 무엇이라고 합니까?

내 제출 답안 : 캡슐화 (오답 ❌)

[ 정답 ] 깊은 복사

-> 중첩 객체를 단순 대입하면 참조 주소만 복사되는 얕은 복사가 발생하지만, `JSON.stringify`로 문자열화한 뒤 `JSON.parse`로 다시 파싱하면 참조를 공유하지 않는 독립적인 복사본, 즉 깊은 복사가 생성된다.
