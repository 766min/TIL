# PART 1. 브라우저는 HTML을 받아서 어떻게 화면으로 바꿀까 — 렌더링 파이프라인

### | window라는 이름은 왜 window일까 |

- 지금이야 창을 여러 개 띄우고 분할해서 쓰는 게 당연하지만, "윈도우(Window)"라는 이름은 옛날 컴퓨터 화면이 지금처럼 자유롭게 분할되지 않고 화면 전체가 하나의 네모난 창 단위로 다뤄지던 시절의 관습이 이어진 이름이다. 브라우저를 하나 켜면 그 자체가 하나의 "창(Window)"이고, 그 창 하나마다 전역 객체 `Window`가 하나씩 자동으로 만들어진다.
- 탭을 여러 개 열어놓으면 창(윈도우) 하나 안에 문서(Document)가 여러 개 들어있는 셈이다 — 탭 하나 = 문서(Document) 하나. 그래서 `window` 안에 `document`가 속하는 구조(`window.document`)가 만들어진다.

### | DOM은 HTML 코드 그 자체가 아니다 |

- HTML은 그냥 텍스트 파일이다. 이 텍스트를 브라우저가 프로그램(자바스크립트)이 다룰 수 있는 형태로 바꾸는 과정이 필요한데, 이 변환을 전담하는 게 HTML 파서(Parser)다.
- 파서가 HTML 텍스트를 한 줄씩 해석해서, 그 결과로 만들어내는 것이 DOM(Document Object Model) 트리다. 즉 DOM은 "HTML 텍스트를 해석해서 만든 JSON과 비슷한 객체 구조"라고 이해하면 된다 — HTML 코드 자체가 아니라 그 코드를 해석한 결과물이다.
- 그래서 "페이지 소스 보기(원본 HTML 텍스트)"와 "개발자 도구의 Elements 탭(DOM)"은 서로 다른 것을 보여준다.

| 구분 | 원본 HTML 텍스트 (페이지 소스 보기) | Elements 탭 (DOM) |
| --- | --- | --- |
| 정체 | 서버가 보내준 원본 그대로의 순수 텍스트 파일 | 브라우저가 그 텍스트를 해석해서 만든, 살아있는 구조(객체) |
| 자바스크립트로 바꾸면? | 바뀌지 않는다. 항상 최초 원본 그대로 남아있다 | 실시간으로 바뀐다. 지금 이 순간 화면에 반영된 실제 상태를 보여준다 |

### | 트리 구조는 왜 필요할까 — 탐색 속도 |

- 트리 구조를 굳이 쓰는 이유는 탐색 속도 때문이다. 전화번호부에서 "사"로 시작하는 이름을 찾는다고 생각해 보면, 책을 처음부터 한 장씩 넘기지 않고 책 중앙을 펼쳐서 "사"가 앞쪽에 있는지 뒤쪽에 있는지 먼저 가늠한 뒤, 해당하는 절반만 다시 좁혀 나간다. 이렇게 매번 탐색 범위를 절반씩 줄여나가는 방식이라 전체를 순서대로 다 뒤지는 것보다 훨씬 빠르다 (이런 시간 복잡도를 `O(log n)`이라 부른다).
- DOM도 `body` 안에 `p`가 있고 그 `p` 안에 `span`이 있는 식으로, 태그를 부모-자식 관계의 트리로 구조화해서 관리하기 때문에 특정 요소를 빠르게 찾아 들어갈 수 있다.
- 대신 트리는 "저장 구조"일 뿐 "구축 비용"이 공짜는 아니다. 요소를 새로 추가하거나 삭제할 때마다 트리가 재구성되어야 하므로, 대규모 사이트에서 DOM 조작이 잦아지면 그만큼 느려질 수 있다.

### | 웹 브라우저의 자바스크립트 실행 9단계 순서 |

브라우저가 HTML 문서를 받아와서 화면에 출력하고 자바스크립트를 구동하기까지는 다음과 같은 엄격한 순서가 존재한다.

1. **Window 객체 생성** — 웹 페이지가 열리는 즉시 전역 객체인 Window 객체가 브라우저 탭마다 하나씩 자동으로 만들어진다.
2. **Document 객체 생성 및 로딩 개시** — Document 객체가 Window 객체의 프로퍼티로 생성되며, `document.readyState`가 `"loading"`으로 지정된다.
3. **HTML 구문 분석 및 DOM 트리 구축** — HTML 파서가 문서를 위에서부터 한 줄씩 읽어 내려가며 DOM 트리에 노드를 추가한다. 이 시점에 이미지 등 무거운 리소스는 프리로드 스캐너가 옆으로 빼내어 미리 다운로드를 시작해 둔다(본문 파싱을 막지 않기 위함).
4. **script 요소의 동기적 실행** — 구문 분석 중 `<script>` 태그를 만나면 파싱이 일시적으로 멈추고, 자바스크립트 코드의 다운로드·실행을 마친 뒤에야 파싱이 재개된다. 자바스크립트는 HTML·CSS보다 실행 비용이 무겁고, 아직 뒤쪽 DOM이 만들어지지 않은 상태이기 때문에 `<script>`를 문서 맨 위에 그대로 적어두면 아직 존재하지 않는 버튼 등을 찾다가 실패하는 문제가 생긴다 — 그래서 보통 `<script>`는 `body` 맨 아래에 두거나, `defer` 속성을 붙여 실행 시점 자체를 뒤로 미룬다.
5. **DOM 트리 구축 완료** — 모든 HTML 내용을 다 읽고 구조화가 끝나면 `document.readyState`가 `"interactive"`로 바뀐다. "인터랙티브(상호작용 가능)"하다는 건 "HTML 트리는 다 만들어졌으니 이제 조작해도 된다"는 뜻이고, 아직 외부 CSS·이미지 등은 다운로드 중일 수 있다.
6. **DOMContentLoaded 이벤트 발생** — Document 객체에 DOM 트리 구축 완료를 알리는 이벤트가 발생한다. 이 시점부터는 이미지 로드 여부와 상관없이 요소 조작이 가능하다.
7. **외부 리소스 다운로드 완료 대기** — 3단계 시점부터 미리 받고 있던 이미지 등 외부 리소스의 다운로드가 모두 끝날 때까지 대기한다.
8. **readyState 완료 변경** — 모든 외부 리소스까지 다운로드가 끝나면 `document.readyState`가 `"complete"`로 바뀐다.
9. **Load 이벤트 발생 및 비동기 대기** — Window 객체를 대상으로 `load` 이벤트가 발생하며, 이후부터는 사용자 이벤트나 네트워크 응답을 비동기로 수신하는 대기 상태로 들어간다.

```javascript
// DOM 트리 구축이 끝나 조작이 가능한 시점 (사용자가 오래 기다리지 않고 바로 조작 가능)
document.addEventListener("DOMContentLoaded", () => {
    console.log("1. DOMContentLoaded 발생 - readyState:", document.readyState); // interactive
});

// 이미지 등 외부 리소스까지 완전히 로드된 시점
window.addEventListener("load", () => {
    console.log("2. window load 발생 - readyState:", document.readyState); // complete
});
```

### | 왜 버튼에 이벤트가 안 걸릴 때가 있을까 — 스크립트 실행 시점 문제 |

```javascript
// <script>가 body 상단(버튼 DOM이 아직 안 만들어진 시점)에 있으면
// document.getElementById("swap")가 null을 반환해 아래 코드가 통째로 에러난다.
const buttonEl = document.getElementById("swap");
buttonEl.addEventListener("click", function () {
    const classList = buttonEl.classList;
    if (classList.contains("swap")) {
        classList.remove("swap");
    } else {
        classList.add("wrap"); // ⚠️ 오타: "swap"이 아니라 "wrap"을 추가하고 있다
    }
});
```

- 이 코드가 실습 중에 안 먹혔던 이유는 두 가지가 겹쳐서다.
  1. **실행 순서 문제**: DOM 트리는 위에서 아래로 순서대로 만들어지는데, `<script>`가 버튼(`#swap`)보다 먼저 나와 있으면 스크립트가 실행되는 시점에는 아직 그 버튼의 DOM 노드가 만들어져 있지 않다. `getElementById`는 `null`을 반환하고, `null.addEventListener(...)`는 즉시 에러를 던진다.
  2. **오타 문제**: 클래스를 뺄 때는 `remove("swap")`을 쓰면서 넣을 때는 `add("wrap")`을 써서, 클래스 이름 자체가 서로 다르다. 이러면 토글이 아니라 "swap"은 계속 빠지기만 하고 "wrap"은 계속 쌓이기만 하는 상태가 된다.
- 이 두 문제를 한 번에 피하는 방법은 스크립트를 `DOMContentLoaded` 안에 넣거나 `body` 맨 아래로 옮기는 것, 그리고 클래스 하나를 왔다갔다 시킬 때는 `remove`/`add`를 따로 쓰지 말고 **`classList.toggle("swap")` 하나로 처리**하는 것이다. 이러면 문자열을 두 번 따로 적다가 오타 낼 일 자체가 사라진다.

# PART 2. BOM — 브라우저 객체 모델 (Browser Object Model)

### | window: 최상위 전역 객체 |

- **BOM(Browser Object Model)**은 브라우저 창·주소창·이력창 등 웹 페이지 "바깥"의 브라우저 환경 요소들을 객체로 구조화해 조작할 수 있게 해주는 인터페이스다. `window`가 이 전체의 최상위 객체다.
- `window`는 자바스크립트의 전역 실행 컨텍스트(함수·블록 바깥의 가장 바깥 영역)에서 다음 식별자들과 완전히 동일한 객체를 가리킨다. (단, 일반 독립 창 기준)

| 식별자 | window와 같은 이유 |
| --- | --- |
| `window` | 전역 객체 자신을 가리키는 프로퍼티 |
| `this` | 전역 스코프에서 `this`는 전역 객체(Window)에 바인딩된다 |
| `parent` | 현재 창이 `<iframe>` 내부가 아닌 독립 창이면, 부모 창을 가리키는 `parent` 역시 자기 자신(Window)을 가리킨다 |

```javascript
console.log(window === this);                          // true
console.log(window === parent);                         // true
console.log(window.location === location);               // true — window는 생략 가능
console.log(window.document === document);               // true — document도 사실 window.document의 축약형
```

- `document`, `location`, `history`, `navigator`, `screen` 같은 하위 객체는 원칙적으로 `window.location`처럼 접두어를 붙여 접근하지만, `window`가 전역 객체라 이름을 생략해도 동일하게 동작한다. 즉 `document`는 사실 `window.document`를 줄여 쓴 것이다.

### | window의 하위 객체 5인방 |

| 하위 객체 | 담당 |
| --- | --- |
| `document` | HTML 문서와 관련된 정보·기능 제공 |
| `location` | 주소창(URL)의 경로와 이동 |
| `history` | 현재 탭의 방문 기록 |
| `navigator` | 브라우저 종류·언어·네트워크 상태 등 실행 환경 정보 |
| `screen` | 사용자 모니터 화면의 해상도 정보 |

### | location — 주소창 제어 |

| 메서드/프로퍼티 | 설명 |
| --- | --- |
| `location.href` | 전체 URL을 읽거나 수정. 이 속성에 바로 값을 대입해서 페이지를 이동시키는 경우가 `assign()`보다 오히려 더 흔하다 |
| `location.assign(url)` | 지정한 URL로 이동. **방문 기록이 남아서 '뒤로 가기'로 복귀 가능** |
| `location.replace(url)` | 지정한 URL로 이동하되 **현재 페이지의 방문 기록 자체를 삭제**하고 대체. '뒤로 가기'로 복귀 불가 |
| `location.reload()` | 현재 페이지를 서버에서 다시 읽어와 새로고침 |
| `location.hash` | URL 끝의 `#`으로 시작하는 부분만 반환 |

```javascript
location.assign("https://www.naver.com");  // 이동 + 방문기록 추가(뒤로가기 가능)
location.replace("https://www.naver.com"); // 이동, 방문기록은 삭제(뒤로가기 불가)
```

- URL 뒤에 붙는 두 가지 문자열, **쿼리스트링**과 **해시**는 역할이 완전히 다르다.
  - **쿼리스트링(`?key=value`)**: 편지에 요청사항을 적어서 우체국(서버)에 실제로 보내는 것과 같다. 서버가 이 내용을 보고 응답 내용을 다르게 만들어준다.
  - **해시(`#anchor`)**: 내 책상에 붙여놓은 포스트잇 메모에 가깝다. 서버(우체국)는 이게 붙어있는지조차 모르고, 오직 브라우저(나) 혼자만 참고한다. 주로 브라우저 안에서 스크롤 위치처럼 "이 페이지 안에서만 의미 있는 상태"를 기억해 둘 때 쓴다.

### | history — 방문 기록 제어 |

| 프로퍼티/메서드 | 설명 |
| --- | --- |
| `history.length` | 현재 탭 세션에 쌓인 총 방문 페이지 개수 |
| `history.back()` | 한 단계 이전 페이지로 이동 |
| `history.forward()` | 한 단계 다음 페이지로 이동 |
| `history.go(n)` | n이 음수면 그만큼 뒤로, 양수면 그만큼 앞으로 이동 (예: `history.go(-2)`는 2단계 뒤로) |
| `history.scrollRestoration` | `"auto"`면 이전 스크롤 위치를 기억해 복구, `"manual"`이면 복구하지 않음 |
| `history.pushState(state, title, url)` | 새로고침 없이 세션 기록에 새 상태와 URL을 추가 |

### | navigator / screen |

- **`navigator`**: `navigator.userAgent`(브라우저 종류·버전 식별 문자열), `navigator.language`(설정 언어), `navigator.onLine`(네트워크 연결 여부)를 제공한다. `userAgent` 문자열을 검사해 브라우저 종류별로 분기 처리할 때 쓴다.
- **`screen`**: `screen.width`/`screen.height`(모니터 전체 해상도), `screen.availWidth`/`screen.availHeight`(작업 표시줄을 제외한 실제 가용 해상도)를 제공한다.

### | pageYOffset — 스크롤 위치 추적 |

- `window.pageYOffset`(= `window.scrollY`)은 페이지가 세로로 얼마나 스크롤 됐는지를 픽셀 단위 숫자로 알려주는 프로퍼티다. **읽기 전용**이라 여기에 직접 값을 대입해도(`window.pageYOffset = 500`) 스크롤이 실제로 움직이지는 않는다. 스크롤 위치를 실제로 옮기고 싶으면 `window.scrollTo(x, y)` 같은 별도 메서드를 써야 한다.

```javascript
// 300px 넘게 스크롤하면 '위로 가기' 버튼을 보여주는 실전 패턴
const backToTopBtn = document.querySelector("#backToTop");
window.addEventListener("scroll", () => {
    if (window.pageYOffset > 300) {
        backToTopBtn.style.display = "block";
    } else {
        backToTopBtn.style.display = "none";
    }
});
```

### | 팝업창 제어와 동일 출처 정책(SOP) |

```javascript
let w = open("", "new_page", "width=400,height=300"); // 새 창 열기 → 자식 Window 객체 반환
w.moveTo(100, 150);   // 절대 좌표로 이동
w.resizeTo(500, 400); // 절대 크기로 재조정
w.close();            // 창 닫기
```

- 부모 창은 `open()`이 반환한 변수로 자식 창을 참조하고, 자식 창은 `window.opener`로 부모 창을 참조한다.
- 다만 서로 다른 출처(도메인)의 창끼리는 자바스크립트로 서로의 문서를 마음대로 조작할 수 없다. **동일 출처 정책(SOP, Same-Origin Policy)**이 프로토콜·포트 번호·호스트 이름(도메인) 3가지가 모두 일치할 때만 상호 접근을 허용하기 때문이다 — 브라우저의 렌더링 엔진 종류가 같은지는 이 조건에 포함되지 않는다.

# PART 3. DOM — 문서 객체 모델 (Document Object Model)

### | DOM은 document의 줄임말이 아니다 |

- **DOM**은 "document"의 줄임말이 아니라 **D**ocument(html 문서) **O**bject(그 문서를 프로그램이 다룰 수 있는 객체 형태로) **M**odel(모델)의 약자다. 즉 DOM은 "HTML 문서를 트리 구조의 객체로 표현하는 방식(개념) 그 자체"를 가리키는 말이고, `document`는 그 방식에 따라 실제로 만들어진 결과물이다.
- 비유하자면 DOM은 지도를 만드는 **설계도(규격)**이고, `document`는 그 설계도대로 실제 그려진 **진짜 지도 한 장**이다.

### | 트리 구조와 노드 |

- 트리 구조는 나무를 거꾸로 뒤집어 놓은 모양이다. 하나의 뿌리(시작점)에서 가지가 뻗어나가고, 그 가지에서 다시 가지가 뻗어나가는 구조를 말한다(단순히 계층으로 이어지는 구조라면 다 트리 구조다 — 예: 컴퓨터의 파일 탐색기 폴더 구조도 트리다).
- 이 트리에서 박스 하나하나(`html`, `head`, `body`, `title`, `h1`, `p` …)를 **노드(Node)**라고 부른다. "HTML 문서를 트리 구조로 표현한다"는 말은 곧 "각 태그를 노드라는 하나의 단위로 만들고, 그 노드들을 부모-자식 관계로 연결해서 구조화한다"는 뜻이다.
- DOM을 트리 구조로 만들어두는 이유는, 그래야 자바스크립트가 이 구조를 따라 이동하면서 원하는 노드를 탐색하고 조작할 수 있기 때문이다.

### | 노드의 3가지 유형 |

| 유형 | 설명 |
| --- | --- |
| 문서 노드 (Document Node) | 트리 최상단에 위치한 루트 노드. `document` 객체를 가리킨다 |
| 요소 노드 (Element Node) | HTML 태그를 객체화한 것 |
| 텍스트 노드 (Text Node) | HTML 요소 내부의 실제 글자 콘텐츠 |

- **공백 노드**: HTML을 작성할 때 넣은 줄바꿈이나 탭 문자는 브라우저에 의해 공백만 담긴 텍스트 노드로 만들어진다. 그래서 모든 노드를 순서대로 탐색하면 눈에 보이지 않는 빈 노드까지 섞여서 나올 수 있다는 점을 감안해야 한다.

### | 노드 계층 탐색 프로퍼티 |

| 탐색 대상 | 부모 | 자식(목록) | 첫/끝 자식 | 형제 |
| --- | --- | --- | --- | --- |
| 모든 노드 (공백 포함) | `parentNode` | `childNodes` | `firstChild` / `lastChild` | `nextSibling` / `previousSibling` |
| HTML 요소 노드만 | `parentElement` | `children` | `firstElementChild` / `lastElementChild` | `nextElementSibling` / `previousElementSibling` |

- 공백 노드 때문에 헷갈리는 걸 피하려면 실무에서는 대부분 오른쪽 "요소 노드만" 탐색하는 프로퍼티를 사용한다.

### | console.dir과 "객체가 되어야 선택할 수 있다" |

- 콘솔에 `document`라고 치면 문서 전체(html)가 나오고, `document.head`라고 치면 head 부분이 나온다.
- `console.dir(document.head)`처럼 찍어보면 그 실체가 키-값 쌍으로 이루어진 **객체**라는 걸 확인할 수 있다. HTML의 모든 태그는 이렇게 객체 형태로 존재할 때만 자바스크립트로 선택하고 CSS까지 통제할 수 있다 — 텍스트인 상태로는 아무것도 조작할 수 없다.
- `document` 안에 또 `document`(하위 문서 구조)가 들어있는 듯한 중첩 형태는, UI 설계에서 "작은 부품을 조합해 큰 구조를 만드는" 컴포지트 패턴(Composite Pattern)과 비슷한 결의 패턴이다.

# PART 4. 요소(Node)를 선택하는 방법 — 반드시 암기

### | 속성·태그 기준 선택 |

| 메서드 | 설명 |
| --- | --- |
| `document.getElementById("id값")` | 일치하는 요소 **하나** 반환 |
| `document.getElementsByClassName("클래스명")` | 일치하는 모든 클래스 요소 반환 |
| `document.getElementsByTagName("태그명")` | 일치하는 모든 태그 목록 반환 |
| `document.getElementsByName("name값")` | 일치하는 모든 `name` 속성 요소 반환 |

- 위 메서드들이 복수 개를 반환할 때는 배열이 아니라 **유사 배열 객체**(NodeList 또는 HTMLCollection)를 반환한다. 특히 `getElementsBy...` 계열이 반환하는 목록은 **동적 객체(Live Object)**라서, HTML 문서가 바뀌면 그 목록 내용도 실시간으로 같이 바뀐다. 요소를 순회하면서 추가·삭제하면 목록의 길이 자체가 도중에 변할 수 있으므로 주의해야 한다.

### | CSS 선택자 기준 선택 (현대적인 방식) |

- `document.querySelector("선택자")` : 일치하는 요소 중 **첫 번째**만 반환.
- `document.querySelectorAll("선택자")` : 일치하는 모든 요소를 **정적인** NodeList로 반환. 문서 내용이 바뀌어도 이미 뽑아온 목록 상태는 유지되므로, 반복문 안에서 안전하게 순회할 수 있다.

### | 그 외 접근 경로 |

- **문서 전체 / head / body** : `window.document`, `window.document.head`, `window.document.body`
- **양식(form) 이름으로 접근**: `<form name="frmLogin">`처럼 `name`이 있으면, `document.forms.frmLogin.elements.항목이름.value`라는 정식 경로 대신 `frmLogin.항목이름.value`처럼 아주 짧게 단축해서 쓸 수 있다.

```javascript
// <form name="joinForm"> 내부에 <input name="userEmail">이 있을 때
const emailValue = document.joinForm.userEmail.value; // 기본 단축
const emailValue2 = joinForm.userEmail.value;          // 더 짧은 단축
```

- **상대적 접근(요소 노드 기준)**: `parentElement`(부모) · `children`(자식) · `firstElementChild`/`lastElementChild`(첫/끝 자식) · `nextElementSibling`/`previousElementSibling`(다음/이전 형제)

# PART 5. 요소의 속성과 내용 다루기

### | 속성(Attribute) 제어 |

| 메서드 | 설명 |
| --- | --- |
| `element.getAttribute("속성명")` | 속성 값 조회 |
| `element.setAttribute("속성명", "값")` | 속성 값 설정/수정 |
| `element.hasAttribute("속성명")` | 속성 존재 여부 확인 |
| `element.removeAttribute("속성명")` | 속성 제거 |

- `id`, `type`, `src`, `href`, `target`, `action`처럼 자주 쓰는 속성은 `element.id`, `element.href`처럼 프로퍼티로 바로 접근할 수 있다. 다만 `class`는 자바스크립트의 예약어라 `element.class`로는 접근이 안 되고, 대신 `element.className`(문자열 전체) 또는 `element.classList`(목록 객체)로 접근한다.

### | data-* 속성 (데이터 속성) |

- `<input data-price="10000">`처럼 `data-`로 시작하는 속성은 HTML5 표준이 정식으로 정해둔 **커스텀 데이터 속성**이다. 반면 `<input price="10000">`처럼 표준에 없는 이름을 임의로 붙이면 비표준 속성이라 취급이 불안정하고, `element.price`처럼 프로퍼티로 자동 접근되지도 않는다.
- `data-*` 속성들은 `element.dataset` 객체를 통해 한 번에 깔끔하게 읽고 쓸 수 있다 (`data-price` → `dataset.price`). 실무에서 "이 요소에 자바스크립트만 참고할 값을 몰래 붙여두고 싶을 때" 가장 많이 쓰는 방식이라 꼭 익혀둘 것.

### | classList — 클래스를 안전하게 제어하는 인터페이스 |

- `element.classList`는 클래스 목록을 관리하는 `DOMTokenList` 객체를 반환한다. 클래스 문자열을 직접 잘라 붙이거나 파싱할 필요 없이 아래 메서드로 안전하게 제어할 수 있다.

| 메서드 | 설명 |
| --- | --- |
| `classList.add("클래스명")` | 클래스 추가 |
| `classList.remove("클래스명")` | 클래스 제거 |
| `classList.toggle("클래스명")` | 없으면 추가, 있으면 제거 |
| `classList.contains("클래스명")` | 포함 여부를 불리언으로 반환 |

- 하나의 클래스를 켰다 껐다 반복하는 상황이라면 `add`/`remove`를 조건문으로 나눠 쓰기보다 `toggle` 하나로 처리하는 편이 훨씬 안전하다 (PART 1의 오타 사례처럼 문자열을 두 번 따로 적다가 실수하는 걸 원천적으로 막아준다).

### | innerHTML vs textContent |

| 프로퍼티 | 설명 |
| --- | --- |
| `innerHTML` | 내부 콘텐츠를 HTML 코드로 해석해서 반영. 태그 구조 자체를 바꿀 수 있음 |
| `textContent` | 태그를 해석하지 않고 순수 텍스트로만 처리. 더 안전함 |

- `document.write()` 같은 레거시 API는 페이지 로딩(`load`) 이후에 실행되면 기존 문서 전체를 하얗게 지워버리는 데다, 브라우저의 프리로드 최적화를 방해해 로딩 속도를 떨어뜨리고, HTML을 문자열로 직접 꽂아 넣는 방식이라 악성 스크립트 삽입(XSS) 공격에도 취약하다. 지금은 `textContent`, `appendChild()`, `insertAdjacentHTML()` 등으로 대체해서 쓴다.

# PART 6. 노드 생성·삽입·삭제, 그리고 위치·폼 제어

### | 새 노드 만들기 |

```javascript
const newLi = document.createElement("li");      // 요소 노드 생성 (아직 트리에는 미연결)
newLi.textContent = "새로운 항목";
document.createTextNode("텍스트");                 // 텍스트 노드 생성
```

- `createElement`/`createTextNode`로 만든 노드는 만들어진 시점엔 기존 DOM 트리와 아무 연결이 없는, 메모리 상에만 떠 있는 상태다. 실제로 화면에 나타나게 하려면 아래처럼 부모 노드에 삽입해 줘야 한다.

### | 삽입/삭제 — 과거 표준 vs 최신 표준 |

| 과거 표준 | 설명 |
| --- | --- |
| `부모.appendChild(자식노드)` | 맨 마지막에 추가. 오직 **DOM 노드 객체 하나**만 인수로 받는다 |
| `부모.insertBefore(새노드, 기준노드)` | 기준 노드 바로 앞에 삽입 |
| `부모.removeChild(자식노드)` | 자식 삭제. **반드시 부모를 거쳐야** 삭제 가능 |
| `부모.replaceChild(새노드, 옛노드)` | 자식 교체 |

| 최신 표준 | 설명 |
| --- | --- |
| `부모.append(노드 또는 문자열)` | 맨 마지막에 추가. **여러 개 동시 삽입 가능**, 문자열을 넣으면 자동으로 텍스트 노드로 변환 |
| `부모.prepend(노드 또는 문자열)` | 맨 처음에 추가 |
| `요소.remove()` | 부모를 거칠 필요 없이 **요소 자체가 자기 자신을 직접 삭제** |

### | 좌표계 두 가지 |

| 좌표계 | 원점(0,0) 기준 |
| --- | --- |
| 뷰포트 좌표계(윈도우 좌표계) | 현재 화면에 보이는 브라우저 표시 영역의 좌상단. 스크롤해도 화면 기준이라 변하지 않음 |
| 문서 좌표계 | 스크롤 상태와 무관하게 전체 문서의 좌상단 |

- `element.getBoundingClientRect()`는 뷰포트 좌표계 기준으로 해당 요소의 `left`/`top`/`right`/`bottom`/`width`/`height`를 담은 객체를 반환한다.

### | 폼 데이터 다루기 |

```javascript
// <form name="orderForm"><input name="productName" value="..."></form>
const extractedData = orderForm.productName.value; // 단축 표기법
```

- 인라인 스타일을 수정할 때는 `element.style.backgroundColor`처럼 하이픈이 들어간 CSS 속성(`background-color`)을 카멜 케이스로 바꿔서 써야 한다.

### | 데일리 퀘스트 |

Q1. 웹 브라우저의 자바스크립트 실행 순서 중, HTML 파싱이 완료되어 DOM 트리 구축이 끝났음을 알리는 이벤트로, 이미지 등 외부 리소스의 로드 완료 여부와 상관없이 발생하는 것은 무엇인가요?

[ 보기 ]

a. load

b. DOMContentLoaded

c. readyState

d. beforeunload

내 제출 답안 : 미제출 (오답 ❌)

[ 정답 ] b. DOMContentLoaded

-> `DOMContentLoaded`는 DOM 트리 구축이 완료되는 시점에 발생하며 이미지 등의 외부 리소스 로드와는 무관하다. `load`는 모든 리소스 다운로드까지 끝난 후 발생하는 이벤트이므로 오답이다. `readyState`는 이벤트가 아니라 문서 상태를 나타내는 프로퍼티이며, `beforeunload`는 교안에 등장하지 않는 개념이다.

Q2. 외부 자바스크립트 파일을 `<script>` 태그로 불러올 때 사용하는 속성 중, HTML 파싱을 막지 않고 병렬로 다운로드하지만 실행 시점에는 파싱이 중단되며 여러 파일 간 실행 순서가 보장되지 않는 속성은 무엇인가요?

[ 보기 ]

a. defer

b. async

c. loading

d. sync

내 제출 답안 : 미제출 (오답 ❌)

[ 정답 ] b. async

-> `async` 속성은 다운로드는 비동기로 진행하지만 다운로드가 끝나는 즉시 실행되며, 이때 파싱이 중단되고 실행 순서도 보장되지 않는다. `defer`는 실행이 DOM 트리 구축 완료 시점으로 예약되고 순서가 유지되므로 오답이다. `loading`과 `sync`는 교안에 존재하지 않는 속성명이다.

Q3. 현재 페이지의 방문 이력을 삭제하지 않고 남겨둔 채로 새로운 URL로 페이지를 이동시켜, 사용자가 '뒤로 가기' 버튼으로 이전 페이지에 복귀할 수 있도록 하는 Location 객체의 메서드는 무엇인가요?

내 제출 답안 : 미제출 (오답 ❌)

[ 정답 ] location.assign()

-> `location.assign(url)`은 새 URL로 문서를 로드하면서도 이전 페이지 주소를 방문 이력에 그대로 남기기 때문에 뒤로 가기 버튼으로 복귀가 가능하다. 이는 이력을 삭제하는 `location.replace()`와 대비되는 특징이다.

Q4. 자바스크립트의 전역 실행 컨텍스트(함수나 블록 외부의 가장 바깥 영역)에서, window 객체와 완전히 동일한 참조 대상이 아닌 것은 무엇인가요? (단, 일반 독립 창 기준)

[ 보기 ]

a. this

b. parent

c. document

d. window 자기 자신

내 제출 답안 : 미제출 (오답 ❌)

[ 정답 ] c. document

-> 전역 스코프에서 `this`와 `parent`는 `window`와 동일한 객체를 참조하지만, `document`는 `window`의 하위 프로퍼티로 별개의 Document 객체를 가리키므로 `window`와 동일하지 않다. `window.document`와 `document`는 같지만, `window` 자체와 `document`는 다른 객체다.

Q5. HTML 요소를 구성하는 객체가 제공하는 프로퍼티로, add·remove·toggle·contains 메서드를 통해 클래스 문자열을 직접 파싱하지 않고도 CSS 클래스를 안전하게 추가·삭제·전환할 수 있게 해주는 것은 무엇인가요?

내 제출 답안 : 미제출 (오답 ❌)

[ 정답 ] classList

-> `classList`는 `DOMTokenList` 객체를 반환하여 클래스 목록을 `add`, `remove`, `toggle`, `contains` 메서드로 손쉽게 제어할 수 있게 해주는 프로퍼티다. 이는 인라인 스타일을 직접 수정하는 방식보다 일관성 있는 스타일 제어를 가능하게 한다.
