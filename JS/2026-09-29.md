# PART 1. 배열(Array) 완전 정리

### | 배열이란 — 연속된 메모리 공간 |

- 배열은 사물함처럼 **같은 크기의 공간들이 순서대로 이어져 있는** 자료구조다. 각 칸마다 번호(인덱스)가 매겨져 있어서 원하는 칸에 바로 접근할 수 있다.
- 자바스크립트 배열은 타입 제약 없이 모든 종류의 값을 담을 수 있는 컬렉션(여러 데이터를 하나로 묶어 관리하는 자료구조 중 하나)이다.

### | 배열을 만드는 방법 |

```javascript
// 1. 배열 리터럴 — 실무에서 압도적으로 많이 쓰는 방식
const arr1 = [1, 2, 3];

// 2. Array 생성자 함수
const arr2 = new Array(1, 2, 3); // [1, 2, 3] — arr1과 완전히 동일한 배열
const arr3 = new Array(3);       // [ <3개의 빈 슬롯> ] — 길이만 3인 빈 배열
```

- `new Array(...)`의 동작은 매개변수 개수·타입에 따라 갈린다.
  - 매개변수를 **0 이상의 정수 1개만** 넘기면, 그 값은 "요소의 개수(길이)"로 해석되어 빈 슬롯 n개짜리 배열이 만들어진다.
  - 그 외의 경우(정수가 아닌 값 1개, 또는 값을 2개 이상) 넘기면 넘긴 값들 자체가 배열의 요소가 된다.
- 이 두 가지 동작이 갈라지는 지점이 헷갈리기 쉬워서, 실무에서는 의도를 명확히 드러내는 배열 리터럴 `[...]` 표기를 훨씬 선호한다.

### | 배열과 프로토타입 체인 |

```javascript
const arr = [1, 2, 3];
console.log(arr instanceof Array);                            // true
console.log(Object.getPrototypeOf(arr) === Array.prototype);  // true
```

- 배열 리터럴 `[...]`로 만들든 `new Array(...)`로 만들든, 만들어진 인스턴스는 동일하게 `Array.prototype`을 상속받는다. 즉 `[1,2,3]`과 `new Array(1,2,3)`은 생김새만 다를 뿐 결과물은 동일하다.
- `instanceof`는 좌변 객체의 프로토타입 체인 위에 우변 생성자의 `prototype`이 실제로 놓여 있는지를 검사하는 연산자다 — "이 객체가 이 생성자 계열로부터 상속받은 게 맞는가"를 확인하는 도구다.
- 배열과 일반 객체는 "프로토타입 체인이 다르다 = 상속 관계가 다르다"고 표현할 수 있다. 배열은 `Array.prototype`을 기준으로 상속 여부를 확인하고, 일반 객체는 `Object.prototype`을 기준으로 확인한다.

### | 배열 메서드 총정리 |

- 배열 메서드는 크게 세 갈래로 나뉜다.
  1. **수정 메서드(Mutator)** — 원본 배열 자체를 직접 바꾼다.
  2. **접근자 메서드(Accessor)** — 원본은 그대로 두고 새로운 값이나 배열을 반환한다.
  3. **반복 메서드(Iteration)** — 콜백 함수를 받아 요소를 하나씩 순회하며 처리한다.

| 분류 | 메서드 | 설명 |
| --- | --- | --- |
| 수정 (원본 변경) | `push(...요소)` | 배열 **끝**에 요소 추가 |
| 수정 | `unshift(...요소)` | 배열 **앞**에 요소 추가 |
| 수정 | `pop()` | **끝** 요소를 꺼내며 제거 (반환값: 제거된 요소) |
| 수정 | `shift()` | **앞** 요소를 꺼내며 제거 (반환값: 제거된 요소) |
| 수정 | `splice(시작, 삭제개수, ...추가요소)` | 지정 위치의 요소를 삭제하거나 그 자리에 새 요소를 끼워 넣는다. 매개변수를 세 개까지 받아 "추가"와 "삭제"를 한 메서드로 함께 처리하는 유일한 메서드 |
| 접근자 (원본 유지) | `slice(시작, 끝)` | 지정 구간을 잘라 **새 배열**로 반환. 원본은 건드리지 않음 |
| 접근자 | `indexOf(값)` | 값의 위치를 왼쪽 → 오른쪽 순서로 탐색해 반환 (없으면 `-1`) |
| 접근자 | `lastIndexOf(값)` | 값의 위치를 오른쪽 → 왼쪽 순서로 탐색해 반환 |
| 접근자 | `concat(...)`, `join(구분자)` | 배열 합치기 / 문자열로 합치기. 둘 다 원본 유지 |
| 반복 (콜백 기반) | `forEach(callback)` | 각 요소를 순서대로 콜백에 넘겨 실행만 할 뿐, 반환값은 `undefined` |
| 반복 | `map(callback)` | 콜백이 리턴한 값들로 이루어진 **새 배열**을 반환 |
| 반복 | `filter(callback)` | 콜백이 `true`를 리턴한 요소만 모아 **새 배열**로 반환 |

- `map`/`filter`는 이름 때문에 "원본을 수정하는 메서드"처럼 느껴지기 쉬운데, 실제로는 원본을 전혀 바꾸지 않고 매번 **새 배열**을 만들어 반환한다. 판단 기준은 어디까지나 "원본 배열 자체가 바뀌었는가"이며, 이 기준으로 보면 `map`/`filter`는 접근자·반복 쪽에 속한다.

### | Symbol.iterator — 배열이 반복 가능한 이유 |

```javascript
const arr = [10, 20, 30];
for (const v of arr) {
    console.log(v); // 10, 20, 30
}
```

- 배열이 `for...of` 문으로 순회 가능한 이유는 `Array.prototype`에 `Symbol.iterator`라는 특수한 메서드(반복자, Iterator)가 내장되어 있기 때문이다.
- `Symbol.iterator`를 호출하면 `next()` 메서드를 가진 반복자 객체가 반환되고, `for...of`는 내부적으로 이 `next()`를 반복 호출하면서 값을 하나씩 꺼낸다.

# PART 2. 자바스크립트 객체의 분류 — 네이티브 객체와 호스트 객체

### | 네이티브 객체 vs 호스트 객체 |

- 자바스크립트의 객체는 크게 두 갈래로 나뉜다.
  - **네이티브 객체(Native Object)** : 브라우저든 Node.js든 실행 환경과 무관하게, 자바스크립트 언어 자체 스펙(ECMAScript)에 항상 포함되어 있는 공통 객체.
  - **호스트 객체(Host Object)** : 언어 자체 스펙에는 없고, 실행 환경(웹 브라우저 또는 Node.js)이 추가로 얹어주는 객체. 브라우저의 BOM/DOM(`window`, `document`), Node.js의 전역 객체(`process`, `require`) 등이 여기 속한다.

### | 네이티브 객체 ① — 내장 생성자(표준) 객체 |

- **`Object`** : 모든 객체의 조상 격. `{}`로 만드는 객체는 전부 이 `Object`를 기반으로 한다.
- **`String`, `Number`, `Boolean`** : 원시 래퍼 객체 (바로 아래에서 자세히 다룸).
- **`Function`, `Date`, `Error`, `RegExp`, `Array`** 등도 모두 내장 생성자 객체에 속한다.

### | 원시 래퍼 객체(Wrapper Object)란 |

```javascript
const text = "javascript";
console.log(text.toUpperCase()); // "JAVASCRIPT"
```

- `text`는 원시값(문자열 리터럴)이라 원래는 메서드를 가질 수 없어야 정상이다. 원시값은 그냥 "값" 그 자체, 종이 한 장일 뿐 스스로 무언가를 할 힘이 없기 때문이다.
- 그런데도 `.toUpperCase()`가 동작하는 이유는, `text.메서드`처럼 원시값에 마침표(`.`)를 찍어 접근하는 순간 자바스크립트 엔진이 그 값을 **임시로 `String` 객체로 감싸서(Wrapping)** 메서드를 대신 실행시켜 주기 때문이다.
- 이 임시 객체는 메서드 실행 결과만 반환하고 그 즉시 사라진다. 원본 `text`는 여전히 원시값 그대로 남아 있다.
- 이렇게 "원시값을 잠깐 포장해서 메서드를 쓸 수 있게 해주는 임시 껍데기" 역할을 하는 생성자가 `String`, `Number`, `Boolean`이며, 이를 **원시 래퍼 객체**라고 부른다.

### | Number 관련 판별 함수 정리 |

| 함수 | 하는 일 | 주의할 점 |
| --- | --- | --- |
| `NaN` | "Not a Number" — 유효하지 않은 숫자 연산의 결과값 그 자체 | 함수가 아니라 값이다 |
| `isNaN(값)` | 인자를 내부적으로 `Number()`로 강제 변환한 뒤, 그 결과가 `NaN`인지 검사 | 숫자로 변환 가능한 문자열(`"123"`)은 `Number("123")`이 `123`이 되어버려 `isNaN`이 `false`를 반환한다 → "숫자다"로 오판하기 쉽다 |
| `Number(값)` | 값을 숫자로 강제 변환. 변환 불가능하면 `NaN` 반환 | |
| `typeof 값` | 값의 실제 자료형을 문자열로 반환 | 문자열인지 숫자인지 정확히 구분하고 싶을 땐 `isNaN`보다 `typeof`가 더 믿을 만하다 |
| `parseInt(값)` | 문자열을 정수로 변환 | |
| `parseFloat(값)` | 문자열을 실수로 변환 | |

### | 네이티브 객체 ② — 내장 객체 (JSON, Math) |

- `new`로 인스턴스를 만드는 생성자가 아니라, 처음부터 완성된 상태로 바로 갖다 쓰는 "도구 모음" 객체다.

**JSON**
- `JSON.stringify(객체)` : 자바스크립트 객체 → JSON 문자열 (직렬화)
- `JSON.parse(문자열)` : JSON 문자열 → 자바스크립트 객체 (역직렬화)

**Math**
- `Math.abs()` 절댓값 · `Math.sqrt()` 제곱근 · `Math.round()` 반올림 · `Math.floor()` 버림(내림) · `Math.ceil()` 올림 · `Math.trunc()` 절사(소수점을 그냥 잘라냄, 음수에서 `floor`와 결과가 달라질 수 있음)

### | Symbol |

- 자바스크립트의 7번째 원시 타입. 호출할 때마다 세상에 단 하나뿐인, 절대 겹치지 않는 유일무이한 값을 만들어낸다. 주로 객체 프로퍼티 키가 다른 코드와 충돌하지 않도록 보장하고 싶을 때 사용한다.

# PART 3. 화살표 함수 심화 — 왜 this를 스스로 못 가질까

### | "이름 없는 함수"와 렉시컬 this |

- 화살표 함수는 함수 선언문으로 만들 수 없고 항상 표현식으로만 정의되는, 사실상 **이름 없는 임시 함수**다.
- 함수가 실행될 때 자바스크립트 엔진은 그 함수만을 위한 실행 컨텍스트(Execution Context, EC)를 새로 만들고, 그 안에 `this`·`arguments` 같은 것들을 자동으로 채워 넣는다. 그런데 화살표 함수는 자기 자신의 `this`/`arguments`/`super`/`new.target`을 스스로 바인딩하지 않는다.
- 그래서 화살표 함수 내부에서 `this`를 찾으면, 자기 것이 없으니 함수가 **정의된 시점**의 바로 바깥 스코프로 올라가 그곳의 `this`를 그대로 값으로 캡처해서 쓴다. 이를 **렉시컬 this(Lexical this)**라 부른다.
- 한번 캡처된 this는 고정되어, 나중에 함수를 누가 어떤 방식으로 호출하든 절대 바뀌지 않는다. 반대로 일반 함수의 this는 "누가 호출했는지(호출 방식)"에 따라 매번 동적으로 다시 결정된다.
- 그래서 콜백·이벤트 핸들러 안에서 "바깥 컨텍스트의 this를 그대로 쓰고 싶을 때" 화살표 함수가 유용하다 — 일반 함수를 썼다면 호출 시점에 this가 엉뚱한 값(전역 객체나 `undefined`)으로 바뀌어버렸을 상황을 미리 막아준다.
- 같은 이유로 화살표 함수는 `new` 연산자로 인스턴스를 만들 수 없고(`prototype` 프로퍼티가 없음), 함수 내부에서 `arguments` 객체도 쓸 수 없다.

# PART 4. this 바인딩 심화, 그리고 콜백 함수 vs 클로저

### | this 바인딩을 메모리 관점으로 이해하기 |

- "바인딩(binding)"이라는 단어를 "묶다"보다는 **"이름표를 갖다 붙인다"**는 식으로 이해하면 더 직관적이다.
- 함수가 호출될 때마다 엔진은 메모리 어딘가에 그 함수만을 위한 공간(실행 컨텍스트)을 새로 만들고, 그 공간 한 켠에 `this`라는 이름표를 붙여 특정 객체를 가리키게 놓아둔다.
- `call`/`apply`/`bind`를 쓰는 **명시적 바인딩**은, 이 이름표가 원래 자동으로 결정될 자리에 개발자가 직접 "이 객체를 가리켜라"고 값을 지정해서 덮어씌우는 것이다.
- `this`를 "바인딩"이라는 단어 자체에 너무 얽매여 이해할 필요는 없다 — 함수가 호출되는 순간 실행 컨텍스트가 자동으로 만들어지면서 그 안에 `this`가 채워지는 것 자체가 이미 바인딩이다. 즉 `this`를 "쓴다"는 행위 자체가 곧 바인딩이 일어났다는 뜻이다.

### | 콜백 함수 vs 클로저 — "역할" 대 "현상" |

- 이 둘을 자주 헷갈리는 이유는, 실제로 콜백이면서 동시에 클로저인 경우가 매우 많기 때문이다. 하지만 두 개념은 애초에 서로 다른 층위의 질문에 답하는 말이다.

| 구분 | 콜백 함수 (Callback) | 클로저 (Closure) |
| --- | --- | --- |
| 질문의 성격 | **역할** — 이 함수가 어떻게 "쓰이는가" | **현상** — 이 함수에게 무슨 일이 "벌어지는가" |
| 정의 | 다른 함수의 인자로 넘겨져서, 나중에 그 함수 내부에서 호출되는 함수 | 함수가 자신을 감싸던 바깥 함수의 변수를, 그 바깥 함수의 실행이 끝난 뒤에도 계속 기억하고 있는 현상 |

```javascript
// 콜백의 예 — filter에 함수를 인자로 "넘겨서" 나중에 호출되게 한다 (= 역할 이야기)
products.filter(function (p) { return p.stock > 0; });
```

```javascript
// 클로저의 예 — 콜백이 아니라 그냥 값처럼 리턴된 함수인데,
// 바깥 함수 createSecureStorage가 이미 끝났는데도 secureValue를 계속 기억한다 (= 현상 이야기)
function createSecureStorage() {
    let secureValue = "비밀";
    return function () {
        return secureValue;
    };
}
```

- 두 예시에서 보듯 콜백은 "함수를 어디에 어떻게 넘겼는가"를 설명하는 말이고, 클로저는 "함수가 무엇을 계속 붙잡고 있는가"를 설명하는 말이다. 원칙적으로는 서로 아무 관계가 없다.

```javascript
// 콜백이면서 동시에 클로저인 경우
function delayedGreeting(name) {
    setTimeout(function () {
        console.log("안녕, " + name); // name을 계속 기억 → 클로저
    }, 1000); // setTimeout에 넘겨져서 나중에 호출됨 → 콜백
}
delayedGreeting("철수");
```

- `setTimeout`에 넘긴 이 익명 함수는 두 가지를 동시에 만족한다.
  - **콜백이다** : `setTimeout`의 인자로 넘겨져서 1초 뒤에 대신 호출되기 때문.
  - **클로저이다** : `delayedGreeting` 함수의 실행이 이미 끝나 스택에서 사라진 뒤에도, 그 안의 지역 변수 `name`을 계속 참조하고 있기 때문.
- 즉 이 경우는 "콜백이면서 동시에 클로저"인 것이지, "콜백 = 클로저"라서 그런 게 아니다.
- 반대로 바깥 스코프의 무언가를 딱히 "기억"할 필요가 없는 콜백도 얼마든지 있다. 그런 콜백은 클로저라는 성질이 거의 의미가 없어진다 — 콜백이라고 해서 항상 클로저인 것은 아니다.

Q5. call, apply, bind 메서드에 대한 설명으로 옳지 않은 것을 고르세요.

[ 보기 ]

a. call은 함수를 즉시 실행하며 인수를 쉼표로 구분해 개별 전달한다.

b. apply는 함수를 즉시 실행하며 인수들을 배열 형태로 한 번에 전달한다.

c. bind는 함수를 즉시 실행하지 않고 this가 고정된 새로운 함수를 반환한다.

내 제출 답안 : d. (정답 ✅)
