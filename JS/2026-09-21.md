# PART 1. JavaScript 실행 환경과 기본기

### | JavaScript는 어디서, 어떻게 실행되나 |

- **JavaScript는 인터프리터 언어**다. (파이썬도 마찬가지) 컴파일 언어처럼 전체 코드를 미리 기계어로 통째로 번역해두는 게 아니라, **한 줄씩 그때그때 해석하면서 실행**한다.

- **JS 해석 엔진이란** : JS 코드는 그 자체로는 의미 없는 글자 뭉치일 뿐이라, 컴퓨터가 실제로 이해하고 실행하려면 번역해서 실행해주는 프로그램이 필요하다. 이 프로그램이 "JS 해석 엔진"이다. 비유하자면 JS 코드는 **외국어로 쓰인 대본**이고, 해석 엔진은 **그 대본을 실시간으로 읽고 연기까지 해주는 통역 배우**다.

- **V8** : 이 통역 배우 중 하나가 구글이 만든 V8이다. 원래는 크롬 브라우저 안에서만 살고 있어서, 크롬으로 웹사이트를 열면 그 페이지 안의 JS 코드를 V8이 읽고 실행해주는 방식이었다.

- **Node.js란** : V8이 원래 "브라우저 안에서만" 동작하도록 만들어졌는데, 이 통역 배우를 브라우저 밖으로 꺼내서 컴퓨터에서도 그냥 쓸 수 있게 포장한 것이 Node.js다. 즉:
  - **크롬 브라우저** = V8 통역 배우가 브라우저 안에 살면서, 웹페이지를 열 때마다 그 안의 JS를 실행해주는 환경
  - **Node.js** = 같은 V8 통역 배우를 브라우저 밖으로 데리고 나와서, 컴퓨터 자체에서 JS 파일을 직접 실행할 수 있게 만든 환경 — 그 자체로 **런타임(Runtime)**, "JS 코드를 실행해주는 환경"

- **왜 중요한가** : Node.js가 나오기 전엔 JS로 "웹페이지 안에서 버튼 누르면 반응하는" 정도의 일만 할 수 있었다. Node.js 덕분에 JS로 서버를 만들거나, 파일을 읽고 쓰거나, 터미널에서 스크립트를 실행하는 것까지 가능해졌다 — 웹 브라우저라는 울타리를 벗어난 것.

##### | 자주 쓰는 명령어 |

| 명령어 | 뜻 |
| --- | --- |
| `node` | 자바스크립트 코드를 실행하는 런타임 명령어 |
| `npm` (Node Package Manager) | 외부 패키지를 설치·관리할 때 쓰는 명령어 |
| `npx` (Node Package Executor) | 패키지를 설치하지 않고 일회성으로 실행할 때 쓰는 명령어 |
| `NVM` (Node Version Manager) | 한 컴퓨터에 여러 버전의 Node.js를 설치해두고, 명령어 한 줄로 버전을 전환하게 해주는 도구 |

- **왜 NVM이 필요한가** : 예를 들어 Jupyter에서 JS를 돌리는 `ijavascript` 커널은 Node.js v20 이하에서만 동작하는데, 최신 프레임워크들은 최신 버전의 Node.js를 요구하는 경우가 많다. 한 컴퓨터에서 버전이 다른 여러 프로젝트를 동시에 다뤄야 하니 NVM으로 필요할 때마다 버전을 바꿔가며 쓴다.

### | JavaScript vs TypeScript — 왜 TypeScript가 따로 생겼나 |

- 브라우저 화면 안에서 버튼을 누르거나 뭔가 움직이게 만드는 프로그래밍 언어가 **JavaScript**다.

- JS는 태생적으로 허술한 부분이 있었다 — 원래 숫자였던 변수에 문자를 넣어도 **아무 말 없이 그냥 받아준다.** 실수인지 아닌지 알려주지 않아서, 나중에 엉뚱한 곳에서 문제가 터지는 위험이 있었다.

```javascript
let age = 25;
age = "스물다섯";      // ① 이 줄을 쓸 때도 조용
console.log(age);      // ② 실행할 때도 조용, 그냥 "스물다섯" 출력됨

// ... 한참 뒤 다른 코드에서
console.log(age * 2);  // ③ 여기서야 이상한 값(NaN)이 나옴 — 뒤늦게 문제가 터짐
```

- 그래서 마이크로소프트가 JS 위에 **타입 검사라는 안전장치를 하나 얹은 언어**를 만들었는데, 그게 **TypeScript**다. 변수 옆에 `: number`처럼 타입을 적어두면, 실수했을 때 실행도 하기 전에 바로 알려준다.

```typescript
let age: number = 25;
age = "스물다섯";       // ← 이 줄을 타이핑하는 순간, 바로 빨간 줄이 뜸
```

- **TypeScript는 JS를 대체하는 게 아니라 JS 위에 얹는 것**이다. TS로 코드를 짜도, 실행될 때는 결국 JS로 자동 번역돼서 브라우저에 전달된다. (TypeScript는 설계도, JavaScript는 실제 건물)

- **왜 JS 자체를 안 고쳤나** : JS는 구글·애플 등 모든 브라우저 회사가 다 같이 동의해야 스펙이 바뀌는 언어라 몇 년씩 걸린다. 반면 TypeScript는 브라우저 안에 직접 들어가는 게 아니라 "번역 프로그램"이라서, 마이크로소프트가 허락 없이 혼자 빠르게 만들 수 있었다. (지금은 전 세계에 공개돼서 누구나 씀)

| 구분 | 장점 | 단점 |
| --- | --- | --- |
| **JavaScript** | 타입을 안 적어도 돼서 빠르게 짤 수 있음, 별도 번역 없이 바로 실행됨, 배우기 쉬움 | 실수를 실행할 때까지 모름, 코드가 커지면 관리가 힘듦 |
| **TypeScript** | 타이핑하는 순간 실수를 잡아줌, 자동완성이 정확해짐, 여럿이 같이 짤 때 안전함 | 타이핑이 늘어남, 실행 전 번역 과정이 하나 더 필요함, 배울 게 하나 더 늘어남, 작은 프로젝트엔 과할 수 있음 |

- **정적 타입 vs 그렇지 않은 것** : TS는 "정적 타입"을 가진다 — 코딩하는 동안, 실행하기 전부터 타입이 정해져 있다는 뜻. JS도 타입이 있긴 하지만, **프로그램을 실행하기 전까지는 그냥 모르고 있을 뿐**이다. 그래서 같은 실수(문자열을 숫자로 나누기 등)를 해도, JS는 실행할 때 되어서야 오류가 나고 TS는 타이핑하는 즉시 빨간 줄로 알려준다.

### | 변수와 상수 — JavaScript는 "상자", Python은 "이름표" |

| 구분 | JavaScript | Python |
| --- | --- | --- |
| 변수 선언 | 반드시 키워드 필요 — `let age = 25;` | 키워드 없이 바로 — `age = 25` |
| 상수 | `const`로 선언하면 **진짜로** 재할당이 막힘 | "진짜 상수" 개념 자체가 없음 (대문자 이름은 관례일 뿐, 강제로 안 막아줌) |
| 스코프 | `{ }` 중괄호 안에서 만든 변수는 그 안에서만 유효 | `if`문 안에서 만든 변수도 함수 전체에서 계속 보임 |

- **JavaScript의 변수는 "상자"** : 상자 안에 값을 담는 개념. 값이 바뀌면 상자는 그대로고 안의 내용물만 교체된다. `const`로 선언하면 이 상자 뚜껑에 자물쇠를 채우는 것과 같아서, 값을 바꾸려 해도 상자가 안 열려 바뀌지 않는다. (그래서 JS엔 "진짜 상수"가 존재할 수 있다)

- **Python의 변수는 "이름표"** : 컴퓨터 메모리 어딘가에 값이 먼저 만들어지고, 거기에 이름표를 붙이는 개념. 값을 바꾸면 원래 값에 붙어있던 이름표를 떼서, 새로운 값에 옮겨 붙이는 것이다. (이름표를 다른 값으로 옮겨 붙이는 것뿐이라, 애초에 "물리적으로 못 바꾸게 막을 대상"이 없어서 Python엔 진짜 상수가 없다)

# PART 2. `var`의 몰락과 `let`/`const`의 등장

### | 호이스팅(Hoisting)이란 정확히 뭔가 |

- **호이스팅** : "끌어올리다(hoist)"라는 뜻. 자바스크립트는 코드를 실행하기 **전에**, 먼저 한 번 훑어보면서 변수 이름표를 미리 만들어둔다. 실제로 코드 위치가 움직이는 건 아니지만, 선언 부분이 마치 맨 위로 끌어올려진 것처럼 동작해서 이렇게 부른다.

```javascript
console.log(name); // 이 줄이 먼저 실행되는데
var name = "철수";  // name은 이 아래에서 선언된다.
```

- 위 코드는 "아직 안 만든 걸 왜 불러?" 하고 에러가 나야 할 것 같지만, JS가 미리 이름표부터 만들어두기 때문에 에러가 안 난다 — 이게 호이스팅이다. 실제로는 두 단계로 처리된다.

```javascript
// 1단계 (미리 훑어보기) : 이름표만 만듦, 내용은 비워둠
var name;              // 이름표 'name'은 있는데 안이 비어있다.

// 2단계 (진짜 실행) : 위에서부터 순서대로
console.log(name);     // 아직 내용이 안 채워져서 -> undefined
name = "철수";          // 여기 와서야 내용이 채워진다.
```

##### | `window`가 뭔가 |

- **`window`는 브라우저가 탭(창)을 하나 열 때 자동으로 만들어주는 가장 큰 보관함**이다. 브라우저 탭을 하나 여는 건 새 집을 한 채 짓는 것과 같아서, 그 집 안에는 원래부터 있는 기본 시설(수도·전기·가구)이 딸려있다 — `window`가 바로 그 집 전체다. (Node.js 환경에서는 이 최상위 객체가 `global`이라는 이름으로 불린다)

---

### | `var`의 5가지 문제점 (전부 실전에서 겪을 수 있는 버그들) |

##### | 문제 1. 에러 없이 `undefined`가 나온다 |

- 원래는 "아직 준비 안 된 걸 쓰면" 에러를 내는 게 맞는데, `var`는 에러 없이 애매한 값(`undefined`)을 줘서 **실수를 알아채기 어렵게 만든다.**

##### | 문제 2. 전역변수 오염 — 중괄호를 무시한다 |

```javascript
if (true) {
    var age = 25;
}
console.log(age);   // 25 (중괄호 밖인데도 보임!)
```

- `var`는 `{ }` 중괄호 안에서 만들었어도, 그 안에 갇히지 않고 바깥까지 새어 나간다. 반복문이나 `if`문 안에서 임시로 쓰려던 변수가 바깥까지 새어 나가서, 의도치 않게 다른 코드와 이름이 겹치거나 값이 바뀔 수 있다.

- **왜 이게 "오염"으로 이어지나** : 함수 밖(파일 최상위)에서 `var`로 변수를 만들면, 그 변수는 자동으로 전역(`window`) 공간 안에 놓이게 되고, 페이지 안 다른 코드에서도 그 변수를 건드릴 수 있게 된다. 원래 중괄호는 그 안에서 만든 변수를 밖에서 못 보게 가둬주는 역할을 해야 하는데, `var`는 이 규칙을 안 지킨다.
  - 그 중괄호가 **함수 안**에 있었다면, 변수는 중괄호는 넘어도 함수라는 더 큰 울타리는 못 넘는다 — `var`가 유일하게 존중하는 경계가 "함수"이기 때문. 이 경우 영향은 함수 안에서만 그친다.
  - 그런데 그 중괄호가 **파일 맨 바깥(최상위)**에 있었다면, 가둬줄 함수라는 울타리 자체가 없어서 변수가 더 갈 곳이 없어지고, 결국 프로그램이 시작할 때부터 존재하던 가장 큰 공용 공간인 **전역(window)**까지 흘러 들어간다.
  - 이렇게 원래 갇혀있어야 할 변수가 통제 없이 전역까지 쌓이는 현상을 **전역변수 오염**이라 부른다. (비유 : 공원 잔디밭에 쓰레기가 하나둘 버려지는 것 — 하나만으론 사고가 안 나지만, 쌓이다 보면 결국 누군가 밟고 넘어지는 사고로 이어진다)
  - 참고로 `let`이 도입된 이유가 바로 이것 — `let`은 함수라는 큰 울타리가 없어도 중괄호 하나만으로 변수를 확실히 가둬줘서, 이 오염 자체가 애초에 일어나지 않는다. (`let`이 있기 전엔, `var`가 유일하게 존중하는 게 "함수"였기 때문에 일부러 가짜 함수를 벽처럼 만들어 감싸는 편법을 쓰기도 했다)

##### | 문제 3. 같은 이름을 또 선언해도 에러가 안 난다 |

```javascript
var name = "철수";
var name = "영희";   // 에러 안 남, 그냥 덮어씀
console.log(name);   // "영희"
```

- 코드가 길어지면, 다른 곳에서 이미 쓴 이름을 또 썼다는 걸 모르고 실수로 값을 덮어쓰는 사고가 난다.

##### | 문제 4. 반복문에서 예상 밖의 값이 나온다 (제일 유명한 `var` 버그) |

```javascript
for (var i = 0; i < 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
// 1초 뒤 예상: 0, 1, 2
// 실제 결과: 3, 3, 3   ← 전부 똑같이 3이 나옴!
```

- `var`는 중괄호를 무시하기 때문에, 반복문 3번을 돌면서 `i`라는 상자를 매번 새로 만드는 게 아니라 **처음 만든 상자 하나를 계속 재활용**한다. 상자 3개를 각각 만든 게 아니라 상자 하나의 내용물만 계속 바꾼 거라서, 1초 뒤 상자들을 열어보면 이미 내용물이 전부 3으로 바뀐 뒤다.

##### | 문제 5. 선언자를 생략하면 전역변수가 된다 |

```javascript
function makeUser() {
    age = 25;   // ← var, let, const 아무것도 안 씀!
}

makeUser();
console.log(age);   // 25 (함수 밖인데도 보임!!)
```

- 함수 안에서 변수를 쓸 때 아무 키워드도 안 붙이면, JS는 확인 없이 그냥 조용히 전역변수로 만들어버린다. (이건 엄밀히는 `var`만의 문제라기보다, `var` 시대에 자주 발생했던 "선언 깜빡함" 실수로 묶어 이해하는 게 맞다 — `let`을 쓸 때도 선언 자체를 깜빡하면 똑같이 일어난다)

### | `let`/`const`(ES6, 2015)가 위 문제들을 전부 고친 방식 |

```javascript
// 문제 1 해결 — 애매한 undefined 대신 확실한 에러
console.log(name); // ReferenceError
let name = "철수";

// 문제 2 해결 — 중괄호 밖으로 안 새어 나감
if (true) {
    let age = 25;
}
console.log(age);   // ReferenceError!

// 문제 3 해결 — 같은 이름 또 선언하면 에러
let name2 = "철수";
let name2 = "영희";  // SyntaxError!

// 문제 4 해결 — let은 반복마다 상자를 "새로" 만들어서, 각 상자에 따로 값이 저장됨
for (let i = 0; i < 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
// 결과: 0, 1, 2   ← 제대로 나옴!
```

| 구분 | 뜻 | 언제 쓰나 |
| --- | --- | --- |
| `let` | 값이 변할 수 있는 변수 | 루프 카운터, 증감하는 점수처럼 실행 도중 값이 계속 바뀌어야 할 때 |
| `const` | 값이 변하지 않는 상수 | 환경설정값, 고정 경로 등 재할당이 필요 없는 모든 경우 |

- **권장 습관** : 코드 안정성을 위해 **기본적으로 전부 `const`로 선언**하고, 나중에 값 변경이 정말 필요해지는 경우에만 그 변수를 제한적으로 `let`으로 바꾸는 게 좋다. (보통 실무에서도 `const`를 훨씬 많이 쓰고, "바꾸려고 하는 것"만 `let`을 쓴다)

- 정리하면 `let`/`const`가 고친 3가지 근본 원리 : ① **블록 레벨 스코프**(중괄호 `{}` 안에서만 수명을 가짐) ② **호이스팅 사전 차단**(선언 전 접근 시 즉시 ReferenceError) ③ **재선언·재할당 규칙 강화**

# PART 3. 주석, 데이터 타입, 연산자, 제어문, 예외 처리

### | 주석(Comments) |

- **단일 행 주석 (`//`)** : 기호 오른쪽 한 줄만 무시.
- **다중 행 주석 (`/* */`)** : 시작(`/*`)과 끝(`*/`) 사이 여러 줄을 통째로 무시.

```javascript
let activeUserLimit = 50; // 최대 활성 유입 수 제한

/*
  이 영역은 줄 바꿈이 일어나더라도
  엔진이 무시하고 실행하지 않습니다.
*/
console.log("주석 영역 밖의 실제 실행 코드입니다.");
```

- **`console.log(...)`란** : 괄호 안에 값이나 변수를 넣으면 콘솔 창에 출력해주는 명령어. 변수가 잘 만들어졌는지, 연산 결과가 맞는지 실시간으로 확인하는 가장 기본적인 도구다.

### | 데이터 타입과 `typeof` |

| 타입 | 설명 |
| --- | --- |
| Number | 정수·실수 구분 없이 모든 숫자를 하나의 형식으로 다룸 |
| String | 따옴표로 감싼 텍스트 |
| Boolean | `true` / `false` |
| null | "값이 없음"을 개발자가 **의도적으로** 표시한 상태 |
| undefined | 변수를 선언만 하고 값을 안 넣어서, 엔진이 실체를 모르는 **초기 기본 상태** |

```javascript
let count = 42;
let greeting = "Hello";
let isCompleted = false;
let emptyBox = null;
let unknownBox;

console.log(typeof count);       // "number"
console.log(typeof greeting);    // "string"
console.log(typeof isCompleted); // "boolean"
console.log(typeof unknownBox);  // "undefined"
console.log(typeof emptyBox);    // "object" ← 스펙 오류! (아래 참고)
```

- **`typeof null`이 `"object"`인 이유** : 자바스크립트 설계 초기의 대표적인 스펙 오류다. 이미 만들어진 수많은 프로그램의 하위 호환성을 지키려고 고치지 않고 그대로 유지되고 있다. 실제 `09-21 데일리 퀘스트` 문항으로도 나온 유명한 함정.

### | 문자열 결합 — 더하기(+) vs 템플릿 리터럴 |

- **더하기 연산자** : 문자열끼리는 이어붙이고, 문자열+숫자는 숫자가 문자로 자동 변환돼서 합쳐진다. 변수가 많아지면 따옴표와 `+`가 뒤엉켜 오타가 나기 쉽다.

- **템플릿 리터럴(ES6, 권장)** : 백틱(`` ` ``)으로 전체를 감싸고, `${변수명}` 형태로 표현식을 바로 넣는다.

```javascript
let userName = "민수";
let userScore = 90;

// 기존 방식
console.log("안녕하세요, " + userName + "님의 점수는 " + userScore + "점입니다.");

// 템플릿 리터럴 (권장)
console.log(`안녕하세요, ${userName}님의 점수는 ${userScore}점입니다.`);
```

### | Truthy와 Falsy — 조건문의 숨은 규칙 |

- JS는 명확한 `true`/`false`가 아니어도, 조건문 안에서 참/거짓으로 취급하는 고유한 성질이 있다.

- **Falsy (false로 자동 인식되는 딱 6가지)** : `false`, `0`, `""`(빈 문자열), `null`, `undefined`, `NaN`
- 이 6가지를 **제외한 모든 값**은 Truthy다. **빈 배열 `[]`, 빈 객체 `{}`도 Truthy**라는 게 가장 헷갈리는 포인트 (두 곳의 퀴즈에서 모두 나온 함정 문제).

```javascript
let inputName = "";  // Falsy
if (inputName) {
    console.log(`입력된 이름: ${inputName}`);
} else {
    console.log("이름이 입력되지 않았습니다."); // 이쪽이 실행됨
}

let userCartCount = 0;  // Falsy
if (!userCartCount) {
    console.log("장바구니가 비어 있습니다."); // !0 -> !false -> true
}
```

### | 기본 연산자 |

- **산술·복합 대입** : `+`, `-`, `*`, `/`, `%`(나머지), `+=`, `-=` 등
- **엄격한 일치(`===`, `!==`)** : 값뿐 아니라 **타입까지** 엄격하게 비교. (`"19" === 19`는 타입이 달라서 `false`)
- **논리 연산자** : `&&`(양쪽 다 참이어야 참) / `||`(한쪽만 참이어도 참) / `!`(반전)

```javascript
let requiredAge = 19;
let enteredAge = "19"; // 문자열

let isMatch = (enteredAge === requiredAge); // 타입이 달라서 false
console.log(isMatch); // false

let hasCard = true;
let isEligible = (typeof enteredAge === "string") && hasCard;
console.log(isEligible); // true
```

### | 제어문 — 조건문, 선택문, 반복문 |

##### | `if` / `if-else` / `if-else if-else` |

```javascript
let userRole = "manager";

if (userRole === "admin") {
    console.log("최고 관리자 권한입니다.");
} else if (userRole === "manager") {
    console.log("중간 관리자 권한입니다."); // 여기서 종료
} else {
    console.log("일반 사용자 권한입니다.");
}
```

##### | `switch-case` — 음료 자판기 비유 |

- 음료 선택(스위치) → 해당 칸 찾기(case) → 배출 후 멈춤(break) → 일치하는 게 없으면 기본 메시지(default).

```javascript
let couponType = "SILVER";
let discountRate;

switch (couponType) {
    case "GOLD":
        discountRate = 30;
        break;
    case "SILVER":
        discountRate = 20; // 여기 실행됨
        break;              // 없으면 아래 BRONZE까지 덮어씌워짐
    case "BRONZE":
        discountRate = 10;
        break;
    default:
        discountRate = 0;
}
console.log(`할인율은 ${discountRate}% 입니다.`); // 20%
```

- **`break`를 빼먹으면** : 일치한 `case` 이후 모든 `case`가 조건 비교도 없이 줄줄이 실행되는 **Fall-through(흘러내림)** 현상이 생긴다.

##### | 반복문 — `for` / `while` / `do-while` |

- **`for`문** : 반복 횟수가 정해져 있을 때. `(초기화식; 조건식; 증감식)` 3요소로 구성.
  - 카운터 변수로 관례적으로 `i`(Index/Iterator/Integer)를 쓰고, 중첩되면 `j`, `k` 순으로 쓴다.
  - 배열처럼 0부터 세는 데이터는 `i=0; i<length`, "1부터 100까지 합"처럼 사람이 이해하기 쉬운 계산은 `i=1; i<=100`처럼 쓰는 게 관례.

```javascript
let total = 0;
for (let i = 1; i <= 100; i++) {
    total += i;
}
console.log(`1부터 100까지 모두 더한 결과는 [ ${total} ] 입니다.`); // 5050
```

- **중첩 for문** : 바깥 루프가 한 번 돌 때마다 안쪽 루프가 처음부터 끝까지 전부 돈다. (시침이 한 칸 움직이는 동안 분침이 한 바퀴 다 도는 것과 같은 비유)

```javascript
for (let i = 2; i <= 3; i++) {
    console.log(`\n=== ${i}단 ===`);
    for (let j = 1; j <= 9; j++) {
        console.log(`${i} x ${j} = ${i * j}`);
    }
}
```

- **`while`문** : 정확한 반복 횟수를 모를 때, "조건이 만족되는 동안" 계속 실행. 시작 전에 조건부터 검사하므로, 처음부터 거짓이면 한 번도 실행 안 됨. **조건을 거짓으로 바꿀 장치가 없으면 무한 루프**에 빠진다.

```javascript
let stamina = 3;
while (stamina > 0) {
    console.log(`훈련 진행 중! 남은 체력: ${stamina}`);
    stamina--; // 이게 없으면 무한 루프
}
```

- **`do-while`문** : 조건이 거짓이든 참이든 **일단 최소 1회는 실행(do)**한 뒤 조건을 검사(while)한다. (놀이기구를 일단 태우고 내릴 때 티켓을 검사하는 것과 같은 비유 — 티켓이 없어도 최소 한 번은 탄다)

```javascript
let hasTicket = false;
do {
    console.log("놀이기구에 일단 탑승하여 재미있게 즐깁니다!");
} while (hasTicket === true);
```

##### | `break` vs `continue` |

| 키워드 | 비유 | 역할 |
| --- | --- | --- |
| `break` | 마트에서 찾던 물건을 발견하자마자 쇼핑을 중단하고 계산대로 가는 것 | 반복문을 즉시 중단하고 완전히 탈출 |
| `continue` | 줄 서서 예방접종 맞을 때, 이번 사람이 자리에 없으면 패스하고 다음 사람 부르는 것 | 이번 회차만 건너뛰고 다음 회차로 즉시 이동 |

```javascript
// break: 5를 찾으면 즉시 중단
for (let i = 1; i <= 10; i++) {
    if (i === 5) { break; }
    console.log(i);
}

// continue: 짝수는 건너뛰고 홀수만 출력
for (let i = 1; i <= 5; i++) {
    if (i % 2 === 0) { continue; }
    console.log(`홀수 출력: ${i}`);
}
```

### | 예외 처리 — `try` / `catch` / `finally` |

```javascript
try {
    console.log(nonExistentData); // 존재하지 않는 변수 → 에러 발생
    console.log("이 줄은 실행되지 않습니다.");
} catch (error) {
    console.log("안내: 오류가 포착되었습니다.");
    console.log(`- 에러 종류: ${error.name}`);
    console.log(`- 에러 원인: ${error.message}`);
} finally {
    console.log("정리 작업이 수행되었습니다."); // 에러 여부 상관없이 항상 실행
}
```

| 블록 | 역할 |
| --- | --- |
| `try` | 에러 발생 가능성이 있는 코드를 넣는 감시 구역. 에러가 나면 즉시 `catch`로 이동 |
| `catch (error)` | 에러 발생 시에만 실행. `error` 매개변수에 에러 정보가 담긴 객체가 자동 전달됨 |
| `finally` (선택) | 에러 발생 여부와 무관하게 맨 마지막에 무조건 실행 (연결 끊기, 파일 닫기 등 정리 작업용) |

- 에러 객체의 주요 속성 : `error.name`(에러 종류, 예: `ReferenceError`), `error.message`(에러 원인 설명), `error.stack`(발생 위치 추적 이력)

# PART 4. 객체 리터럴, 배열, 구조 분해와 전개 연산자

### | 객체 리터럴(Object Literal) |

- **객체** : 이름(Key)과 값(Value)을 한 쌍(프로퍼티)으로 묶은 데이터를 여러 개 모은 복합 데이터 타입. 연관 배열(Associative Array), 사전(Dictionary) 구조로 동작한다.

```javascript
const card = {
    suit: "하트", // 콜론(:) 왼쪽은 키, 오른쪽은 값
    rank: "A"     // 프로퍼티는 쉼표(,)로 구분
};

const obj = {}; // 빈 객체
```

##### | 프로퍼티 읽기·추가·수정·삭제 |

```javascript
const card = { suit: "하트", rank: "A" };

console.log(card.suit);     // 마침표 연산자 -> 하트
console.log(card['rank']);  // 대괄호 연산자 -> A
console.log(card.color);    // 없는 프로퍼티 -> undefined

card.value = 14;            // 없던 키에 값 대입 -> 새로 추가
card.suit = "스페이드";      // 있던 키에 값 대입 -> 수정
console.log(card);          // { suit: "스페이드", rank: "A", value: 14 }

delete card.rank;           // 프로퍼티 삭제
console.log(card);          // { suit: "스페이드", value: 14 }
```

- **`in` 연산자** : 특정 프로퍼티가 객체에 있는지 검사 (`"suit" in card` → `true`)

##### | 메서드와 `this` |

- **메서드** : 프로퍼티 값이 함수인 경우. **`this`**는 그 메서드를 호출한 객체 자기 자신을 가리킨다.

```javascript
const person = {
    name: "이용교",
    age: 45,
    getLoginInfo: function() {
        return `${this.name} (${this.age}세)`; // this로 객체 내부 프로퍼티 접근
    }
};
console.log(person.getLoginInfo()); // "이용교 (45세)"
```

##### | 객체는 참조 타입(Reference Type) |

- 객체를 변수에 대입하면, 실제 값이 아니라 **메모리상 위치 정보(참조)**가 저장된다. 하나의 객체를 여러 변수가 같이 가리키면, 한쪽에서 바꾼 게 다른 쪽에도 그대로 반영된다.

```javascript
const card = { suit: "하트", rank: "A" };
const a = card; // a에는 card가 가리키는 객체의 참조 주소가 복사됨

a.suit = "스페이드";
console.log(card.suit); // "스페이드" — a로 바꿨는데 card도 바뀜
```

### | 배열(Array) |

- 순서가 있는 데이터를 연속적으로 관리하는 객체 타입 자료구조. 각 위치는 **인덱스**(0부터 시작)로 식별하고, `length`는 최대 인덱스+1 값이다.

```javascript
const evens = [2, 4, 6, 8];
console.log(evens.length); // 4

const various = [3.14, "pi", true, { x: 1, y: 2 }, [2, 4, 6, 8]]; // 타입 혼합 가능
```

- **배열의 실체** : JS 배열은 연속된 메모리를 차지하는 진짜 물리 배열이 아니라, 인덱스를 문자열 키(`"0"`, `"1"`)로 다루는 **가상 배열(Array 객체)**이다. `colors["2"]`처럼 문자열로 접근해도 정상 동작한다.

##### | 요소 추가·삭제 |

```javascript
const a = ["A", "B", "C"];
a[3] = "D";           // 인덱스 지정 추가 -> ["A","B","C","D"]

delete a[1];          // 삭제해도 length는 안 줄고 해당 칸만 비워짐
console.log(a);        // ["A", undefined, "C", "D"]
console.log(a.length); // 4 (그대로)
```

##### | 배열 메서드 — "원본을 바꾸는가" 기준으로 정리 |

| 메서드 | 원본 변경 | 기능 |
| --- | --- | --- |
| `push(값)` | O | 맨 끝에 추가 |
| `pop()` | O | 맨 끝 제거 후 반환 |
| `unshift(값)` | O | 맨 앞에 추가 |
| `shift()` | O | 맨 앞 제거 후 반환 |
| `reverse()` | O | 순서 뒤집기 |
| `splice(시작,개수,...)` | O | 특정 위치 삭제·삽입 |
| `slice(시작,끝)` | ✗ (새 배열) | 구간 복사 |
| `concat(배열)` | ✗ (새 배열) | 배열 결합 |
| `join(구분자)` | ✗ (문자열) | 구분자로 이어붙여 문자열화 |
| `forEach(콜백)` | ✗ | 순회하며 실행만 (반환값 없음) |
| `map(콜백)` | ✗ (새 배열) | 가공해서 새 배열 |
| `filter(콜백)` | ✗ (새 배열) | 조건 맞는 것만 걸러냄 |
| `some(콜백)` | ✗ (Boolean) | 하나라도 조건 맞으면 true |
| `every(콜백)` | ✗ (Boolean) | 전부 조건 맞아야 true |
| `reduce(콜백,초기값)` | ✗ (누적값) | 하나의 값으로 누적 계산 |

```javascript
const products = [
    { id: 101, name: "기계식 키보드", price: 100000, stock: 5, isAdultOnly: false },
    { id: 102, name: "무선 게이밍 마우스", price: 50000, stock: 0, isAdultOnly: false },
    { id: 104, name: "전통 스파클링 와인", price: 35000, stock: 3, isAdultOnly: true }
];

// filter: 품절 아닌 상품만
const sellableItems = products.filter(product => product.stock > 0);

// some: 성인 인증 필요 상품이 하나라도 있나
const hasAdultProduct = products.some(product => product.isAdultOnly); // true

// every: 전부 재고 있나
const isAllInStock = products.every(product => product.stock > 0); // false

// reduce: 재고 * 가격의 전체 합
const totalInventoryValue = products.reduce((sum, product) => {
    return sum + (product.price * product.stock);
}, 0);
```

```javascript
const matrix = [[1, 2, 3], [4, 5, 6]];
console.log(matrix[1][2]); // 6 (1행 2열)

// 유사 배열 객체: 배열은 아니지만 정수 키 + length를 가진 객체
const arrayLike = { 0: "A", 1: "B", 2: "C", length: 3 };
const resultString = Array.prototype.join.call(arrayLike, ",");
console.log(resultString); // "A,B,C"
```

### | 구조 분해 할당(Destructuring)과 전개 연산자(Spread, `...`) |

##### | 배열 구조 분해 |

```javascript
const RGB = ["red", "green", "blue"];
const [r, g, b] = RGB;              // 순서대로 할당
const [first, , third] = RGB;       // 쉼표로 건너뛰기 -> first=red, third=blue

const point = [120];
const [x, y = 0] = point;           // 값 없으면 기본값 0 -> y=0

const fruits = ["apple", "banana", "orange", "grape"];
const [primary, ...others] = fruits; // primary=apple, others=[banana,orange,grape]
```

##### | 객체 구조 분해 |

```javascript
const user = { id: 101, nickname: "자바스크립트", role: "admin" };
const { nickname, role } = user;          // 키 이름과 동일한 변수명
const { id: userId } = user;              // 다른 이름으로 매핑

// 중첩 객체 + 기본값
const product = { name: "키보드", spec: { switchType: "적축" } };
const { spec: { switchType }, warranty = "1년 보증" } = product;
```

##### | 전개 연산자 — 배열/객체 복사와 병합 |

```javascript
// 배열: 결합 + 얕은 복사
const carParts = [...["엔진", "바퀴"], "범퍼", ...["핸들", "시트"]];
const original = [1, 2, 3];
const copy = [...original]; // 참조를 끊은 독립적 복사
copy.push(4);
console.log(original); // [1,2,3] (원본 그대로)

// 객체: 복사하며 특정 프로퍼티만 덮어쓰기
const baseSetting = { theme: "light", volume: 50 };
const userSetting = { ...baseSetting, volume: 80, autoUpdate: true };
console.log(baseSetting); // { theme: "light", volume: 50 } (원본 유지)
console.log(userSetting); // { theme: "light", volume: 80, autoUpdate: true }
```

- 구조 분해 할당은 **값을 받는 왼쪽**에서 쓰고, 전개 연산자는 **값을 펼쳐서 전달·나열하는 곳**에서 쓴다는 게 핵심 차이.

# PART 5. 내장 객체와 원시 래퍼 객체

### | 전역 객체(Global Object) |

| 환경 | 전역 객체 이름 |
| --- | --- |
| 웹 브라우저 | `window` |
| Node.js | `global` |
| 통합 표준 (ES2020+) | `globalThis` — 환경 상관없이 항상 최상위 전역 객체를 가리킴 |

- 참고로 `const`/`let`으로 선언한 전역 변수는 (과거의 `var`와 달리) 전역 객체의 프로퍼티로 자동 등록되지 않는다.

### | `Math` 객체 |

| 메서드 | 예시 | 결과 |
| --- | --- | --- |
| `Math.abs(x)` | `Math.abs(-5)` | 5 |
| `Math.round(x)` | `Math.round(4.5)` | 5 |
| `Math.ceil(x)` | `Math.ceil(4.1)` | 5 (올림) |
| `Math.floor(x)` | `Math.floor(4.9)` | 4 (내림) |
| `Math.max(...values)` | `Math.max(1,5,3)` | 5 |
| `Math.random()` | - | 0 이상 1 미만 난수 |

```javascript
function getRandomInt(min, max) {
    return Math.floor(Math.random() * (max - min + 1)) + min;
}
console.log(getRandomInt(1, 6)); // 주사위: 1~6 사이 정수
```

### | `JSON` 객체 — 직렬화/역직렬화 |

```javascript
const orderInfo = { id: 1052, product: "스마트폰" };

const serializedData = JSON.stringify(orderInfo, null, 2); // 객체 -> 문자열 (직렬화)
console.log(typeof serializedData); // "string"

const parsedData = JSON.parse(serializedData);              // 문자열 -> 객체 (역직렬화)
console.log(typeof parsedData);     // "object"
```

### | 원시 타입이 메서드를 호출할 수 있는 이유 — 자동 박싱/언박싱 |

- `text.toUpperCase()`처럼 원시 값(string)에 마침표를 찍어 메서드를 쓸 수 있는 건, JS 엔진이 내부적으로 **자동 박싱(Auto-Boxing)** → **메서드 실행** → **언박싱(Unboxing) 및 소멸**을 순식간에 처리해주기 때문이다.

1. **자동 박싱** : 원시 값에 `.`을 찍는 순간, 엔진이 그 값을 임시로 감싸는 래퍼 객체(`String` 인스턴스)를 생성.
2. **메서드 실행** : 그 임시 객체의 메서드를 실행하고 결과 반환.
3. **언박싱 및 소멸** : 실행이 끝나면 임시 객체를 즉시 파괴하고 원래 원시 값으로 되돌림.

```javascript
let nickname = "gildong";
nickname.tempData = "회원정보A"; // 순간적으로 임시 객체가 생겼다가 바로 사라짐
console.log(nickname.tempData);   // undefined (임시 객체가 이미 소멸돼서 못 찾음)
```

- **`new String()`처럼 래퍼 객체를 직접 만들면 안 되는 이유** : 원시 타입이 아니라 진짜 **객체**가 만들어지는데, "비어있지 않은 객체는 내부 값과 상관없이 항상 Truthy"라는 규칙 때문에 예상치 못한 버그가 생긴다.

```javascript
const objectWrapper = new Boolean(false); // false를 넣었는데도...
if (objectWrapper) {
    console.log("출력됩니다!"); // 객체 자체는 항상 Truthy라서 실행됨
}
```
