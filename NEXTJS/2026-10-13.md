# PART 1. Next.js 동작 원리 & 프로젝트 구축
### | React SPA와 Next.js 하이브리드 렌더링의 차이 |

- CSR(React 기본)과 SSR(Next.js 기본)의 차이, Prerender와 Hydration 개념을 실제 프로젝트 생성과 디렉터리 구조에 적용해보는 데 집중한다.

| 구분 | React SPA | Next.js 하이브리드 렌더링 |
| --- | --- | --- |
| 초기 접속 시 | 내용이 없는 빈 HTML + 큰 자바스크립트 파일만 받음 | 서버가 뼈대(글자·이미지)를 미리 만든 완성된 HTML을 받음 |
| 화면 표시 시점 | 브라우저가 JS를 전부 실행한 뒤에야 화면이 그려짐 | 자바스크립트 다운로드가 끝나기 전에도 화면을 즉시 확인 가능 |

- **사전 렌더링(Prerender)**은 서버가 미리 HTML 문서를 그려두는 작업으로, 첫 화면 속도가 빨라지고 검색 엔진 크롤러가 콘텐츠를 읽기 쉬워진다. **하이드레이션(Hydration)**은 그 정적 HTML 위에 자바스크립트 클릭 이벤트와 상태(State)를 연결하는 과정이다 — 건조된 음식에 물을 부어 생기를 불어넣는 것에 비유할 수 있다.

### | 터미널로 프로젝트 생성하기 |

```bash
# create-next-app 명령어로 chapter02-1 이름의 프로젝트 생성을 시작
npx create-next-app@latest chapter02-1
```

```txt
Need to install the following packages:
create-next-app@16.2.11
Ok to proceed? (y) y

✔ Would you like to use the recommended Next.js defaults? › Yes, use recommended defaults
```

- 추천 기본 설정(Yes, use recommended defaults)을 고르면 TypeScript, App Router, Tailwind CSS, ESLint, 경로 별칭(`@/*`)이 자동으로 세팅된다. 이어서 `cd chapter02-1` → `npm run dev`로 개발 서버를 띄우고 `http://localhost:3000`에서 Next.js 시작 화면을 확인한다.

### | app/ 디렉터리의 특수 파일 |

| 파일명 | 역할 |
| --- | --- |
| page.tsx | 해당 경로로 접속했을 때 사용자 눈에 보이는 실제 웹 페이지 UI |
| layout.tsx | 헤더·푸터처럼 여러 페이지에서 공통으로 유지되는 레이아웃 틀 |
| globals.css | Tailwind CSS 기본 설정 및 애플리케이션 전역 디자인 |

```ts
// app/page.tsx — 웹사이트 메인 홈 경로('/')에 접속했을 때 보여주는 페이지 컴포넌트
export default function HomePage() {
  return (
    <main className="p-10 font-sans">
      <h1 className="text-2xl font-bold mb-4">안녕하세요! 첫 Next.js 앱입니다.</h1>
      <p className="text-gray-600">
        서버에서 사전 렌더링(Prerender)되어 빠르게 전달된 화면입니다.
      </p>
    </main>
  );
}
```

```ts
// app/layout.tsx — 애플리케이션 전체 페이지를 감싸는 최상위 공통 레이아웃
import "./globals.css";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode; // 각 page.tsx 화면이 전달되어 위치하는 자리
}) {
  return (
    <html lang="ko">
      <body>
        <header className="p-5 bg-gray-100 border-b border-gray-300">
          <strong className="text-lg">My Next.js App</strong>
        </header>
        {children}
      </body>
    </html>
  );
}
```

- 이 두 코드가 실제로 만드는 화면: `/` 경로로 접속하면 먼저 `layout.tsx`가 적용돼 회색 배경의 헤더("My Next.js App")가 모든 페이지 상단에 공통으로 뜨고, 그 아래 `{children}` 자리에 `page.tsx`의 내용인 제목("안녕하세요! 첫 Next.js 앱입니다.")과 설명 문단이 들어간다. 즉 레이아웃은 액자, page.tsx는 액자 안에 끼우는 그림에 해당한다.
- `page.tsx`와 `layout.tsx`를 분리하지 않고 모든 페이지에 헤더 코드를 매번 복사해 넣는다면 어떻게 될까. 헤더 문구나 스타일을 하나 고칠 때마다 페이지 수만큼 똑같은 수정을 반복해야 하고, 한 곳이라도 빠뜨리면 페이지마다 헤더 모양이 제각각이 되는 사고가 난다. `layout.tsx`로 공통 틀을 한 번만 정의해두면 이런 중복과 누락을 원천적으로 막을 수 있다.

### | 용어 정리 |

| 용어 | 영어 표현 | 설명 |
| --- | --- | --- |
| 사전 렌더링 | Prerender | 서버가 웹 페이지의 HTML 결과물을 미리 제작해 두는 작업 |
| 하이드레이션 | Hydration | 렌더링된 HTML에 자바스크립트 동작·상태를 결합하는 과정 |
| 추천 기본 설정 | Recommended Defaults | TypeScript, App Router, Tailwind CSS 등을 포함하는 공식 권장 세팅 |
| 앱 라우터 | App Router | app 폴더 구조를 기준으로 페이지 경로를 자동 설정하는 시스템 |

# PART 2. Virtual DOM & JSX/TSX 컴포넌트
### | 명령형 UI와 선언적 UI |

- 오늘은 "왜 리액트 방식이 더 편한가"에 해당하는 선언적 UI 개념과 실습 코드 위주로 정리한다.

| 구분 | 설명 |
| --- | --- |
| 명령형 UI(기존 JS) | 화면의 특정 요소를 직접 하나씩 찾아가서 변경하는 방식 |
| 선언적 UI(React) | "화면이 어떤 상태여야 하는지" 결과 형태만 정의하면 리액트가 알아서 변경 사항을 적용 |

- 명령형 방식이라면 어떻게 될까. 버튼을 눌러 숫자를 바꿀 때마다 `document.getElementById(...).innerText = ...`처럼 화면 요소를 직접 찾아가 값을 바꾸는 코드를 매번 작성해야 한다. 요소가 늘어날수록 "어디를 어떻게 바꿀지" 추적하는 코드가 기하급수적으로 복잡해진다. 선언적 UI는 "데이터가 이렇게 바뀌면 화면은 이렇게 보여야 한다"만 기술하고, 실제로 어떤 DOM 노드를 건드릴지는 리액트(가상 DOM의 Diffing과 재조정)가 알아서 계산한다.

### | SWC가 TSX를 변환하는 과정 |

- Next.js는 Babel/Webpack 대신 Rust 기반의 SWC/Turbopack을 쓰는데, 오늘은 그 SWC가 정확히 무엇을 변환하는지를 배운다 — 웹 브라우저는 TSX 문법을 읽지 못하므로, SWC 엔진이 TSX 코드를 순수 자바스크립트 함수 호출 코드(`React.createElement`)로 자동 변환해준다.
- TSX가 결국 `React.createElement()`라는 함수 호출로 바뀐다는 사실은 "컴포넌트는 왜 단일 루트 요소만 반환해야 하는가"의 근본적인 이유이기도 하다. 함수는 한 번에 단 하나의 객체만 반환할 수 있으므로, 최상위 태그가 여러 개면애초에 변환된 자바스크립트 코드 자체가 성립하지 않는다.

### | React.JSX.Element vs React.ReactNode |

| 타입 | 의미 |
| --- | --- |
| React.JSX.Element | 오직 JSX 요소만 반환한다는 뜻으로 엄격하게 제한 |
| React.ReactNode | JSX 요소뿐 아니라 문자열, 숫자, null, 함수, 객체 등 더 폭넓은 값을 포함 |

### | 실습 — 구조화된 데이터를 TSX로 렌더링하기 |

```ts
// React 모듈과 Fragment 컴포넌트를 함께 불러온다
import React, { Fragment } from "react";

// 사용자 프로필 데이터의 타입을 명시하는 인터페이스
interface UserProfile {
  userName: string;
  userRole: string;
  itemPrice: number;
  itemCount: number;
  isVIP: boolean;
  hasCoupon: boolean;
}

// 반환 타입 React.JSX.Element — 이 함수가 명확한 JSX 요소를 반환함을 타입 시스템에 알림
export default function HomePage(): React.JSX.Element {
  const user: UserProfile = {
    userName: "김민수",
    userRole: "수강생",
    itemPrice: 15000,
    itemCount: 2,
    isVIP: true,
    hasCoupon: true,
  };

  return (
    // Fragment — 실제 브라우저 DOM에 감싸는 태그를 남기지 않음
    <Fragment>
      <h1>{user.userName}님의 프로필</h1>
      <hr />
      <div>
        <p>직업: {user.userRole}</p>
        <br />
        {/* 삼항 연산자 — isVIP 값에 따라 다른 문구 출력 */}
        <p>회원 등급: {user.isVIP ? "VIP 회원" : "일반 회원"}</p>
        {/* && 연산자(단락 회로 평가) — hasCoupon이 true일 때만 출력 */}
        {user.hasCoupon && <p>사용 가능한 10% 할인 쿠폰이 있습니다!</p>}
        <p>총 결제 예정 금액: {user.itemPrice * user.itemCount}원</p>
      </div>
    </Fragment>
  );
}
```

- 이 코드가 실제로 만드는 화면: "김민수님의 프로필"이라는 제목 아래 가로줄(`<hr />`)이 하나 그어지고, "직업: 수강생" 문장과 줄바꿈(`<br />`) 뒤에 "회원 등급: VIP 회원"(삼항 연산자 결과), "사용 가능한 10% 할인 쿠폰이 있습니다!"(hasCoupon이 true라서 출력됨), 마지막으로 "총 결제 예정 금액: 30000원"(15000 × 2, 중괄호 안에서 바로 연산)이 차례로 보인다. 만약 `hasCoupon`이 `false`였다면 `&&` 뒤의 `<p>` 전체가 화면에서 통째로 사라진다 — `if`문을 쓰지 않고도 조건부 렌더링이 가능한 이유다.

### | 용어 정리 |

| 용어 | 영어 표현 | 설명 |
| --- | --- | --- |
| 선언적 UI | Declarative UI | 결과 상태만 정의하면 리액트가 변경 사항을 알아서 적용하는 방식 |
| SWC | Speedy Web Compiler | TSX를 React.createElement 호출 코드로 변환하는 Rust 기반 컴파일러 |
| 단락 회로 평가 | Short-circuit Evaluation | 조건이 true일 때만 뒤의 요소를 반환하는 `&&` 연산 규칙 |
| React.JSX.Element | React.JSX.Element | JSX 태그 형태만을 반환하도록 제한하는 엄격한 타입 |

# PART 3. 컴포넌트 기초, Props 전달 & 구조 분해 할당
### | 컴포넌트란 무엇인가 |

- **컴포넌트(Component)**는 화면의 특정 영역(버튼, 카드, 헤더 등)을 만드는 자바스크립트/타입스크립트 함수다. JSX를 반환하며, 한 번 만들어두면 여러 페이지에서 레고 블록처럼 재사용할 수 있다.

### | 컴포넌트를 정의하는 3가지 규칙 |

| 규칙 | 내용 |
| --- | --- |
| ① 파스칼 케이스(PascalCase) | 함수 이름의 첫 글자는 반드시 대문자(예: `ProductCard`) — 소문자로 시작하면 리액트가 일반 HTML 태그로 오인함 |
| ② JSX 반환 | `return ( ... )`로 화면에 표시할 코드를 반환 |
| ③ export 여부 | 다른 파일에서 쓸 컴포넌트는 `export default`, 파일 내부 전용은 `export` 없이 선언 |

```ts
// [내부 전용 컴포넌트] export가 없으므로 이 파일 내부에서만 보조용으로 쓰임
function StockBadge(): React.JSX.Element {
  return <span style={{ color: 'green', fontWeight: 'bold' }}>[재고 있음]</span>;
}

// [외부 공개용 메인 컴포넌트] export default가 붙어 다른 파일에서 import 가능
export default function ProductCard(): React.JSX.Element {
  return (
    <div style={{ border: '1px solid #ccc', padding: '16px', borderRadius: '8px' }}>
      <h2>무선 게이밍 마우스 <StockBadge /></h2>
      <p>가격: 49,000원</p>
    </div>
  );
}
```

- 이 코드가 만드는 화면: 테두리가 있는 카드 안에 "무선 게이밍 마우스" 제목과 그 옆에 초록색 굵은 글씨로 "[재고 있음]"이 함께 출력되고, 그 아래 "가격: 49,000원" 문단이 보인다. `StockBadge`는 `export`가 없어서 이 파일 밖에서는 `import`할 수 없다 — 이 파일 안의 `ProductCard`를 조립하는 부품으로만 쓰인다.

### | Props — 부모에서 자식으로 데이터 전달하기 |

- **Props(Properties)**는 부모 컴포넌트가 자식 컴포넌트의 속성(Attribute) 형태로 넘겨주는 데이터다. 데이터는 항상 **[부모 → 자식]** 한 방향으로만 흐르며, 자식은 전달받은 Props를 직접 수정할 수 없다(Read-only).
- 문자열은 큰따옴표/작은따옴표로 감싸 전달하고(`title="무선 게이밍 마우스"`), 숫자·불리언·변수·객체 같은 자바스크립트 값은 중괄호로 감싸 전달한다(`price={49000}`, `isStock={true}`).

```ts
// [app/components/ProductCard.tsx - 자식 컴포넌트]
interface ProductCardProps {
  title: string;
  price: number;
  isStock: boolean;
}

export default function ProductCard(props: ProductCardProps): React.JSX.Element {
  return (
    <div style={{ border: '1px solid #ccc', padding: '16px', borderRadius: '8px' }}>
      <h2>{props.title}</h2>
      <p>가격: {props.price.toLocaleString()}원</p>
      <p>상태: {props.isStock ? '구매 가능' : '품절'}</p>
    </div>
  );
}
```

```ts
// [app/page.tsx - 부모 컴포넌트]
import ProductCard from './components/ProductCard';

export default function HomePage(): React.JSX.Element {
  return (
    <main style={{ padding: '20px' }}>
      <h1>오늘의 추천 상품</h1>
      <ProductCard title="무선 게이밍 마우스" price={49000} isStock={true} />
    </main>
  );
}
```

- 만약 Props에 타입을 지정하지 않았다면 어떻게 될까. `price` 자리에 실수로 문자열 `"49000"`을 넘겨도 컴파일 시점에는 아무 문제가 없다가, 자식 컴포넌트 안에서 `props.price.toLocaleString()`처럼 숫자 전용 메서드를 호출하는 순간 런타임 에러가 터지거나, `price * count` 같은 연산에서 의도치 않은 문자열 이어붙이기가 일어날 수 있다. `ProductCardProps` 인터페이스로 타입을 고정해두면 이런 실수를 컴파일 시점에 바로 잡아낸다.

### | 구조 분해 할당(Destructuring)으로 Props 다루기 |

- 매번 `props.title`, `props.price`처럼 점(`.`) 표기를 반복하는 대신, 매개변수 자리에서 `{ title, price, isStock }`처럼 객체를 바로 해체해 가져오면 코드가 훨씬 간결해진다.

```ts
// 매개변수 자리에서 곧바로 필요한 속성만 뽑아낸다 (props. 생략 가능)
export default function ProductCard({ title, price, isStock }: ProductCardProps): React.JSX.Element {
  return (
    <div style={{ border: '1px solid #ccc', padding: '16px', borderRadius: '8px' }}>
      <h2>{title}</h2>
      <p>가격: {price.toLocaleString()}원</p>
      <p>상태: {isStock ? '구매 가능' : '품절'}</p>
    </div>
  );
}
```

- 구조 분해 할당이 없다면 Props 속성이 5개, 10개로 늘어날수록 `props.`을 매번 타이핑해야 해서 코드 길이가 불필요하게 늘어나고 가독성도 떨어진다. 매개변수 자리에서 한 번에 해체해두면 함수 본문에서는 변수명만으로 바로 쓸 수 있다.

### | 특별한 Props — children |

- `children`은 컴포넌트의 여는 태그와 닫는 태그 사이(`<Card>여기 내용</Card>`)에 들어간 요소를 전달받는 리액트의 약속된 특별한 Prop이다. 일반 Props는 `<ProductCard price={49000} />`처럼 셀프클로징 태그로 속성을 넘기지만, children은 태그 사이에 자식 HTML이나 다른 컴포넌트를 통째로 집어넣어 감싸는(Wrapper) 구조를 만든다. 무엇이든 들어올 수 있으므로 타입은 `React.ReactNode`를 쓴다.

```ts
// [app/components/Card.tsx]
interface CardProps {
  children: React.ReactNode;
}

export default function Card({ children }: CardProps): React.JSX.Element {
  return (
    <div style={{
      border: '1px solid #e1e4e8',
      borderRadius: '12px',
      padding: '20px',
      boxShadow: '0 4px 6px rgba(0,0,0,0.05)',
      backgroundColor: '#ffffff'
    }}>
      {/* 부모가 태그 사이에 넣어준 내용이 이 위치에 렌더링됨 */}
      {children}
    </div>
  );
}
```

```ts
// [app/page.tsx]
import Card from './components/Card';
import ProductCard from './components/ProductCard';

export default function HomePage(): React.JSX.Element {
  return (
    <main style={{ padding: '20px' }}>

      <Card>
        <h2>특별 할인 공지</h2>
        <p>신규 가입 회원에게 10% 할인 쿠폰을 드립니다!</p>
      </Card>
```

# PART 4. 리액트 이벤트 & 'use client' 경계
### | 함수 '호출'과 함수 '참조'의 차이 |

| 작성 방식 | 설명 |
| --- | --- |
| `onClick={handleClick}` (올바름) | 함수 객체의 참조값만 전달 — 사용자가 실제로 클릭하는 시점에 리액트가 실행 |
| `onClick={handleClick()}` (잘못됨) | 괄호를 붙이면 컴포넌트가 렌더링되는 순간 함수가 즉시 실행돼버림 |

- 인자(값)를 넘겨야 할 때는 익명 화살표 함수로 감싸서 전달한다(`onClick={() => handleClick(productId)}`).
- 괄호를 잘못 붙였을 때 어떤 일이 벌어질까. 함수 내부에 상태를 변경하는 로직이 있다면, 렌더링 때마다 함수가 즉시 실행되고 상태 변경이 다시 렌더링을 유발하는 식으로 무한 리렌더링(Infinite Loop) 에러로 이어질 수 있다. "괄호 없이 참조만 넘긴다"는 규칙은 "실행 시점을 클릭하는 순간으로 미룬다"는 의미다.

### | 주요 리액트 이벤트 핸들러 |

| 카테고리 | 이벤트 속성 | 대상 태그 | 설명 |
| --- | --- | --- | --- |
| 마우스 | onClick | button, div 등 | 요소를 마우스로 클릭했을 때 발생 |
|  | onMouseEnter / onMouseLeave | 모든 요소 | 커서가 요소 안으로 들어오거나 밖으로 나갈 때 발생 |
| 입력/폼 | onChange | input, select 등 | 입력값이 변경될 때마다 실시간으로 발생 |
|  | onSubmit | form | 제출 버튼을 누르거나 Enter를 칠 때 발생 |
|  | onFocus / onBlur | input, textarea | 포커스가 맞춰지거나 벗어날 때 발생 |
| 키보드 | onKeyDown / onKeyUp | input, textarea | 키를 누르는/떼는 순간 발생 |

```ts
'use client'; // 이벤트를 사용하므로 클라이언트 컴포넌트로 지정

import React from 'react';

export default function EventPractice(): React.JSX.Element {
  // 마우스 클릭 이벤트 핸들러 (함수 참조용)
  const handleClick = (e: React.MouseEvent<HTMLButtonElement>): void => {
    alert('기본 클릭 이벤트 실행!');
  };

  // 인자를 받는 클릭 핸들러
  const handleItemClick = (itemName: string): void => {
    alert(`${itemName} 상품을 선택했습니다.`);
  };

  const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>): void => {
    if (e.key === 'Enter') {
      alert(`엔터 키가 입력되었습니다! 입력값: ${e.currentTarget.value}`);
    }
  };

  return (
    <div style={{ display: 'flex', flexDirection: 'column', gap: '12px' }}>
      {/* 올바른 함수 참조 방식 */}
      <button onClick={handleClick}>기본 클릭 이벤트 (함수 참조)</button>

      {/* 인자 전달용 화살표 함수 감싸기 방식 */}
      <button onClick={() => handleItemClick('게이밍 키보드')}>인자 전달 클릭 이벤트</button>

      <input
        type="text"
        placeholder="글자 입력 후 Enter를 누르세요"
        onKeyDown={handleKeyDown}
        onFocus={() => console.log('입력창 포커스 획득')}
        onBlur={() => console.log('입력창 포커스 해제')}
      />
    </div>
  );
}
```

- 이 코드가 만드는 실제 동작: 첫 번째 버튼을 누르면 "기본 클릭 이벤트 실행!"이라는 알림창이 뜨고, 두 번째 버튼을 누르면 "게이밍 키보드 상품을 선택했습니다."라는 알림창이 뜬다. 입력창에 글자를 치고 Enter를 누르면 "엔터 키가 입력되었습니다! 입력값: (입력한 글자)"가 뜨고, 입력창을 클릭하거나 벗어날 때마다 콘솔에 포커스 획득/해제 로그가 찍힌다.

### | Form 제출과 e.preventDefault() |

- HTML `<form>` 태그는 제출(submit) 시 페이지 전체를 새로고침하며 서버로 데이터를 전송하는 기본 동작이 있다. 리액트 앱에서는 전체 새로고침이 일어나면 컴포넌트가 가진 상태(State)가 전부 초기화되므로, `e.preventDefault()`로 이 기본 동작을 막아야 한다.

```ts
'use client';

export default function OrderForm(): React.JSX.Element {
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>): void => {
    e.preventDefault(); // 브라우저의 자동 새로고침 기본 동작을 차단
    alert('Form 제출 완료! 페이지가 새로고침되지 않고 유지됩니다.');
  };

  return (
    <form onSubmit={handleSubmit}>
      <input type="text" placeholder="요청사항을 입력하세요" />
      <button type="submit">요청사항 전송</button>
    </form>
  );
}
```

- `e.preventDefault()`가 없다면 어떻게 될까. '요청사항 전송' 버튼을 누르는 순간 브라우저가 페이지 전체를 새로고침해버려서, 지금까지 리액트 state에 저장해뒀던 다른 입력값이나 화면 상태가 전부 날아간다. 리액트에서 Form을 쓸 때는 이 기본 동작을 막고, 데이터 전송은 `fetch` 같은 별도 API 호출로 처리하는 게 일반적이다.

### | Next.js의 Server/Client 경계와 'use client' |

- Next.js App Router의 모든 컴포넌트는 기본적으로 **서버 컴포넌트**로 만들어진다. 서버 컴포넌트에 `onClick` 같은 브라우저 이벤트를 직접 작성하면 서버에서 에러가 난다 — 클릭이라는 동작 자체가 브라우저(클라이언트)에서만 일어날 수 있는 일이기 때문이다. 이벤트 핸들러가 포함된 파일의 **최상단**에 `'use client';` 지침을 적으면 해당 컴포넌트가 브라우저 상호작용을 처리할 수 있는 **클라이언트 컴포넌트**로 전환된다.
- `'use client'`를 선언할 때는 페이지 전체(`page.tsx`)에 붙이기보다, 이벤트를 처리하는 최소한의 자식 컴포넌트에만 선언하는 것이 성능상 좋다. `'use client'`를 쓴다고 100% CSR로만 동작하는 것은 아니다 — 초기 화면은 여전히 서버에서 HTML 뼈대를 먼저 만들고(SSR), 브라우저에 도착한 뒤 자바스크립트가 연결되어 클릭 같은 기능(CSR)이 동작하는 하이브리드 방식이며, 이 연결 과정이 바로 [10/7](2026-10-07.md)에서 배운 하이드레이션이다.
- 지침을 쓰지 않는 기본 서버 컴포넌트는 완성된 결과물만 전송하므로 브라우저로 내려가는 자바스크립트 용량을 0바이트로 유지할 수 있다. `'use client'`를 꼭 필요한 컴포넌트에만 최소한으로 붙여야 하는 이유가 여기 있다 — 범위를 넓게 잡을수록 브라우저가 다운로드하고 실행해야 할 자바스크립트가 늘어난다.

```ts
// [app/components/ProductCard.tsx] — 서버 컴포넌트 (기본값, 'use client' 없음)
export default function ProductCard({ title, price, isStock }: ProductCardProps): React.JSX.Element {
  return (
    <div>
      <h2>{title}</h2>
      <p>가격: {price.toLocaleString()}원</p>
      <p>상태: {isStock ? '구매 가능' : '품절'}</p>
    </div>
  );
}
```

```ts
// [app/components/PayButton.tsx] — 클릭 이벤트가 있으므로 클라이언트 컴포넌트
'use client';

interface PayButtonProps {
  productName: string;
}

export default function PayButton({ productName }: PayButtonProps): React.JSX.Element {
  const handlePayment = (): void => {
    alert(`${productName} 결제가 완료되었습니다!`);

  return <button onClick={handlePayment}>{productName} 결제하기</button>;

```

- 두 컴포넌트를 함께 쓰면, `ProductCard`는 서버에서 미리 그려진 채로 내려오고 `PayButton`만 브라우저에서 자바스크립트로 동작하는 식으로 역할이 나뉜다. 한 페이지 안에서도 "보여주기만 하는 부분"과 "상호작용이 필요한 부분"을 구분해서 최소한으로만 클라이언트 컴포넌트로 지정하는 것이 Next.js App Router의 기본 설계 원칙이다.

### | 용어 정리 |

| 용어 | 영어 표현 | 설명 |
| --- | --- | --- |
| 함수 참조 | Function Reference | 괄호 없이 함수 이름만 넘겨 필요한 시점에 실행되게 하는 방식 |
| 리액트 이벤트 | React Event | onClick, onChange 등 카멜 케이스로 표기하는 상호작용 속성 |
| 기본 동작 방지 | e.preventDefault() | Form 제출 시 브라우저의 자동 새로고침을 막는 메서드 |
| use client | 'use client' | 브라우저 이벤트를 다루는 컴포넌트 최상단에 적는 클라이언트 경계 지침 |

# PART 5. useRef & Direct ref prop 패턴
### | useRef의 두 가지 핵심 역할 |

- `useRef`는 화면을 다시 그리지 않고 "특정 요소의 위치"나 "비밀 데이터"를 기억하는 메모장이다. `useRef`처럼 `use`로 시작하는 리액트의 특수 기능 함수들을 **리액트 훅(React Hook)**이라고 부른다.

### | DOM 요소 직접 참조하기 |

- `useRef()`로 만든 변수를 JSX 태그의 `ref={변수명}` 속성으로 연결하면, 브라우저의 실제 DOM 노드 인스턴스가 그 변수의 `.current`에 자동으로 할당된다. 동작 순서는 "① `useRef()` 상자 생성 → ② JSX `ref` 속성으로 HTML 태그와 연결 → ③ `ref.current`를 통해 Native DOM API(`focus()`, `scrollTop`, `getBoundingClientRect()`) 직접 호출"이다.

```ts
'use client';

import { useRef } from 'react';

export default function FocusInput(): React.JSX.Element {
  // HTMLInputElement 노드 주소를 직접 참조할 변수(ref) 선언
  const inputRef = useRef<HTMLInputElement>(null);

  const handleDomOperation = () => {
    // inputRef.current는 브라우저의 실제 HTMLInputElement 객체 인스턴스
    if (inputRef.current) {
      inputRef.current.focus(); // Native DOM 메서드 호출
      console.log('현재 입력창의 placeholder:', inputRef.current.placeholder);
      console.log('입력창의 실제 너비(px):', inputRef.current.getBoundingClientRect().width);
    }
  };

  return (
    <div>
      <input ref={inputRef} type="text" placeholder="여기에 입력하세요" />
      <button onClick={handleDomOperation}>DOM 객체 제어 및 정보 조회</button>
    </div>
  );
}
```

- 이 코드가 만드는 실제 동작: 버튼을 누르면 입력창에 자동으로 커서가 이동(focus)하고, 동시에 콘솔에 "현재 입력창의 placeholder: 여기에 입력하세요"와 "입력창의 실제 너비(px): (숫자)"가 출력된다. `useRef` 없이 이걸 구현하려면 순수 자바스크립트처럼 `document.querySelector`로 DOM을 직접 찾아야 하는데, 이는 리액트의 선언적 UI 방식과 어긋난다 — `useRef`는 리액트 안에서 "예외적으로 DOM에 직접 접근해야 하는 경우"를 위한 공식 탈출구다.

### | 렌더링을 유발하지 않는 값 저장 |

| 구분 | useState | useRef |
| --- | --- | --- |
| 목적 | 화면 UI에 표시될 데이터 관리 | DOM 참조 및 화면 갱신 없는 데이터 저장 |
| 값 변경 시 | 컴포넌트 재렌더링 발생 | 재렌더링 발생하지 않음 |
| 접근 방식 | 변수명 직접 읽기 | `변수명.current`로 접근 |

```ts
'use client';

import { useRef, useState } from 'react';

export default function CounterComparison(): React.JSX.Element {
  const [stateCount, setStateCount] = useState<number>(0); // 화면을 다시 그리는 상태 변수
  const refCount = useRef<number>(0); // 값은 바뀌지만 화면을 다시 그리지 않는 참조 변수

  const increaseState = () => {
    setStateCount((prev) => prev + 1);
  };

  const increaseRef = () => {
    refCount.current = refCount.current + 1;
    console.log('현재 refCount.current 값:', refCount.current);
  };

  return (
    <div>
      <p>State 값 (화면 리렌더링 발생): <strong>{stateCount}</strong></p>
      <button onClick={increaseState}>State 증가 (화면 갱신)</button>
      <button onClick={increaseRef}>Ref 증가 (콘솔 출력만 진행)</button>
    </div>
  );
}
```

- 이 코드가 만드는 실제 동작: 'State 증가' 버튼을 누르면 화면에 보이는 숫자가 1씩 올라가지만, 'Ref 증가' 버튼을 누르면 화면의 숫자는 전혀 바뀌지 않고 콘솔(F12)에만 `refCount.current` 값이 1씩 올라가는 로그가 찍힌다. 즉 두 버튼 모두 값은 똑같이 증가하지만, 화면에 반영되는 쪽은 `useState`뿐이다.
- JSX(렌더링 영역) 안에서 `{refCount.current}`를 직접 출력하면 "Cannot access refs during render" 에러가 난다. `ref.current`는 반드시 이벤트 핸들러 내부처럼 렌더링 바깥에서만 읽어야 안전하다. 이 제약이 없다면 리액트가 렌더링 도중에 언제 바뀔지 모르는 `ref.current` 값을 읽어 화면을 그리려다가, 가상 DOM과 실제 DOM이 서로 어긋나는 예측 불가능한 상태가 생길 수 있다.

### | Direct ref prop 패턴 |

| 방식 | 설명 |
| --- | --- |
| 과거(forwardRef) | 자식 컴포넌트 내부 DOM 노드 주소를 부모에게 전달하기 위해 `forwardRef()`로 감싸야 했음 |
| 최신(Direct ref prop) | React 19 / Next.js App Router 표준에서는 `ref`를 일반 prop처럼 자식에게 직접 전달 |

```ts
'use client';

import { useRef } from 'react';

interface CustomInputProps {
  label: string;
  ref?: React.RefObject<HTMLInputElement | null>;
}

// 자식 컴포넌트 — ref를 일반 Prop으로 직접 전달받음
function CustomInput({ label, ref }: CustomInputProps): React.JSX.Element {
  return (
    <div>
      <label>{label}</label>
      {/* 부모에게 전달받은 ref를 input 엘리먼트의 ref 속성에 직접 연결 */}
      <input ref={ref} type="text" placeholder="내용을 입력하세요" />
    </div>
  );
}

// 부모 컴포넌트
export default function ParentComponent(): React.JSX.Element {
  const childInputRef = useRef<HTMLInputElement>(null);

  const handleFocusChild = () => {
    if (childInputRef.current) {
      childInputRef.current.focus();
    }
  };

  return (
    <div>
      {/* forwardRef 없이 ref를 속성으로 직접 전달 */}
      <CustomInput label="사용자 이름 입력" ref={childInputRef} />
      <button onClick={handleFocusChild}>자식 컴포넌트 입력창에 포커스</button>
    </div>
  );
}
```

- 이 코드가 만드는 실제 동작: 부모 컴포넌트의 '자식 컴포넌트 입력창에 포커스' 버튼을 누르면, 부모가 아니라 자식(`CustomInput`) 내부에 있는 입력창으로 커서가 이동한다. 부모가 자식 내부의 DOM을 직접 조작할 수 있는 이유는, `childInputRef`라는 ref 상자를 부모가 만들고 그 상자를 `ref` prop으로 자식에게 건네줬기 때문이다 — 자식은 받은 ref 상자를 자신의 `<input>` 태그에 연결만 해줄 뿐이다.
- `forwardRef`로 감싸지 않고 ref를 Props처럼 전달한다면 어떻게 될까. 과거 React에서는 일반 Props와 ref 전달 방식이 서로 다른 문법이라서, 컴포넌트를 작성할 때마다 "이 컴포넌트가 ref를 받아야 하나?"를 미리 고려해 `forwardRef`로 감싸야 했다. Direct ref prop 패턴은 ref도 다른 Props(`label` 등)와 동일한 방식으로 다룰 수 있게 해서, 이런 특수 취급을 없애고 코드를 더 일관되게 만든다.

### | 용어 정리 |

| 용어 | 영어 표현 | 설명 |
| --- | --- | --- |
| 리액트 훅 | React Hook | `use`로 시작하며 리액트의 특수 기능을 연결해주는 함수 |
| useRef | useRef | 렌더링 없이 값을 유지하거나 DOM 노드를 참조하는 훅 |
| ref 속성 | ref Attribute | `useRef()`로 만든 변수와 실제 DOM 노드를 연결하는 JSX 속성 |
| Direct ref prop | Direct Ref Prop | `forwardRef` 없이 자식 컴포넌트에 ref를 직접 전달하는 최신 패턴 |
