# TIL | 2026-09-15
## 공부한 내용 | HTML5 시멘틱 태그 & CSS

- `<div>`만 쓰던 방식에서 벗어나, 검색엔진과 화면 낭독기가 문서 구조를 이해할 수 있게 도와주는 **시멘틱 태그** 정리

- HTML로 만든 뼈대에 실제로 색과 배치를 입히는 **CSS**의 문법, 선택자, 우선순위, 박스 모델, 위치 지정까지 정리.

---

### | 시멘틱 태그(Semantic Tag)란 — `<div>` 대신 의미 있는 이름표를 쓰는 이유 |

- **시멘틱 태그** : 태그 자체에 "의미(Semantic)"를 담아 웹 문서의 구조를 정의하는 태그. 예전에는 구역을 나눌 때 아무 의미 없는 `<div>` 상자만 가득 채웠다면, 이제는 "여기는 헤더(Header) 영역이야", "여기는 푸터(Footer) 영역이야"처럼 이름표가 명확히 붙은 상자를 쓰는 것.

##### | 도입 배경 |

- HTML4 시절엔 구역을 나눌 때 무조건 의미 없는 `<div>`에 `id="header"`나 `class="footer"` 같은 별칭을 개발자 마음대로 붙였다. 사람마다 이름 짓는 규칙이 제각각이라, 구글 같은 검색엔진이 "이 페이지에서 진짜 중요한 정보가 어디 있는지" 찾기가 매우 어려웠다.

- 2014년 HTML5가 표준으로 등장하면서, 모든 개발자가 같은 이름의 태그를 쓰도록 표준 시멘틱 태그들이 도입됐다.

##### | 시멘틱 태그가 필요한 이유 3가지 |

- **검색엔진 최적화(SEO)** : 구글·네이버 검색 로봇이 `<main>`이나 `<article>` 같은 태그를 보면 "아, 여기가 핵심 정보구나!" 하고 우선 분석해서 검색 노출에 유리해진다.

- **웹 접근성(Web Accessibility)** : 시각 장애인이 화면 낭독기(스크린 리더)를 쓸 때, 시멘틱 태그가 있으면 "메뉴 영역입니다", "본문 영역입니다"라고 정확히 안내해줄 수 있다.

- **코드 가독성** : 수많은 `<div>` 더미 속에서 헤매지 않고, 태그 이름만 봐도 그 영역이 무슨 역할인지 한눈에 파악된다.

---

### | 웹 페이지 레이아웃을 구성하는 핵심 시멘틱 태그 |

- 웹사이트 구역은 크게 머리(Header), 본문(Main/Section/Article), 꼬리(Footer)로 구성된다.

| 태그 | 역할 | 비유 |
| --- | --- | --- |
| `<header>` | 맨 위 상단 영역 (로고, 검색창, 주요 내비게이션) | 신문의 제호와 발행일이 적힌 머리글 |
| `<nav>` | 다른 페이지로 이동하는 링크 모음(메뉴바) | 책 맨 앞의 목차(Index) |
| `<main>` | 문서에서 **단 한 번만** 쓸 수 있는 핵심 본문 영역 | 잡지·책의 진짜 내용이 시작되는 본문 |
| `<section>` | 본문 안에서 주제별로 연관된 내용을 묶는 영역 | 책의 '제1장', '제2장' 같은 큰 장(Chapter) |
| `<article>` | 떼어내서 다른 곳에 붙여도 완전히 이해되는 독립 콘텐츠 | 신문의 기사 하나, 블로그 포스트 하나 |
| `<aside>` | 주요 흐름과 직접 상관없는 주변부 내용(사이드바, 광고) | 책·잡지 옆면의 토막 상식이나 광고 |
| `<footer>` | 맨 아래 하단 영역(회사 정보, 저작권, 약관 링크) | 책 맨 뒷장의 발행처 정보 및 판권 |

##### | 시멘틱 태그 vs 비시멘틱 태그(`<div>`, `<span>`) 사용 기준 |

- **시멘틱 태그**를 쓰는 경우 : 구역 안 내용이 의미상 독립된 콘텐츠 영역이거나 특정 역할을 수행할 때.

- **비시멘틱 태그(`<div>`, `<span>`)**를 쓰는 경우 : 검색엔진에게 딱히 알려줄 정보가 없고, 단지 CSS 스타일(글자색, 정렬, 배경색)을 적용하려고 단순히 묶는 용도일 때.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>하루 5분 IT 뉴스 사이트</title>
</head>
<body>

    <header>
        <h1>📰 하루 5분 IT 뉴스</h1>
        <nav>
            <ul>
                <li><a href="#home">홈</a></li>
                <li><a href="#tech">테크 소식</a></li>
                <li><a href="#opinion">칼럼</a></li>
            </ul>
        </nav>
    </header>

    <main>
        <section id="tech">
            <h2>🔥 실시간 테크 뉴스</h2>
            <article>
                <h3>인공지능(AI)이 바꾸는 미래 대학 생활</h3>
                <p>최근 생성형 AI 기술의 발전으로 대학생들의 학습 방식이 혁신적으로 변하고 있습니다...</p>
            </article>
            <article>
                <h3>HTML5 시멘틱 마크업이 중요한 진짜 이유</h3>
                <p>시멘틱 태그를 활용한 마크업은 웹 사이트의 검색 노출 빈도를 극적으로 높여줍니다...</p>
            </article>
        </section>

        <aside>
            <h4>광고 및 이벤트</h4>
            <p>💻 코딩 입문자 필수 코스! 선착순 50% 할인 혜택을 놓치지 마세요!</p>
        </aside>
    </main>

    <footer>
        <p>&copy; 2026 하루 5분 IT 뉴스 Corp. All rights reserved.</p>
        <p>문의사항: contact@itnews5.com</p>
    </footer>

</body>
</html>
```

- 이 구조를 뜯어보면 : `<header>` 안에 로고(`<h1>`)와 메뉴(`<nav>`)가 들어있고, `<main>` 안에 실제 뉴스 기사들(`<section>` 안의 `<article>` 여러 개)과 광고(`<aside>`)가 들어있고, 맨 아래 `<footer>`에 저작권 정보가 들어있다. 태그 이름만 봐도 "아 여기가 메뉴구나, 여기가 기사구나"를 바로 알 수 있다는 게 시멘틱 태그의 핵심.

### | CSS란 무엇이고, 문법 구조는 어떻게 생겼나 |

- **CSS(Cascading Style Sheets)** : HTML 문서에 정의된 요소들의 시각적 스타일을 지정하는 스타일시트 언어. HTML이 뼈대를 만드는 작업이라면, CSS는 그 위에 색·크기·배치 같은 시각적 스타일을 입히는 작업이다.

```css
선택자 {
  속성: 값;
  속성: 값;
}
```

- **선택자(Selector)** : 스타일을 적용할 HTML 요소를 지목 (예: `h1`, `p`)
- **속성(Property)** : 바꾸고 싶은 스타일 특성 (예: `color`, `font-size`)
- **값(Value)** : 그 속성에 줄 구체적인 수치나 형식 (예: `blue`, `20px`)

```css
/* h1 태그의 글자 색상은 파란색, 글자 크기는 20픽셀로 설정 */
h1 {
  color: blue;
  font-size: 20px;
}
```

- **CSS 주석** : `/*`로 시작해서 `*/`로 끝난다. 한 줄이든 여러 줄이든 같은 기호를 쓴다.

##### | CSS의 두 가지 핵심 규칙 — 캐스케이딩과 상속 |

- **캐스케이딩(Cascading)** : "폭포수"라는 어원처럼, 스타일 규칙이 위에서 아래로 흐르며 적용되는 규칙. 여러 스타일이 충돌하면 우선순위에 따라 최종 적용될 스타일이 정해진다.

- **스타일 상속(Inheritance)** : 부모 요소에 적용된 특정 스타일이 자식 요소에게 자연스럽게 물려 내려온다. 예를 들어 `<body>`에 글꼴을 지정하면, 그 안의 `<p>`나 `<span>`은 따로 선언 안 해도 같은 글꼴이 적용된다.

---

### | CSS를 HTML에 적용하는 3가지 방법 |

| 방식 | 작성 위치 | 장점 | 단점 |
| --- | --- | --- | --- |
| 인라인 스타일 | HTML 태그의 `style` 속성 안 | 특정 요소에 빠르고 직관적으로 적용 | 코드가 뒤섞여 가독성 저하, 일괄 수정 불가 |
| 내부 스타일 시트 | `<head>` 안의 `<style>` 태그 안 | 외부 파일 없이 한 문서 안에서 관리 | 다른 HTML 파일에서 재사용 불가 |
| 외부 스타일 시트 (권장) | 분리된 `.css` 파일 | 구조(HTML)와 디자인(CSS) 완전 분리, 재사용성·유지보수성 최고 | `<link>` 태그로 경로를 정확히 연결해야 함 |

```html
<!-- 인라인 -->
<h1 style="color: blue; font-size: 20px;">인라인 스타일이 적용된 타이틀</h1>

<!-- 내부 스타일 시트 -->
<head>
  <style>
    h1 { color: blue; font-size: 20px; }
  </style>
</head>

<!-- 외부 스타일 시트 -->
<head>
  <link rel="stylesheet" href="style.css">
</head>
```

- 실무에서는 유지보수 때문에 **외부 스타일 시트**를 표준으로 쓴다.

### | CSS 선택자(Selector) 정리 |

##### | 기본 선택자 |

| 선택자 | 문법 | 설명 |
| --- | --- | --- |
| 전체 선택자 | `*` | 문서 내 모든 요소 선택. 주로 여백 초기화에 사용 |
| 태그 선택자 | `태그명` | 해당 태그를 가진 모든 요소 선택 |
| 클래스 선택자 | `.클래스명` | `class="..."` 속성을 가진 여러 요소를 그룹으로 선택 (재사용 가능) |
| 아이디 선택자 | `#아이디명` | `id="..."` 속성을 가진 페이지 내 유일한 요소 선택 (중복 불가) |

```css
* { margin: 0; padding: 0; }
p { color: gray; }
.btn-primary { background-color: blue; color: white; }
#main-header { height: 80px; background-color: black; }
```

##### | 복합 관계 선택자(Combinators) — 부모·자식·형제 관계로 고르기 |

| 선택자 | 문법 | 설명 |
| --- | --- | --- |
| 자식 선택자 | `부모 > 자식` | 부모 바로 한 단계 아래(1촌 자식)만 선택 |
| 하위(자손) 선택자 | `조상 자손` (공백) | 내부에 포함된 모든 후손을 깊이 상관없이 전부 선택 |
| 인접 형제 선택자 | `형 + 동생` | 바로 뒤에 인접한 동생 요소 딱 하나만 선택 |
| 일반 형제 선택자 | `형 ~ 동생` | 뒤에 오는 모든 형제 요소를 한 번에 선택 |

```css
.parent > p { color: red; }     /* 바로 아래 자식 p만 */
.ancestor p { color: blue; }    /* 몇 단계든 상관없이 내부 p 전부 */
h1 + p { font-weight: bold; }   /* h1 바로 다음 p 하나만 */
h1 ~ p { color: green; }        /* h1 뒤에 오는 p 전부 */
```

##### | 가상 클래스(`:`) vs 가상 요소(`::`) — 콜론 개수가 다르다 |

- **가상 클래스 (콜론 1개, `:`)** : HTML 구조는 그대로 둔 채, 요소의 특정 "상태"나 "조건"에 스타일을 부여. 예: `.link:hover { color: red; }`

- **가상 요소 (콜론 2개, `::`)** : HTML 문서에 없는 가상의 요소(텍스트/공간)를 CSS로 동적으로 삽입. 예: `.menu::after { content: " 🆕"; }`

- 현대 웹 표준에서는 명확한 구분을 위해 가상 요소는 `::`(콜론 2개)를 쓰는 게 원칙이다.

##### | 자주 쓰는 가상 선택자 모음 |

| 분류 | 선택자 | 설명 |
| --- | --- | --- |
| 구조/위치 | `:first-child` / `:last-child` | 부모 내부 첫/마지막 자식 (태그 종류 무관, 순서만) |
| 구조/위치 | `:nth-child(n)` | 부모 내부 n번째 자식 |
| 구조/위치 | `:first-of-type` / `:last-of-type` | 같은 태그 유형 중 첫/마지막 |
| 구조/위치 | `:nth-of-type(n)` | 같은 태그 유형 중 n번째 |
| 조건 | `:not(선택자)` | 조건과 일치하지 않는 나머지에만 적용(부정 선택자) |
| 조건 | `:is(선택자1, 선택자2)` | 여러 조합을 하나로 묶어 축약(그룹 선택자) |
| 상태 | `:hover` / `:active` | 마우스가 올라간 상태 / 클릭하고 있는 상태 |
| 상태 | `:focus` | 입력창·링크가 포커스를 획득한 상태 |
| 상태 | `:checked` | 체크박스·라디오가 체크된 상태 |
| 상태 | `:disabled` / `:enabled` | 폼 요소가 비활성/활성 상태 |
| 요소 추가 | `::before` / `::after` | 요소의 시작/끝에 가상 콘텐츠 삽입 (반드시 `content` 속성 필요) |
| 요소 추가 | `::placeholder` | input/textarea의 안내 텍스트 스타일만 제어 |
| 요소 추가 | `::selection` | 사용자가 드래그로 선택한 텍스트의 배경/글꼴색 |

```css
/* 다른 태그와 섞여 있어도 p 태그 중 2번째만 정밀 타겟팅 */
div.container p:nth-of-type(2) { color: #2ecc71; }

/* done 클래스가 없는 li에만 스타일 적용 */
ul.todo-list li:not(.done) { font-weight: bold; }

/* 체크박스가 체크되면 바로 뒤 label 색이 바뀜 */
input[type="checkbox"]:checked + label { color: #3498db; }

/* 콘텐츠가 없어도 content 속성은 반드시 필요 */
.menu::after { content: " 🆕"; }
```

### | 스타일 적용 우선순위 — 캐스케이딩과 명시도(Specificity) |

- 한 요소에 여러 CSS 규칙이 동시에 걸리면, 브라우저는 정해진 기준으로 딱 하나의 최종 스타일을 결정한다.

##### | 우선순위 결정 3대 원칙 |

1. **순수 순서 규칙(캐스케이딩)** : 가중치가 완전히 같으면, 더 나중에(아래에) 선언된 스타일이 이긴다.
2. **명시도 가중치(Specificity)** : 선택자가 더 구체적이고 좁은 범위를 겨냥할수록 점수가 높아 우선 적용된다.
3. **인라인 스타일 최우선** : 태그 안에 직접 쓴 `style="..."`은 외부/내부 파일 스타일보다 항상 높은 우선권을 가진다.

- **명시도 가중치 계층** : 인라인 스타일(1000점) > ID 선택자(100점) > 클래스/가상 클래스(10점) > 태그/가상 요소(1점) > 전체 선택자(0점)

```css
/* style.css */
#unique-item { color: purple; }  /* 1순위: ID (100점) */
.group-item  { color: orange; }  /* 2순위: 클래스 (10점) */
p            { color: gray;   }  /* 3순위: 태그 (1점) */
```

```html
<p id="unique-item" class="group-item">선택자 가중치 대결</p>
```

- 위 HTML에 세 규칙이 동시에 걸리면, 가중치가 가장 높은 **보라색(ID 선택자)**이 최종 적용된다. 인라인·내부·외부가 가중치가 같은 경우엔 "문서상 더 아래에 선언된 스타일"이 이긴다.

### | CSS 기본 속성 — 텍스트 & 폰트 |

##### | `font-family` — 글꼴 지정, 대체 폰트(Fallback) |

- 사용자 기기에 특정 글꼴이 없을 수 있어서, 여러 개의 대체 글꼴을 연달아 지정하는 게 일반적이다. 브라우저는 왼쪽부터 순서대로 탐색해서, 기기에 설치된 첫 번째 폰트를 적용한다.

```css
p { font-family: 'Malgun Gothic', 'Apple SD Gothic Neo', sans-serif; }
```

- 마지막엔 반드시 `sans-serif`(고딕체 계열)나 `serif`(명조체 계열) 같은 일반 서체 군을 적어둬야 한다 — 앞선 폰트들이 다 없을 때의 최후 안전장치.

- **시스템 폰트** : OS에 기본 내장된 폰트. 다운로드 없이 로딩이 빠르지만, OS마다 기본 폰트가 달라 화면이 다르게 보일 수 있다.
- **웹 폰트** : 서버/CDN(구글 폰트 등)에서 실시간으로 다운로드하는 폰트. 어떤 기기에서든 일관된 디자인이 가능하지만, 로딩 속도가 느려지거나 폰트가 바뀌며 깜빡이는 현상이 생길 수 있다.

##### | `font-size` — px vs rem vs em, 왜 rem을 권장할까 |

| 단위 | 종류 | 기준 |
| --- | --- | --- |
| `px` | 절대 단위 | 화면 픽셀 고정값. 사용자 브라우저 확대/축소에 능동 대응 어려움 |
| `em` | 상대 단위 | **부모 요소**의 font-size 기준. 중첩되면 계산이 복잡해짐 |
| `rem` | 상대 단위 | **최상위(`<html>`) 요소**의 font-size 기준. 구조가 깊어도 계산이 항상 일관됨 |

- 브라우저 기본 글꼴 크기는 보통 16px이므로, 구조가 아무리 깊게 중첩돼도 `1.5rem`은 항상 24px(16 × 1.5)로 명확하게 계산된다. 그래서 실무에서 `rem`이 가장 널리 권장된다.

##### | `font-weight` — 글자 굵기 |

- 키워드 : `normal`(400에 대응) / `bold`(700에 대응)
- 숫자 : 100(Thin) ~ 900(Black), 100 단위로 정밀 지정 가능. 단, 폰트가 그 두께를 실제로 지원 안 하면 브라우저가 강제로 두껍게 왜곡(Faux Bold)하거나 가장 가까운 두께로 대체한다.

##### | `line-height` — 줄 높이, 단위 없는 숫자를 권장하는 이유 |

- 기본값(`normal`)은 대략 1.2 정도라 글자가 서로 딱 붙는 느낌이라, 보통 1.5~1.8 정도로 늘려서 쓴다.

- **왜 `line-height: 1.5`(단위 없는 숫자)를 `150%`나 `1.5em`보다 권장할까 — 상속 문제 때문이다.**
  - `%`나 `em`을 쓰면, 부모의 font-size로 **계산된 결과값(절대 px)** 자체가 자식에게 상속된다. 예를 들어 부모가 `font-size: 20px; line-height: 150%;`면 계산된 `30px`이라는 고정값이 그대로 내려간다. 자식 글자가 더 커지면 줄 간격은 여전히 30px로 고정돼서 글자끼리 겹치는 사고가 날 수 있다.
  - 반면 단위 없는 숫자(`1.5`)를 쓰면, 자식에게 **"1.5배"라는 비율 공식 자체**가 상속된다. 자식 글자가 30px로 커지면 줄 간격도 알아서 45px(30 × 1.5)로 유연하게 늘어난다. 그래서 실무에서는 무조건 단위 없는 숫자를 약속처럼 사용한다.

##### | `text-align` — 초보자가 자주 하는 실수 |

- `left`(기본) / `right` / `center` / `justify`(양끝 정렬, 마지막 줄은 왼쪽 정렬 유지) 중에서 고른다.

- **자주 하는 실수** : `text-align`은 정렬 대상(텍스트)이 아니라, **그걸 감싸는 부모 블록 요소**에 선언해야 한다. `<span>`에 직접 `text-align: center;`를 줘봤자 안 먹힌다 — `<span>`을 감싸는 부모 `<div>`나 `<p>`에 줘야 한다.

##### | `color` — 색상 표기법 4가지 |

| 표기법 | 예시 | 특징 |
| --- | --- | --- |
| 색상 키워드 | `red`, `blue`, `transparent` | 직관적이지만 정교한 조절 불가. 실무에서 거의 안 씀 |
| HEX 코드 | `#FF0000` | RGB를 16진수 6자리로 표현. 가장 널리 씀. `#FF0000`→`#F00`처럼 축약 가능 |
| RGB | `rgb(255, 0, 0)` | RGB 값을 0~255 숫자로 직접 지정 |
| RGBA | `rgba(255, 0, 0, 0.5)` | RGB + 투명도(Alpha, 0.0~1.0) |

### | CSS 기본 속성 — 배경(Background) |

| 속성 | 역할 |
| --- | --- |
| `background-color` | 배경을 단색으로 채움 (기본값은 `transparent`) |
| `background-image` | `url('경로')`로 배경 이미지 지정. `linear-gradient()` 등 그라데이션도 가능 |
| `background-repeat` | `repeat`(기본, 반복) / `no-repeat`(한 번만, 가장 자주 씀) / `repeat-x` / `repeat-y` |
| `background-position` | 배경 이미지의 시작 기준점 (`center`, `top right`, `10px 50px` 등) |
| `background-size` | `auto`(원본 크기) / `cover`(비율 유지하며 꽉 채움, 잘릴 수 있음) / `contain`(비율 유지하며 전체가 다 보이게, 여백 생길 수 있음) |
| `background-attachment` | `scroll`(기본, 콘텐츠와 함께 스크롤) / `fixed`(화면에 고정, 패럴랙스 효과) |

```css
/* 개별 작성 */
.hero {
  background-color: #000000;
  background-image: url('bg.jpg');
  background-repeat: no-repeat;
  background-attachment: fixed;
  background-position: center;
  background-size: cover;
}

/* background 단축 속성으로 한 줄 요약 (color → image → repeat → attachment → position/size 순서 권장) */
.hero {
  background: #000000 url('bg.jpg') no-repeat fixed center / cover;
}
```

### | 박스 모델(Box Model) — 모든 요소는 사각형 상자다 |

- 텍스트든 이미지든, 화면에 보이는 모든 HTML 요소는 예외 없이 자신만의 사각형 영역을 차지한다. 이 상자는 안쪽부터 바깥쪽으로 4개 영역이 겹겹이 둘러싸고 있다.

| 영역 | 설명 |
| --- | --- |
| 콘텐츠(Content) | 텍스트·이미지 등 실제 내용물이 표시되는 영역 |
| 패딩(Padding) | 콘텐츠와 테두리 사이의 **안쪽** 여백 |
| 테두리(Border) | 요소를 감싸는 외곽 테두리선 |
| 마진(Margin) | 테두리 **바깥**의 여백. 다른 요소와의 간격 조절 |

```css
.box {
    width: 200px;
    height: 100px;
    background-color: lightblue;

    padding: 20px;
    border: 5px solid blue;
    margin: 30px;
}
```

##### | `box-sizing` — 박스 크기 계산 기준 |

- 패딩과 테두리를 넣으면 원래 디자인했던 크기보다 상자가 커져서 레이아웃이 무너지곤 한다. 이걸 제어하는 게 `box-sizing`.

| 구분 | `content-box` (기본값) | `border-box` (실무 권장) |
| --- | --- | --- |
| 작동 원리 | 가로폭에 패딩·테두리를 추가로 더함 | 가로폭 안에 패딩·테두리가 자동 포함됨 |
| 실제 차지 가로폭 | `width` + 좌우 패딩 + 좌우 테두리 | 지정한 `width` 값 그대로 유지 |

```css
.box-content {
    box-sizing: content-box;
    width: 200px;
    padding: 20px;
    border: 5px solid red;
    /* 실제 가로폭 = 200 + 40(패딩 좌우) + 10(테두리 좌우) = 250px */
}

.box-border {
    box-sizing: border-box;
    width: 200px;
    padding: 20px;
    border: 5px solid blue;
    /* 실제 가로폭 = 무조건 설정값인 200px */
}
```

### | `display` 속성 — 요소의 배치 성질 바꾸기 |

##### | Block vs Inline 기본 성질 |

| 구분 | Block | Inline |
| --- | --- | --- |
| 배치 | 항상 새 줄에서 시작, 부모 너비 100% | 줄바꿈 없이 나란히, 콘텐츠 크기만큼만 |
| 크기/여백 | width·height·상하좌우 margin/padding 전부 자유 | width·height 지정 불가. 좌우 margin/padding만 정상 작동, **상하 margin은 무시** |
| 대표 태그 | `<div>`, `<p>`, `<h1>~<h6>`, `<ul>`, `<li>` | `<span>`, `<a>`, `<strong>`, `<em>` |

##### | `display` 값으로 성질 바꾸기 |

| 값 | 효과 |
| --- | --- |
| `display: block;` | 인라인 요소를 블록처럼 (너비/높이/상하마진 조작 가능해짐) |
| `display: inline;` | 블록 요소를 인라인처럼 (글자처럼 나란히 흐름) |
| `display: inline-block;` | 인라인처럼 나란히 서면서 블록처럼 너비/높이/상하마진도 가능 (하이브리드) |
| `display: none;` | 화면에서 완전히 감추고, 차지하던 공간마저 지움 |

##### | `display: none` vs `visibility: hidden` — 공간을 지우느냐 마느냐 |

| 구분 | `display: none;` | `visibility: hidden;` |
| --- | --- | --- |
| 공간 차지 | 차지하지 않음 (공간 소멸) | 그대로 차지함 (투명화만) |
| 레이아웃 영향 | 주변 요소가 빈 공간을 채우려고 이동함 | 주변 요소 위치 그대로 유지 |
| 스크린 리더 | 읽지 않음 | 읽지 않음 |

```css
/* 첫 번째 컨테이너: 초록 상자를 아예 없애서 파란 상자가 위로 붙음 */
.hide-none { display: none; }

/* 두 번째 컨테이너: 초록 상자는 안 보이지만 자리는 그대로 남음 */
.hide-hidden { visibility: hidden; }
```

### | `position` 속성 — 흐름을 벗어나 자유롭게 배치하기 |

| 값 | 설명 |
| --- | --- |
| `static` (기본값) | 문서 흐름 순서대로 배치. `top`/`right`/`bottom`/`left` 줘도 무시됨 |
| `relative` (상대 배치) | **원래 있어야 할 자리**를 기준으로 이동. 주변 흐름은 안 깨짐. `absolute` 자식의 기준점 역할도 함 |
| `absolute` (절대 배치) | 문서 흐름에서 완전히 벗어남. `static`이 아닌 가장 가까운 조상을 기준으로 이동 (없으면 브라우저 전체 화면 기준) |
| `fixed` (화면 고정) | 부모와 상관없이 브라우저 창(Viewport) 기준으로 고정. 스크롤해도 그 자리에 계속 머묾 |

```css
/* 1) relative & absolute 연동 — 부모 기준으로 배지 위치 고정 */
.parent {
    position: relative;   /* 자식(absolute)의 기준점이 됨 */
    width: 250px;
    height: 300px;
}
.child {
    position: absolute;   /* .parent를 기준으로 절대 배치 */
    top: 15px;
    right: 15px;
}

/* 2) fixed — 스크롤해도 화면 우측 하단에 항상 고정되는 TOP 버튼 */
.top-button {
    position: fixed;
    bottom: 30px;
    right: 30px;
}
```

- 정리하면 : `relative`는 "원래 자리에서 살짝 옮기기", `absolute`는 "가장 가까운 relative 부모를 기준점 삼아 완전히 자유롭게 배치하기", `fixed`는 "부모 무시하고 화면 자체에 딱 붙이기".

### | HTML 요소 전체 분류 — 직접 정리해본 카테고리 |

- HTML 태그를 역할별로 크게 나눠보면 이렇게 분류된다.

| 분류 | 대표 태그 |
| --- | --- |
| 메타데이터 요소 | `<title>`, `<base>`, `<link>`, `<meta>`, `<style>` |
| 콘텐츠 구분 요소 | `<h1>~<h6>`, `<header>`, `<footer>`, `<main>`, `<article>`, `<section>`, `<aside>`, `<nav>`, `<address>`, `<div>` |
| 텍스트 콘텐츠 요소 | `<ol>`, `<ul>`, `<li>`, `<dl>`, `<dt>`, `<dd>`, `<p>`, `<hr>`, `<pre>`, `<blockquote>` |
| 인라인 텍스트 요소 | `<a>`, `<abbr>`, `<b>`, `<mark>`, `<em>`, `<strong>`, `<i>`, `<dfn>`, `<q>`, `<u>`, `<span>`, `<br>` |
| 텍스트 수정 요소 | `<ins>`, `<del>` |
| 멀티미디어 요소 | `<img>`, `<audio>`, `<video>`, `<figure>`, `<figcaption>` |
| 내장 콘텐츠 요소 | `<iframe>`, `<canvas>` |
| 스크립트 요소 | `<script>`, `<noscript>` |
| 표 콘텐츠 요소 | `<table>`, `<tr>`, `<th>`, `<td>`, `<caption>` |
| 양식 요소 | `<form>`, `<input>`, `<label>`, `<button>`, `<select>` |
| 전역 속성 (모든 태그에 붙일 수 있음) | `class`, `id`, `style`, `hidden`, `title` |

- 여기서 스스로 궁금했던 점 : **"시멘틱 태그는 그럼 거의 다 시멘틱 태그라고 부를 수 있는 거 아닌가?"** → 아니다. 위 표에서 `<div>`와 `<span>`만 "의미 없는 그릇"이고, 나머지(`<header>`, `<article>`, `<strong>`, `<table>` 등)는 전부 "이건 이런 역할이다"라는 의미를 담고 있어서 시멘틱 태그로 분류된다. 즉 **`<div>`/`<span>`을 뺀 대부분의 HTML5 태그가 이미 시멘틱 태그**라고 보면 된다.

- **"시멘틱 태그는 마크업이랑 뭐가 다른가?"** → 마크업(Markup)은 "태그로 문서를 표시하는 행위" 자체를 가리키는 더 큰 개념이고, 시멘틱(Semantic, 의미론적인)은 그 마크업을 "의미가 잘 전달되도록" 하는 방식이다. 즉 마크업이 상위 개념, 시멘틱 마크업은 그 안의 좋은 방법론 중 하나.

### | Emmet — `!` 치고 탭하면 자동완성되는 그거 |

- VS Code에서 `!`를 치고 Tab을 누르면 HTML5 기본 템플릿 코드 전체가 자동으로 생성되는 걸 본 적 있을 텐데, 이 기능의 이름이 **Emmet**이다. VS Code에 기본 내장된 자동완성 플러그인으로, 약속된 짧은 약어를 입력하고 Tab을 누르면 실제 HTML/CSS 코드로 펼쳐준다.

- `!` : HTML5 기본 템플릿(`<!DOCTYPE html>`부터 `<body>`까지) 전체를 한 번에 생성.
- 템플릿 안 `lang="en"` 부분의 `en`은 문서의 기본 언어가 영어라는 뜻 (한국어 문서면 `lang="ko"`로 직접 바꿔줘야 함).
- `<meta charset="UTF-8">`의 **UTF-8**은 문자 인코딩 방식 중 하나로, 영어·숫자·특수기호는 물론 한글을 포함한 전 세계 거의 모든 문자를 컴퓨터가 숫자로 바꿔 저장/표현할 수 있게 해주는 유니코드 기반 인코딩이다. 요즘 웹 문서는 사실상 UTF-8을 표준으로 쓴다 — 다른 인코딩(EUC-KR 등)을 쓰면 한글이 깨지는 경우가 많아서, 굳이 다른 걸 쓸 이유가 없다면 항상 UTF-8을 쓰는 게 맞다.
- 참고로 **아스키코드(ASCII)**는 영어 알파벳·숫자·특수기호 등 128개 문자만 표현 가능한 옛날 인코딩이고(1바이트만 사용), **멀티바이트 인코딩**(UTF-8 등)은 한글·한자·이모지처럼 훨씬 많은 문자를 표현하기 위해 문자 하나를 여러 바이트로 표현하는 방식이다. UTF-8은 영어는 1바이트로, 한글은 3바이트로 표현하는 식으로 문자마다 필요한 바이트 수가 달라지는 가변 길이 인코딩이다.

### | 하이퍼링크 깊게 보기 — 왜 "하이퍼"링크라고 부를까, `href`를 쓰는 태그들 |

- **하이퍼링크(Hyperlink)** : 현재 문서에서 다른 문서로 연결해 이동하는 것. "하이퍼(Hyper)"는 "보통을 뛰어넘는"이라는 뜻으로, 일반 텍스트(그냥 읽기만 하는 글)를 뛰어넘어 "클릭하면 다른 곳으로 순간이동하는 텍스트"라는 의미를 강조하려고 붙은 이름이다. 그래서 그냥 "링크"가 아니라 "하이퍼텍스트로 연결된 링크" = 하이퍼링크.

- **URL (Uniform Resource Locator)** : 인터넷에서 HTML 페이지, CSS 문서, 이미지 같은 자원(Resource)의 위치를 나타낼 때 쓴다.
  - **절대 URL** : 접근하는 최초 시작점부터 경유한 전체 경로를 다 기록 (`https://example.com/images/photo.jpg`)
  - **상대 URL** : 지금 있는 위치를 기준으로 상대적인 경로만 기록 (`./photo.jpg`, `../images/photo.jpg`)

- **`href` 속성을 쓰는 태그들 — `<a>`만 쓰는 게 아니다:**

| 태그 | 역할 |
| --- | --- |
| `<a>` | anchor(앵커, "닻"이라는 뜻) 태그. 텍스트/이미지에 링크를 걸어 클릭하면 다른 문서로 이동 |
| `<area>` | 이미지 맵에서 정의한 특정 영역을 클릭했을 때 연결되는 URL을 지정 |
| `<base>` | 문서 안의 모든 상대 URL이 따를 기준 URL을 한 번에 지정 |
| `<link>` | 문서와 연결된 외부 리소스(CSS 파일, 파비콘 등)의 경로를 지정. **페이지 이동용이 아니라 리소스 연결용** |

- 즉 **"`<a href>`와 `<link>`의 차이"**는 — `<a>`는 "클릭하면 사용자를 다른 페이지로 이동시키는 것"이고, `<link>`는 "이 문서가 쓸 외부 파일(CSS 등)을 브라우저가 미리 불러오게 연결하는 것"이라 목적 자체가 다르다.

```html
<a href="/apply.html" class="btn">신청하기</a>
```
```css
.btn {
    display: inline-block;
    padding: 10px 20px;
    background-color: yellow;
    text-decoration: none;
    border-radius: 5px;
}
```

- 위처럼 `<a>` 태그에 CSS를 입히면 링크를 버튼처럼 보이게 만들 수도 있다. (`text-decoration: none;`으로 기본 밑줄을 없애는 게 포인트)

### | `id`와 `class` 속성의 차이 |

| 구분 | `id` | `class` |
| --- | --- | --- |
| 중복 | 페이지 전체에서 **단 하나**의 요소에만 지정 (중복 불가) | 같은 유형으로 반복되는 여러 태그에 **반복 사용 가능** |
| CSS에서 부를 때 | `#아이디명` (샵 기호) | `.클래스명` (마침표) |
| 용도 | 유일한 이름을 붙이고 싶을 때 | 여러 태그를 유형별로 묶어 분류하고 싶을 때 |

- `class`는 **전역 속성(Global Attribute)**이라, `<div>`든 `<p>`든 `<span>`이든 어떤 태그에나 다 붙일 수 있다.

- CSS는 위에서 아래로 읽히기 때문에, 같은 요소에 스타일이 중간에 여러 번 반복 지정돼도 최종적으로는 **가장 마지막(맨 아래)에 적힌 스타일**이 적용된다.

### | `<div>`, `<p>`, `<span>` 완전정복 — 직접 브라우저로 비교해본 결과 |

- 셋 다 자주 헷갈리는데, 정리하면 : **`<div>`와 `<p>`는 블록 요소, `<span>`은 인라인 요소**다. 그리고 `<p>`는 "문단"을 위한 태그, `<div>`는 "레이아웃 구획 나누기"를 위한 태그다.

| 태그 | 정식 이름 | 용도 |
| --- | --- | --- |
| `<div>` | division(구획) | 레이아웃을 나누는 그룹핑용. 가로줄 전체(너비 100%)를 차지 |
| `<span>` | (span = 범위) | 줄바꿈 없이, 문장 속 텍스트 일부만 꾸미는 용도. 딱 그 텍스트 크기만큼만 차지 |
| `<p>` | paragraph(문단) | 문단·절 단위 텍스트 구분용. `<div>`와 공간 차지 방식은 같지만, 문단이라 위아래 여백(margin)이 자동으로 붙음 |

- 직접 개발자 도구로 비교해본 결과 :
  1. **공간 차지** : 글자 길이가 짧아도 `<div>`와 `<p>`는 가로 한 줄을 통째로 차지하고 혼자 줄을 바꾼다(→블록). `<span>`은 글자 크기만큼만 차지하고 옆으로 나란히 붙는다(→인라인).
  2. **`<div>` vs `<p>`** : 공간 차지 방식은 같지만, 브라우저가 `<p>`는 "문단"이라고 인식해서 문단 사이에 기본 여백(margin)을 자동으로 넣어준다. `<div>`끼리는 그런 여백이 없어서 붙어 보인다.
  3. **크기 지정** : `<div>`에 `width: 300px; height: 60px;`을 주면 그대로 300×60 상자가 되지만, `<span>`에 똑같이 줘도 **인라인 요소는 width/height를 무시**해서 여전히 글자 크기 그대로 나온다. 상자로 만들고 싶으면 `<div>`를 쓰거나 `<span>`에 `display: block;`을 따로 줘야 한다.
  4. **문장 속 일부만 강조** : 문장 중간 한 단어만 색을 바꾸고 싶으면 반드시 `<span>`을 써야 한다. `<div>`로 감싸면 블록 요소라서 그 부분이 강제로 아래 줄로 떨어져 나가 문장이 끊겨버린다.
  5. **`<p>` 안에 `<div>`를 넣으면?** : `<p>` 안에는 블록 요소를 넣을 수 없다는 규칙 때문에, 브라우저가 내가 쓴 코드를 무시하고 **`<p>`를 조용히 강제로 닫아버린다.** 개발자 도구의 Elements 탭에서 보면 내가 작성한 구조와 실제로 다르게 나타나는데, 이게 무서운 이유는 **브라우저가 에러 메시지를 안 띄우고 알아서 고쳐버리기 때문**이다. 나중에 CSS로 그 `<p>`에 색을 지정했는데 "문단 끝" 부분만 색이 안 바뀌는 식으로 한참 헤매게 된다.
     - 여기서 얻은 인사이트 : **Elements 탭은 "내가 뭘 썼냐"가 아니라 "브라우저가 내 코드를 어떻게 알아들었나"를 보여주는 창이다.** 의도한 화면과 다르게 나올 때는 여기부터 확인하면 원인을 빨리 찾을 수 있다.

##### | 포함 관계 정리 — 뭐 안에 뭘 넣을 수 있나 |

- **`<div>` 안에는 거의 다 들어간다** (의미 없는 그릇이라 제한이 없음). 실무에서 제일 많이 쓰는 조합:
```html
<div class="card">
  <p>설명 문단입니다.</p>          <!-- O -->
  <span>가격</span>                 <!-- O -->
  <div class="inner">또 상자</div>  <!-- O -->
</div>
```

- **`<p>` 안에는 인라인 요소(`<span>` 등)만 들어갈 수 있다.** `<div>`처럼 블록 요소를 넣으면 브라우저가 `<p>`를 강제로 닫아버려서 구조가 깨진다. (참고로 `<p>` 안에 `<p>`도 안 됨 — 문단 안에 문단이 있다는 게 말이 안 되기 때문)

- **`<span>` 안에 `<div>`를 넣는 건 문법적으로는 막혀있지 않지만** (브라우저가 `<p>`처럼 강제로 닫아버리진 않음), 인라인 요소 안에 블록 요소가 들어가는 거라 화면이 이상해지고, 유효성 검사 도구에서는 오류로 잡힌다. CSS도 의도와 다르게 먹는 경우가 많아서 실무에서는 피한다.

##### | 언제 `<div>`를 쓰고, 언제 시멘틱 태그를 써야 할까 |

- `<div>`를 30개쯤 중첩하면 `</div>`가 어느 것과 짝인지 못 찾게 되는데, 이걸 흔히 **"div 수프(div soup)"**라고 부른다. 시멘틱 태그를 쓰면 이 문제가 줄어드는 이유 3가지 :
  1. **코드가 읽힌다** — 태그 이름만 봐도 역할을 알 수 있음
  2. **검색엔진이 이해한다** — `<nav>`를 보면 "여긴 메뉴구나", `class="content"`는 그냥 내가 지은 이름이라 기계는 못 알아들음
  3. **화면 낭독기가 건너뛴다** — 시각장애인용 프로그램은 `<main>`으로 바로 점프하는 기능이 있는데, 전부 `<div>`면 메뉴부터 처음부터 다 읽어야 본문에 도달함

- **그럼 `<div>`는 언제 쓰나?** 의미는 필요 없고 순수하게 스타일링(레이아웃 묶기)만 필요할 때. 단, 함정은 — **`<div>`를 전부 `<section>`으로 바꾸는 것도 답이 아니다.** 그러면 "div 수프"가 "section 수프"로 바뀔 뿐이다. `<section>`은 제목(`<h2>` 등)이 붙는 주제 단위일 때만 쓴다.

- **판단 기준** : "이 덩어리에 제목을 붙인다면 뭐라고 붙일까?"가 떠오르면 `<section>`, 안 떠오르면 `<div>`. 예를 들어 공차 홈페이지 메인 화면에서, 음료 메뉴 카드 하나하나는 독립적인 콘텐츠라 `<article>`을 쓰고, 그 카드들을 가로로 늘어놓는 틀 자체는 의미가 없으니 `<div>`를 쓴다.

##### | `<section>` vs `<article>` 구분법 |

- 구분 기준 : **"이걸 통째로 떼어내서 다른 곳에 붙여도 말이 되나?"**
  - 말이 된다(독립적) → `<article>`
  - 안 된다(문서의 일부일 뿐) → `<section>`

### | 더 다양한 시멘틱 태그들 |

- 어제 다룬 레이아웃 태그(header/nav/main/section/article/aside/footer) 외에, 직접 찾아보면서 알게 된 시멘틱 태그들:

| 태그 | 설명 |
| --- | --- |
| `<form>` | 정보를 제출하기 위한 대화형 컨트롤을 담는 구획 |
| `<details>` / `<summary>` | 클릭해서 열고 닫는 공개 위젯. `<summary>`로 반드시 제목/라벨을 표기해야 함 |
| `<figure>` / `<figcaption>` | 이미지 같은 독립적인 콘텐츠(`<figure>`)와 그 설명·캡션(`<figcaption>`) |
| `<mark>` | 현재 맥락에서 중요하거나 관련 깊은 부분을 하이라이트. (`<span>` + CSS로 그냥 색만 칠하는 것과 다르게, "이 부분이 의미상 중요하다"는 정보 자체를 전달함) |
| `<time>` | 날짜·시간을 나타내는 시멘틱 태그 |
| `<address>` | 문서/기사 작성자의 연락처 정보 |

- 시멘틱 태그는 크게 두 갈래로 나뉜다 — **① 특정 영역을 구분 짓는 "박스" 역할**(header, nav, main, section 등)과 **② 그 안의 내용에 역할을 부여하는 "아이템" 역할**(mark, time, figcaption 등).

### | CSS — `background`와 `background-color`의 차이 |

- **`background-color`** : 배경의 **색상만** 지정.
- **`background`** : `color` 외에도 `image`, `position`, `repeat` 등 다양한 배경 속성을 한 번에 몰아서 지정할 수 있는 단축 속성. 각 값은 띄어쓰기로 구분해서 작성한다.

### | CSS — 취소선 긋기, 헷갈리기 쉬운 속성 |

- 취소선을 그으려면 `font-style: line-through;`가 아니라 **`text-decoration: line-through;`**가 맞다. (`font-style`은 `italic`/`normal`처럼 글자 기울임 관련 속성이고, 밑줄·취소선 같은 "선 장식"은 전부 `text-decoration`이 담당한다.)

```css
.item { text-decoration: line-through; }  /* 취소선 */
.link { text-decoration: underline; }     /* 밑줄 */
.clean { text-decoration: none; }         /* 장식 없음 (링크 밑줄 제거할 때 자주 씀) */
```

##### | 개발자 도구에서 CSS 속성에 취소선이 그어져 보이는 이유 |

- 크롬 개발자 도구의 Styles 패널에서 CSS 선언에 취소선이 그어져 있는 걸 본 적 있을 텐데, 이건 코드가 잘못됐다는 뜻이 아니라 **"이 스타일이 다른 규칙에 의해 무시(오버라이드)되고 있다"**는 표시다. 예를 들어 `* { margin: 0; }`처럼 명시도가 낮은 규칙이, 더 명시도가 높은 다른 규칙(클래스나 ID 선택자)에 덮여서 실제로는 적용 안 되고 있을 때 이렇게 취소선으로 보여준다. (아까 배운 "명시도 가중치" 개념이 실제 화면에 시각적으로 나타난 것)

---

### | CSS — `!important`, 우선순위를 강제로 뒤집는 방법 |

- 명시도 규칙을 다 무시하고 특정 스타일을 무조건 최우선으로 적용하고 싶을 때 값 뒤에 `!important`를 붙인다.

```css
p { color: red !important; }
```

- 이러면 이 선언은 ID 선택자든 인라인 스타일이든 거의 대부분을 이기고 최종 적용된다. **하지만 실무에서는 남용하면 안 된다** — 나중에 다른 사람(혹은 미래의 나)이 이 스타일을 덮어쓰려 해도 `!important`가 계속 이겨버려서, 결국 그걸 이기려고 또 다른 곳에 `!important`를 덕지덕지 붙이게 되는 악순환이 생긴다. 유지보수가 급격히 어려워지는 대표적인 안티패턴.

Q1. 체크박스로 여러 개의 취미를 선택할 수 있게 만들 때, 이를 하나의 그룹으로 묶어 서버가 선택된 값들을 배열 형태로 인식하게 하려면 어떤 속성을 동일하게 지정해야 하나요 ?

a. `id` 속성
