# PART 1. 클론코딩 핵심 개념 정리

### | 여백의 기본 — 택배 상자 모델 |

- 모든 HTML 요소는 택배 상자 하나라고 생각하면 이해가 쉽다.

```
┌──── margin (상자 바깥 여백) ────┐
│  ┌──── border (상자 껍데기) ──┐  │
│  │  ┌── padding (뽁뽁이) ──┐  │  │
│  │  │   content (내용물)   │  │  │
│  │  └────────────────────┘  │  │
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

| 이름 | 비유 | 뜻 |
| --- | --- | --- |
| content | 상자 안 물건 | 글자·그림이 실제로 있는 칸 |
| padding | 상자 안에 넣는 뽁뽁이 | 내용물과 상자 벽 사이 안쪽 여백 |
| border | 상자 종이 두께 | 상자 껍데기 선 |
| margin | 상자끼리 떨어뜨린 거리 | 다른 상자와 나 사이 바깥 여백 |

- **핵심 구분** : `padding`은 안쪽 여백이라 **내가 뚱뚱해진다**(버튼에 주면 버튼이 커짐). `margin`은 바깥 여백이라 **내 크기는 그대로, 옆 친구가 밀려난다.**

```css
padding: 16px;                 /* 사방 전부 16 */
padding: 16px 80px;            /* 위아래 16 / 좌우 80 */
padding: 135px 80px 105px;     /* 위 135 / 좌우 80 / 아래 105 */
padding: 10px 20px 30px 40px;  /* 위 오른쪽 아래 왼쪽 (시계방향) */
```

##### | `box-sizing` — 패딩이 크기에 더해지는 함정 (실제로 겪은 실수) |

```css
.header__inner {
    height: 66px;
    border-bottom: 1px solid #ccc;
    padding: 16px 80px;
}
```

- 66px 헤더를 원했는데 실제로는 `66(내용) + 16(위 패딩) + 16(아래 패딩) + 1(선) = 99px`. `box-sizing`이 없으면 padding과 border는 height에 "더해진다." 상자에 "내용물 66cm"라고 써놓고 스티로폼을 16cm씩 더 넣은 셈.

- **해결법 2가지**
  ```css
  /* 방법 1: 계산에 포함시키기 */
  box-sizing: border-box;

  /* 방법 2: 위아래 padding을 0으로 (넥슨 원본 방식) */
  height: 80px;
  padding: 0 32px;
  ```
  `width: 100%` + `padding`을 같이 쓰면 가로 스크롤바가 생기는데, 이땐 `box-sizing: border-box`가 필수다.

### | `gap` / `line-height` / `letter-spacing` |

| 속성 | 뜻 |
| --- | --- |
| `gap` | flex 안에서 자식들끼리 균일하게 벌리는 간격. `margin` 일일이 안 줘도 됨 |
| `line-height` | 한 줄의 높이(행간). 글자 위아래 숨 쉴 공간 |
| `letter-spacing` | 글자 사이 간격. 음수면 좁아짐 |

- **`line-height`를 반드시 지정해야 하는 이유** : 안 정하면 `normal`이 되는데 폰트마다 값이 다르다(보통 1.2~1.5배). 그러면 `padding`을 아무리 정확히 줘도 줄 높이가 달라서 박스 높이가 안 맞는다.
  ```css
  font-size: 14px;
  line-height: 14px;   /* 딱 글자 크기만큼 → 높이가 오로지 padding으로만 결정됨 */
  ```

- **`letter-spacing` 음수** : 굵은 글씨(`font-weight: 700`)는 자간이 넓어 보이는 착시가 있어서, 디자이너가 `-0.1px` 정도로 살짝 조인다. (넥슨은 사이트 전체에 `-0.1px` 사용)

### | Flexbox 실전 — `align-items` 함정 |

```css
display: flex;
flex-direction: row;    /* 가로 줄 (기본값) */
flex-direction: column; /* 세로 줄 */
gap: 16px;
```

| 속성 | 하는 일 |
| --- | --- |
| `justify-content` | 줄 방향(주축) 정렬 — row면 좌우, column이면 위아래 |
| `align-items` | 줄과 직각 방향(교차축) 정렬 — row면 위아래, column이면 좌우 |
| `flex-wrap` | 넘칠 때 줄바꿈 허용(wrap) / 금지(nowrap) |

- **`align-items` 함정** : 세로줄(`column`)에서 기본값은 `stretch`(다 같이 부모 폭만큼 늘어남).
  ```css
  .billboard__content {
      display: flex;
      flex-direction: column;
      width: 320px;
      /* align-items 안 주면 → 버튼이 320px 길쭉한 막대가 됨! */
      align-items: flex-start;  /* 각자 자기 내용물 크기만큼만, 왼쪽 붙임 */
  }
  ```

### | `position` — 요소를 공중에 띄우기 |

- 넥슨 헤더는 배경이 없고 빌보드 사진 위에 얹혀 있다. 실측하면 `.ness-default-header` 높이 = 0px, 배경 = `rgba(0,0,0,0)`(완전 투명). 즉 헤더와 빌보드가 같은 0px 자리에 겹쳐 있는 구조.

```css
.page-wrap {
    position: relative;   /* ← 기준점 말뚝 (이게 없으면 전부 헛것) */
}
.header {
    position: absolute;
    top: 0;
    left: 0;
    width: 100%;
    z-index: 10;
}
```

- **한 줄씩 왜인지** :
  - `position: absolute` = "너는 줄서기에서 빠져." 원래 HTML 요소는 위에서부터 한 줄로 착착 선다(=문서 흐름). `absolute`를 주면 그 줄에서 뽑혀 나와 공중에 뜬다. 헤더가 빠지면 뒤에 있던 빌보드가 자동으로 맨 위 자리로 당겨 올라온다. (비유 : 줄 서 있던 사람이 헬리콥터 타고 뜨면 뒷사람이 그 자리를 메운다)
  - `top: 0; left: 0;` = 공중에 뜬 요소를 맨 위·맨 왼쪽에 고정. 안 쓰면 원래 있던 자리에 그냥 떠 있다.
  - `width: 100%` = 공중에 뜨면 자기 내용물 크기로 쪼그라든다. block 요소가 가로를 꽉 채우던 성질을 잃어버리므로 다시 말해줘야 한다.
  - `z-index: 10` = 누가 위에 겹치나 정하는 순번표. 숫자 클수록 앞. 없으면 사진이 헤더를 덮어서 로고가 안 보일 수 있다.
  - `.page-wrap { position: relative; }` 이게 없으면 위 코드 전부 무의미 — `absolute`는 "어느 상자를 기준으로 `top: 0`이냐"를 정해야 한다. 부모를 타고 올라가며 `position`이 `static`이 아닌 첫 번째 상자를 찾고, 아무도 없으면 화면 전체가 기준이 돼서 엉뚱한 데 붙는다. `relative`는 자기 위치는 그대로 두고 기준점 역할만 한다.

| 값 | 뜻 |
| --- | --- |
| `static` | 기본값. 줄서기에 그대로 참여 |
| `relative` | 줄서기 자리는 유지하면서 기준점 역할. `top`/`left`로 살짝 밀 수도 있음 |
| `absolute` | 줄서기에서 빠져 공중에 뜸. 가장 가까운 non-static 부모가 기준 |
| `fixed` | 화면에 고정. 스크롤해도 따라다님 |

### | `display` — inline / inline-block / block |

| 값 | 줄바꿈 | 대표 태그 | width/height 먹히나 |
| --- | --- | --- | --- |
| `inline` | 안 함(옆으로 붙음) | `<a>`, `<span>` | ❌ 무시됨 |
| `inline-block` | 안 함 | — | ✅ 먹힘 |
| `block` | 함(한 줄 독차지) | `<div>`, `<h1>~<h6>`, `<p>` | ✅ 먹힘 |

- **실제로 겪은 문제** : 아이콘 `<a>`에 `height: 30px`를 줬는데 크기가 0이었다 → `<a>`는 inline이라 width/height를 무시한다.
  ```css
  .billboard__sns-link {
      display: inline-block;   /* ← 이걸 줘야 크기가 먹힌다 */
      height: 30px;
  }
  ```
  안의 `<img>`가 SVG인데 자체적으로 `width="100%" height="100%"`를 갖고 있으면, 기준이 될 부모 크기가 없으면 계산이 안 된다 → `height: 100%`를 명시해줘야 함.

- **`inline-block` 사이의 정체불명 공백** : `inline-block` 요소 2개를 나란히 두면 HTML 줄바꿈 때문에 약 4px 공백이 생긴다. → 부모를 `display: flex`로 만들고 `gap`으로 정확히 지정하면 해결.

### | 브라우저가 몰래 넣는 기본 여백 |

- `<h1>~<h6>`, `<p>`, `<ul>`은 묻지도 않고 위아래 `margin`을 기본으로 붙인다. (`<h2>` → 위아래 약 0.83em≈33px, `<h3>` → 약 1em≈16px)

- 그래서 `gap: 16px`을 줘도 `h2`의 기본 margin 33px이 더해져서 간격이 제멋대로가 된다.
  ```css
  .billboard__title {
      margin: 0;   /* ← 브라우저가 몰래 넣은 여백을 지워야 내 gap이 지켜진다 */
  }
  ```

### | 퍼센트(%) 높이가 계산 안 되는 이유 |

```html
<body>
  <img class="bg" src="...">   <!-- body에는 height가 없음 -->
</body>
```
```css
.bg { width: 100%; height: 100%; }   /* height가 무시됨! */
```

- `%`는 "부모의 몇 %"라는 뜻이다. 부모(`body`)가 "내 키는 자식들 합친 만큼이야"라고 하는데 자식이 "난 부모 키의 100%야"라고 하면 서로 쳐다보며 계산이 안 된다. → 브라우저는 `height: 100%`를 무시하고 `auto`로 처리한다. 결과 : 높이는 원본 비율대로, 너비만 100% → 엄청 긴 사진이 박힌다.

- `width: 100%`는 잘 먹힌다. 가로는 부모 폭이 항상 정해져 있기 때문. **`%` 높이를 쓰려면 부모에 높이가 있어야 한다는 게 핵심.**

### | `object-fit` vs `background-size` |

| 적용 대상 | 속성 | 용도 |
| --- | --- | --- |
| `<img>`, `<video>` 전용 | `object-fit` | 액자와 내용물 비율이 다를 때 처리법 |
| `background-image`를 쓴 모든 요소 | `background-size` | 배경 그림 크기 처리법 |

- **실제로 겪은 실수** : `background-image`에 `object-fit: cover`를 썼다 → 아무 효과 없음. 배경 이미지에는 `background-size: cover`를 써야 한다.

| 값 | 결과 |
| --- | --- |
| `fill` (object-fit 기본값) | 찌그러뜨려서 억지로 채움 |
| `contain` | 비율 지키되 남는 곳에 여백 생김 |
| `cover` | 비율 지키면서 꽉 채우고 넘치는 부분만 잘라냄 ✅ |

- 비유 : `cover`는 "비율 그대로 크게 넣고 삐져나온 가장자리는 가위로 자르기." 주의 : `object-fit`은 `width`와 `height`가 둘 다 정해져 있어야 의미가 있다. `height`가 `auto`면 자를 틀 자체가 없어서 아무 일도 안 한다.

### | `src` vs `background-image` — 같이 쓰면 안 됨 |

| 방법 | 뜻 |
| --- | --- |
| `<img src="...">` | "이 그림을 보여줘" |
| `background-image: url(...)` | "이 요소 뒤에 벽지를 발라줘" |

- `<img>`는 이미 `src` 그림으로 자기 몸을 꽉 채운다. 그 뒤에 벽지를 발라봤자 앞 그림에 가려져 영원히 안 보인다. (액자에 사진 끼워놓고 액자 뒷판에 똑같은 사진 또 붙인 꼴)

- **HTML은 위에서 아래로 쌓는 종이** : `<img>`를 배경으로 쓰려던 게 실은 "첫 번째 사진"이 되어 뒤의 요소를 아래로 밀어냈다. `<img>`도 자리를 차지하는 물건이지 배경이 아니다. → 배경으로 쓰려면 ① CSS `background-image`를 쓰거나 ② `position: absolute`로 뒤에 깔아야 한다.

### | 색 표기법 — `rgba`와 투명도, `backdrop-filter` |

```
rgba( 255 , 255 , 255 , 0.2 )
       빨강  초록  파랑   알파(불투명도)
```

- 앞 세 숫자는 빨강/초록/파랑을 각각 0~255만큼 섞기. 마지막 alpha는 불투명도(0=완전 투명, 1=꽉 찬 색). `rgba(255,255,255,0.2)`는 흰 셀로판지 한 장을 올려놓은 느낌.

- **어두운 막(dim) 씌우기** (사진 위 흰 글씨가 안 읽힐 때):
  ```css
  background-image:
      linear-gradient(rgba(0,0,0,0.55), rgba(0,0,0,0.55)),
      url("img/billboard.png");
  background-size: cover;
  background-position: center;
  ```
  검정 셀로판지 55%를 사진 위에 덮어 어둡게 만들고, 그 위의 흰 글씨가 잘 보이게 하는 기법. `background-image`는 쉼표로 여러 장을 겹칠 수 있고, 먼저 쓴 게 위에 온다.

- **`backdrop-filter` — 젖빛 유리 효과**
  ```css
  background: rgba(255, 255, 255, 0.2);
  backdrop-filter: blur(20px);
  ```
  아이폰 제어센터 같은 유리 질감. `filter: blur()`는 **나 자신**을 흐리게(글자까지 뭉개짐 ❌), `backdrop-filter: blur()`는 **내 뒤에 있는 것만** 흐리게(글자는 선명 ✅). `backdrop`(뒷배경)이라는 이름 그대로다. 반투명 배경(`rgba`)이 없으면 효과가 안 보이니 둘은 세트로 써야 한다.

### | CSS 상속 — `<a>` 색이 안 먹히는 이유 |

```css
.category-menu__title { color: #000; }   /* ❌ 링크 색이 안 바뀜 */
```

- `<a>` 태그는 브라우저가 준 자기 기본색(파란색/보라색)을 갖고 있다. **"자기가 직접 가진 색"이 "부모에게서 물려받은 색"을 항상 이긴다.**
  ```css
  .category-menu__title a { color: #000; }   /* ✅ a를 직접 겨냥 */
  ```

| 상속됨 | 상속 안 됨 |
| --- | --- |
| `color`, `font-size`, `font-family`, `font-weight`, `line-height`, `letter-spacing`, `text-align` | `width`, `height`, `margin`, `padding`, `border`, `background`, `display`, `position` |

- **크기·여백 계열은 절대 상속되지 않는다.**

### | SVG 아이콘이 안 보일 때 |

- `<img src="icon.svg">`로 불러온 SVG는 외부 CSS가 내부를 못 건드린다 (브라우저가 별개의 문서로 취급).

| 파일 안의 값 | 왜 안 보였나 |
| --- | --- |
| `fill="none"` | 색이 아예 없어서 안 보임 (넥슨 로고 사례) |
| `fill="currentColor"` | 검은 배경에서 검정으로 해석됨 (하트 아이콘 사례) |

- 해결법은 **SVG 파일 자체를 열어서 `fill="white"`로 고치는 것**. CSS로 `color`를 줘도 `<img>` 안까지는 못 들어간다. 색을 CSS로 바꾸고 싶으면 SVG 코드를 HTML에 직접 붙여넣어야 한다.

- SVG 받는 법 : 개발자도구 Elements에서 해당 `<svg>` 우클릭 → Copy → Copy element → 메모장에 붙여넣고 `.svg`로 저장 (fill 값 확인 필수)

### | `<video>` 태그 속성 |

```html
<video class="billboard__video"
       src="img/xxx.mp4"
       autoplay loop muted playsinline></video>
```

| 속성 | 뜻 |
| --- | --- |
| `autoplay` | 페이지 열리자마자 자동 재생 |
| `loop` | 끝나면 처음부터 무한 반복 |
| `muted` | 음소거 |
| `controls` | 재생바·볼륨·전체화면 UI 표시 |
| `playsinline` | 모바일에서 전체화면으로 안 튀어나오게(제자리 재생) |

- **`autoplay`는 `muted` 없이는 절대 안 된다.** 크롬·사파리 정책상 "소리 나는 영상은 사용자가 누르기 전엔 자동재생 금지"(광고가 갑자기 소리 지르는 걸 막으려는 규칙)라서, 자동재생하려면 "저 소리 안 나요"를 `muted`로 증명해야 통과된다.

- **크기는 HTML이 아니라 CSS로** : `<video width="500" height="300">`은 화면 크기가 바뀌어도 절대 안 변하지만, CSS로 지정(`width: 712px; height: 400px; object-fit: cover;`)하면 나중에 미디어쿼리로 반응형 대응이 가능하다. "모양에 관한 건 전부 CSS"가 원칙.

### | BEM 네이밍 규칙 |

```
block__element--modifier
블록__요소--상태
```

| 부분 | 뜻 | 예 |
| --- | --- | --- |
| `block` | 독립적인 덩어리 | `header`, `billboard`, `category-menu` |
| `__element` | 그 덩어리 안의 부품 | `header__logo`, `billboard__title` |
| `--modifier` | 상태나 변형 | `button--disabled`, `title--large` |

```html
<header class="header">
  <div class="header__inner">
    <div class="header__logo">
      <img class="header__logo-icon">
```

- 장점 : 클래스 이름만 보고 어디에 속한 뭔지 바로 안다. 주의 : `__`는 한 단계만 쓴다 (`header__inner__logo__icon` ❌).

### | 실측하는 습관 — 개발자도구 사용법, 8px 스케일 |

- **디자인은 보통 8의 배수로 간격을 잡는다** : `4 / 8 / 16 / 24 / 32 / 40 / 48 / 64 / 80`

| 값 | 용도 |
| --- | --- |
| 4~8px | 아이콘과 글자 사이 |
| 16~28px | 버튼 안 좌우 padding |
| 8~16px | 같은 그룹 요소 사이 |
| 24~40px | 다른 그룹 사이 |
| 32~80px | 섹션 좌우 여백 |
| 80~135px | 섹션 위아래 여백 |

- 패딩을 얼마나 줘야 할지 모르겠으면 **원본 사이트에서 직접 재는 게** 답이다.

- **개발자도구에서 값 재는 법** :
  1. 원본 페이지에서 F12 → Elements 탭
  2. 왼쪽 위 화살표 아이콘 클릭 → 재고 싶은 요소 클릭
  3. 오른쪽 **Computed 탭 = 최종 계산된 실제 값** (이걸 봐야 함. Styles 탭은 작성된 CSS 원문이라 상속·덮어쓰기 때문에 실제 값과 다를 수 있음)
  4. 상단 기기 아이콘으로 뷰포트를 1440px로 맞춘 뒤 재기 (모바일 화면에서 재면 값이 다르게 나옴)

- 이미지/영상 다운로드 : Network 탭 → 새로고침 → Img/Media 필터 → 파일 클릭 → URL 복사 → 주소창에 붙여넣기 (뒤의 `?h=1280&f=webp` 같은 쿼리스트링은 지워야 원본이 나옴)

1. HTML 뼈대 먼저 — 클래스 이름은 BEM으로 처음부터 제대로
2. 초기화 CSS — `margin: 0`, `list-style: none`, `text-decoration: none`

4. 레이아웃(flex) 먼저, 색·폰트는 나중에
5. 값이 헷갈리면 원본 개발자도구에서 재기 — 추측하지 말 것
6. 뷰포트 크기를 맞추고 재기 — 모바일에서 잰 값은 데스크톱과 다름

# PART 2. 실전에서 막혔던 것 — 증상별 해결 기록

### | 어디까지가 한 덩어리인지 모르겠다 |

- **증상** : 화면을 보면 덩어리가 나뉘어 보이는 것 같은데, 막상 태그를 치려니 어디서 끊어야 할지 판단이 안 됨. 만들었다가 지우고 합치기를 반복.

- **해결 — 기준 세 가지**
  1. **배경색이 바뀌면 거기서 끊는다** — 가장 확실한 경계.
  2. **같은 모양이 반복되면 그게 한 덩어리다** — 상품 카드처럼 반복되면 그 하나가 부품(컴포넌트).
  3. **자식이 하나뿐인 상자는 만들지 않는다** — 판단법 : "이 div를 지우면 화면이 달라지나?" 안 달라지면 필요 없는 것.

- 실제로 걷어낸 껍데기 : `billboard__title-wrap`(안에 `<h2>` 하나뿐인데 `gap` 줌 — 자식이 하나라 gap이 할 일 없음), `billboard__video-wrap`(안에 `<video>` 하나뿐, CSS도 없음)

- **배운 것** : 코드보다 경계를 먼저 정한다. 기준이 없으면 매번 다르게 자르게 된다.

---

### | 클래스 이름을 못 짓겠다 |

- **증상** : 눈에 보이는 대로 `product1`, `product2`, `bestseller1~5`처럼 이름 붙임 → 똑같이 생긴 카드 8개에 클래스가 24개 생김. 이미지 크기 하나 바꾸려면 8군데를 전부 고쳐야 했고, 하나 빠뜨리면 그 카드만 어긋남.

- **해결 — 모양이 같으면 클래스도 같게**
  ```html
  <div class="product-card">
    <img class="product-card__img" src="img/product1.png" alt="...">
    <div class="product-card__info">
      <a class="product-card__store">NEXON ESSENTIAL STORE</a>
      <div class="product-card__name">렌티큘러 포토카드</div>
    </div>
  </div>
  ```
  다른 건 이미지 경로와 글자뿐. CSS 한 줄로 카드 8개가 전부 바뀜. (클래스 37개 → 22개, 카드용 CSS 8벌 → 1벌)

- **공용 부품은 색을 자기가 갖지 않는다** — 같은 제목 부품을 검은 배경·흰 배경 양쪽에서 써야 할 때:
  ```css
  .section-head__title-text {
      font-size: 25px;
      font-weight: 900;
      /* color 없음 — 부모에게서 물려받음 */
  }
  .special-offer { color: #fff; }   /* 검은 배경 */
  .best-seller   { color: #000; }   /* 흰 배경 */
  ```
  공용 부품에는 "어디서나 같은 것"만 넣고, "장소마다 다른 것"은 부모가 정한다.

- **이름 짓는 규칙** : 확장자(`png`)나 순번(`1`, `2`)은 이름에 넣지 않는다(jpg로 바꾸면 이름이 거짓말이 됨). `__title`인데 실제로 제목이 아니면 이름이 틀린 것. **주의 : 숫자로 시작하는 클래스는 CSS를 못 붙인다** — `class="1"`이면 `.1 { }`은 문법 오류로 그 규칙 전체가 버려지는데, 오류 메시지도 안 뜬다.

---

### | 카드가 화면 밖으로 삐져나간다 — `flex`의 숨은 기본값 |

- **증상** : 상품 카드 세 개를 `display: flex`로 나란히 놨더니 마지막 카드가 화면을 넘어감. 이미지 크기를 줄여도, width를 퍼센트로 바꿔도 똑같았음.

- **원인** : flex 자식은 기본값이 **`min-width: auto`**다. 뜻은 "내 내용물보다 작아지는 건 거부한다." 안에 든 이미지가 406px이면 카드도 406px 밑으로는 절대 안 줄어든다. `flex: 1`을 줘도 이 거부권이 먼저 이긴다.

- **해결**
  ```css
  .special-offer__list .product-card {
      flex: 1;        /* 남는 공간을 나눠 갖기 */
      min-width: 0;   /* ← 내용물보다 작아져도 좋다 */
  }
  ```

- **배운 것** : 문제가 크기가 아니라 "작아지기를 거부하는 성질"에 있었다. width를 아무리 만져도 안 되는 이유가 이것. (반대로 캐러셀을 만들 거면 정반대로 `flex: 0 0 406px` — "절대 안 줄어들고 고정" → 넘쳐서 스크롤됨)

---

### | 여백을 얼마나 줘야 할지 모르겠다 — 뷰포트를 맞추고 재야 한다 |

- 처음에 잰 값이 전부 작게 나와서 이상했는데, **브라우저 창이 좁은 상태에서 쟀기 때문**이었다. 사이트가 화면 폭에 따라 값을 바꾸므로, **1440px로 맞춘 다음 다시 재야** 한다.

| 좁은 창에서 잰 값(틀림) | 항목 | 1440px 실측 |
| --- | --- | --- |
| 11px 57px | 카테고리 바 여백 | 15.5px 80px |
| 66px / 57px | 헤더 | 80px / 0 32px |
| 2rem | 배너 제목 | 40px / 48px |
| 500 × 300 | 영상 | 712 × 400 |

- **margin이냐 padding이냐** : 섹션 안쪽 숨통 = `padding`(배경색이 그 여백까지 칠해짐), 섹션끼리 띄우기 = `margin`(배경 밖). `margin: 100px`을 줬더니 그 자리에 검은 body 배경이 그대로 보여서 → `padding: 100px 80px`이 맞는 답이었다. 좌우 값은 다른 섹션과 맞춰야 세로선이 일직선으로 떨어진다.

- **배운 것** : 추측하지 않는다. 재면 5초, 추측하면 30분.

### | CSS 파일이 금방 지저분해진다 |

- **해결 ① — 파일 전체 순서 다섯 칸**

| 칸 | 내용 |
| --- | --- |
| 1. 초기화 | 브라우저 기본값 지우기 |
| 2. 변수·폰트 | `:root`에 반복되는 값 |
| 3. 레이아웃 | `.page-wrap` 같은 바깥 상자 |
| 4. 컴포넌트 | 화면에 보이는 순서 그대로 |
| 5. 미디어쿼리 | **반드시 맨 아래** |

- **해결 ② — 규칙 하나 안의 속성 순서** (밖에서 안으로) : ① 어떻게 놓이나(`display`/`position`/`z-index`) → ② 자식을 어떻게(`flex-direction`/`justify-content`/`gap`) → ③ 크기와 여백(`box-sizing`/`width`/`height`/`margin`/`padding`) → ④ 겉모습(`border`/`border-radius`/`background`) → ⑤ 글자(`color`/`font-size`/`line-height`)

- **해결 ③ — 부모를 자식보다 먼저** : HTML 구조 순서대로, 바깥 → 안쪽. 안 그러면 실수로 안쪽 스타일을 덮어쓰는 사고가 난다.

- **한 가지만 기억한다면 : CSS는 나중에 쓴 것이 이긴다.** 순서 규칙은 전부 여기서 나온다.

##### | 미디어쿼리를 맨 위에 두면 벌어지는 일 |

```css
/* 파일 맨 위에 두면... */
@media all and (min-width:1024px){ ... }

.header { ... }   /* 아래 일반 규칙이 이걸 덮어써버림 */
```

- CSS는 우선순위가 같을 때 나중에 쓴 게 이기므로, **미디어쿼리는 항상 파일 맨 아래**에 둬야 한다. (시험지에 답을 먼저 쓰고 그 위에 문제를 덮어쓴 꼴)

- 덤 : CSS 문법 오류는 **조용히 무시된다.** 브라우저는 이해 못 하는 줄을 에러 메시지 없이 그냥 버리니, 내용 채우기 전엔 주석 처리해두는 게 안전하다.

##### | CSS를 고쳤는데 안 먹히는 이유 — 선택자가 길수록 힘이 세다 |

```css
.best-seller__list .product-card img { width: 100%; }   /* 먼저 쓴 것인데도 이김 */
.product-card__img { width: 406px; }                     /* 나중에 썼는데 짐 */
```

- `.best-seller__list .product-card img`는 클래스 2개+태그 1개, `.product-card__img`는 클래스 1개 — **"나중이 이긴다"는 힘(명시도)이 같을 때의 이야기**지, 선택자가 길수록 먼저 쓴 것도 이길 수 있다.

- 긴 선택자의 다른 문제 : 특정 섹션 안으로 한정되어 있어서 다른 섹션의 같은 카드엔 적용이 안 됨. → **원칙 : 클래스 하나로 끝낸다.** `.A .B .C`처럼 줄줄이 엮지 않는다.

### | 자주 겪은 에러 & 원인 체크리스트 |

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 영상이 재생 안 됨 | `file://`로 열었음 | Live Server로 열기 |
| 영상이 재생 안 됨 | `.vscode` 폴더가 Live Server 루트를 잘못 잡음 | 그 폴더 삭제 |
| 영상이 00:00에 멈춤 | `autoplay`인데 `muted`가 없음 | `muted` 추가 |
| SVG 아이콘이 안 보임 | 파일 안에 `fill="none"`/`fill="currentColor"` | SVG 파일을 직접 수정 |
| 아이콘 크기가 0 | `<a>`가 inline이라 height 무시 | `display: inline-block` |
| 링크 색이 안 바뀜 | `<a>` 자기 기본색이 상속색을 이김 | `.부모 a { color: ... }` |
| 박스가 의도보다 큼 | padding이 height에 더해짐 | `box-sizing: border-box` |
| height:100%가 무시됨 | 부모에 height가 없음 | 부모에 height 주거나 다른 방법 |
| 요소 간격이 제멋대로 | `<h2>` 등의 브라우저 기본 margin | `margin: 0` |
| flex 세로줄에서 버튼이 길쭉해짐 | 기본값 `stretch` | `align-items: flex-start` |
| position:absolute가 엉뚱한 데 붙음 | 기준점 부모가 없음 | 부모에 `position: relative` |
| 클래스를 만들었는데 아무 변화 없음 | HTML에 그 클래스가 없음(오타) / 숫자로 시작 / 더 힘센 선택자에 덮임 | 오타·존재 여부 확인, 클래스 하나로 정리 |

- **초기화 CSS에 색을 박으면 안 되는 이유** : `a { color: #fff; }`처럼 초기화에 색을 넣으면 흰 배경 섹션이 생길 때마다 매번 덮어써야 한다. `a { color: inherit; }`으로 부모 색을 그대로 물려받게 하면, 검은 배경에선 흰색·흰 배경에선 검정으로 자동으로 맞는다. (단, 색을 아예 안 주면 브라우저 기본 파란색으로 돌아가니 주의)

Q2. `box-sizing` 속성 값 중, width와 height에 패딩과 테두리가 포함되어 계산되어 실무에서 권장되는 값은 무엇인가요 ?

내 제출 답안 : `100` (오답 ❌)

[ 정답 ] `border-box`

-> `border-box`는 지정한 width/height 안에 패딩과 테두리를 포함시켜 계산하므로 레이아웃이 무너지지 않아 실무에서 널리 권장된다. 기본값인 `content-box`는 패딩과 테두리가 추가되면 전체 크기가 커지는 문제가 있다.

Q3. 인라인(Inline) 요소인 `<span>`에 CSS를 적용할 때 나타나는 현상으로 올바른 것은 ?

### | 회고 — 클론코딩 하면서 아쉬웠던 점 |

- **이번에 한 순서(틀린 순서)** : 화면부터 만들기 → 막힘 → 고치기 → 구조가 뒤틀림 → 다 만들고 되돌아가기. 처음에 "일단 눈에 보이는 대로" 마크업부터 시작했다가, 나중에 구조 자체를 다시 짜야 하는 일이 여러 번 있었다.

- **가장 아쉬웠던 건 클래스 이름을 미리 정하지 않고 시작한 것.** `product1`, `bestseller1~5`처럼 보이는 대로 이름 붙이다가 나중에 똑같이 생긴 카드 8개에 클래스가 24개나 생겨서, 이미지 크기 하나 바꾸려고 8군데를 일일이 고쳐야 했다. BEM 규칙을 먼저 정해놓고 시작했다면 이 시행착오는 아예 없었을 일이다.

- **"자식이 하나뿐인 div"를 습관적으로 감쌌던 것도 아쉬운 부분.** 불안한 마음에 겹겹이 `<div>`로 감쌌는데, 나중에 보니 아무 역할도 안 하는 빈 껍데기가 여러 개였다. "이 div를 지우면 화면이 달라지나?"라는 질문을 처음부터 스스로에게 던졌어야 했다.

- **`flex`의 `min-width: auto` 기본값**처럼, 겉보기엔 크기 문제 같지만 실은 "작아지기를 거부하는 성질" 때문에 생긴 버그를 찾는 데 시간이 꽤 걸렸다. width를 아무리 만져도 안 먹히는 게 이상하다고 느꼈을 때, 더 빨리 "혹시 flex 자체의 기본 동작 때문 아닐까?"를 의심했어야 했는데 계속 크기값만 바꿔가며 시행착오를 반복했다.

- **여백은 눈대중으로 맞추려다가 제일 많이 헤맸다.** 개발자도구 Computed 탭에서 직접 재면 5초면 끝날 일을, 뷰포트 크기도 안 맞춘 채 감으로 숫자를 바꿔가며 30분 넘게 씨름했다. "추측하지 말고 재자"는 오늘 얻은 것 중 제일 크게 남는 교훈.

- **다음 클론코딩엔 순서를 바꿔야겠다** : 화면부터 만들지 않고, **구조 그리기 → 이름(BEM) 정하기 → 코드 쓰기** 순서로 시작하기. 그리고 값이 헷갈리면 바로 개발자도구로 재는 습관을 처음부터 들이기.
