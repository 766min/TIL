### | HTML이 뭐고, 왜 "웹 표준"을 지켜야 할까 |

- 마트 영수증을 떠올려보면, 맨 위엔 가게 이름, 중간엔 구매 항목, 맨 아래엔 결제 금액이 정해진 자리에 나뉘어 있다. 웹페이지도 마찬가지로 글자와 그림을 아무 데나 배치하는 게 아니라, 각 역할에 맞는 **뼈대**를 먼저 세워야 한다. 이 뼈대를 만드는 언어가 **HTML(HyperText Markup Language)**이다.

- **마크업 언어(Markup Language)** : 태그를 사용해서 "이 글자는 제목이다", "이 글자는 본문이다"처럼 문서의 데이터가 어떤 역할을 하는지 표시해주는 언어. HTML이 바로 이 마크업 언어에 속한다.

- **웹 표준(Web Standards)** : 크롬, 사파리, 엣지 등 **어떤 브라우저로 봐도 똑같은 화면과 기능**이 나오도록 만들어진 국제 공식 규칙이다. 이 규칙을 안 지키고 코드를 짜면, 내 컴퓨터 크롬에서는 잘 보이던 화면이 다른 사람 사파리에서는 깨져 보일 수 있다.

##### | 왜 "웹 표준"이 중요한 개념이 됐을까 — 브라우저 전쟁의 역사 |

- 2000년대 초 마이크로소프트의 **인터넷 익스플로러(IE)**가 윈도우에 기본 탑재되면서 점유율을 거의 독점(한때 95% 이상)했다. 점유율을 다 잡고 나니 마이크로소프트는 W3C(웹 표준을 정하는 국제기구) 규칙을 지킬 이유가 없어져서, **ActiveX** 같은 IE 전용 독자 기술을 밀어붙였다.

- 한국은 온라인 뱅킹·공공기관 사이트가 법적으로 **공인인증서 + ActiveX**를 요구해서, 전 세계가 IE를 떠난 뒤에도 한참 동안 "은행 업무 보려면 IE 필수"라는 상황에 갇혀 있었다. (이른바 "액티브X 논란")

- 이후 **크롬(2008)**이 웹 표준을 엄격히 지키면서 속도·확장성까지 앞서자 개발자와 사용자가 대거 이동했고, 결국 마이크로소프트도 IE를 접고 **엣지(Edge)**를 크롬과 같은 엔진(Chromium) 기반으로 새로 만들었다.

- 지금은 반대로 "누가 더 표준을 잘 지키느냐"가 경쟁력이 됐다. `caniuse.com` 같은 사이트에서 브라우저별 표준 지원 여부를 비교할 정도로, 독자 기술을 고집하기보다 표준 준수가 곧 신뢰도인 시대가 됐다.

- **태그(Tag)란?** 옷에 붙은 가격표처럼, 웹페이지의 특정 글자나 그림이 어떤 의미와 역할을 가지는지 컴퓨터에게 알려주는 "이름표"다.

  - 태그의 기본 규칙 :
    1. 보통 `<태그명>`으로 시작해서 `</태그명>`으로 끝나는 **쌍**을 이룬다.
    2. 시작 태그와 끝 태그 사이에 실제로 화면에 보여줄 내용을 넣는다. (예: `<p>내용</p>`)
    3. 예외적으로 `<meta>`, `<img>`, `<br>`, `<hr>` 같은 일부 태그는 끝나는 태그가 없는 **단독 태그**로 쓰인다.

### | HTML 문서의 필수 뼈대 4가지 |

- HTML 문서는 항상 이 4가지 태그를 갖추고 시작해야 한다.

| 태그 | 역할 |
| --- | --- |
| `<!DOCTYPE html>` | 이 문서가 최신 HTML5 버전으로 작성됐다는 걸 브라우저에 알리는 선언문 |
| `<html>` | 전체 HTML 문서의 시작과 끝을 지정하는 가장 바깥쪽 그릇 태그 |
| `<head>` | 문서 제목, 인코딩 설정 등 브라우저가 알아야 할 정보(메타데이터)를 담는 구역 — **화면에는 안 보임** |
| `<body>` | 화면에 실제로 눈에 보이는 모든 콘텐츠(텍스트, 이미지, 영상)가 들어가는 구역 |

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>나의 첫 웹 문서</title>
</head>
<body>
    화면에 글자가 나타납니다.
</body>
</html>
```

- VS Code에서 `index.html`을 작성하고 F5를 누른 다음 Web App(Chrome)을 선택하면, 바로 크롬 브라우저에서 결과를 확인할 수 있다.

##### | HTML 주석(Comment) |

- 브라우저 화면에는 안 나타나지만, 코드 안에 메모를 남겨두고 싶을 때 쓰는 게 주석이다. 코드 역할을 기록해두거나, 특정 코드를 잠깐 화면에서 감추고 싶을 때 사용한다.

- 문법 : `<!--` 로 시작해서 `-->` 로 끝나고, 그 사이에 들어간 내용은 브라우저가 통째로 무시한다.

```html
<body>
    <h1>HTML 주석 배우기</h1>
    <p>이 문단은 웹 브라우저 화면에 정상적으로 출력됩니다.</p>
    <!--<p>주석 처리된 영역은 화면에 표시되지 않습니다.</p>-->
</body>
```

### | 제목 태그(`<h1>`~`<h6>`)로 중요도 표현하기 |

- 책의 대제목·중제목·소제목처럼, 문서의 핵심 제목을 지정할 때 쓴다.

- **위계 구조** : `<h1>`이 가장 중요한 대제목이고, 숫자가 커질수록(h2, h3...) 중요도가 낮아지면서 글자 크기도 작아진다.

- **주의 사항** : 한 페이지 안에서 `<h1>`은 가장 핵심이 되는 주제 하나에만 쓰는 게 권장된다. (제목을 강조하고 싶다고 h1을 여러 개 쓰면 안 됨)

##### | 화면을 채우는 두 가지 방식 — 블록(Block) vs 인라인(Inline) |

| 구분 | 인라인(Inline) 요소 | 블록(Block) 요소 |
| --- | --- | --- |
| 줄바꿈 여부 | 줄바꿈 없이 옆으로 나란히 배치 | 태그를 쓰면 자동으로 줄바꿈 |
| 영역 크기 | 자기 콘텐츠 크기만큼만 차지 | 가로 한 줄을 전부 차지 (너비 100%) |
| 주요 태그 | `<span>`, `<strong>`, `<em>`, `<a>`, `<img>` 등 | `<h1>~<h6>`, `<p>`, `<div>`, `<ul>`, `<li>` 등 |

- **블록 요소** : 면적(상자) 개념. 새로운 정보 묶음이나 문단을 시작할 때 쓴다.

- **인라인 요소** : 흐름(선) 개념. 문장 안에서 특정 단어나 일부분만 꾸며줄 때 쓴다.

- **포함 규칙** : 블록 요소 안에는 블록 요소와 인라인 요소를 둘 다 넣을 수 있지만, **인라인 요소 안에는 블록 요소를 넣을 수 없다.**
  - `<p><span>텍스트</span></p>` → O
  - `<span><p>텍스트</p></span>` → X

##### | 본문 서식 태그로 문장 다듬기 |

| 태그 | 설명 |
| --- | --- |
| `<p>` | 하나의 독립된 문단(Paragraph). 끝나면 자동으로 줄바꿈과 여백 생김 |
| `<br>` | 문단 안에서 강제 줄바꿈(Break). 끝 태그가 없는 단독 태그 |
| `<span>` | 줄바꿈 없이 문장 안 특정 글자만 묶어서 스타일 지정할 때 |
| `<strong>` | 내용상 매우 중요한 텍스트 — 글자가 **굵게** 표시됨 |
| `<em>` | 흐름상 강조하고 싶은 텍스트 — 글자가 *이탤릭*으로 표시됨 |
| `<mark>` | 형광펜을 칠한 것처럼 배경색을 노랗게 하이라이트 |
| `<u>` | 텍스트 아래에 밑줄 |
| `<hr>` | 내용 흐름이 바뀔 때 구분하는 수평선. 단독 태그 |

```html
<body>
    <h1>1장. 프론트엔드 개발 입문</h1>
    <h2>1강. HTML의 개념</h2>
    <p>HTML은 웹 문서의 <strong>뼈대</strong>를 담당하는 언어입니다.</p>
    <p>웹 표준을 준수하면 브라우저의 종류와 관계없이<br>동일한 화면을 볼 수 있습니다.</p>
    <hr>
    <p>내일 배울 내용은 <span style="color: blue;">하이퍼링크와 멀티미디어</span> 태그입니다.</p>
    <p>오늘 과제는 <mark>저녁 10시까지</mark> 반드시 제출해야 합니다.</p>
    <p>참고 자료는 <u>공지사항 게시판</u>에서 다운로드할 수 있습니다.</p>
</body>
```

- 한 줄씩 보면 : `<strong>뼈대</strong>`는 "뼈대"라는 단어만 굵게, `<br>`은 그 자리에서 강제로 줄을 바꾸고, `<span style="color: blue;">`는 그 부분 글자만 파란색으로, `<mark>저녁 10시까지</mark>`는 그 문구에 노란 형광펜을 칠한 것처럼 강조된다.

### | 하이퍼링크 태그 `<a>` |

- `<a>` 태그는 현재 페이지에서 다른 페이지로 이동하는 "통로" 역할을 한다. Hyperlink(하이퍼링크)를 뜻하며, 반드시 어디로 이동할지 지정해주는 속성과 함께 쓴다.

- **`href` 속성** : 연결할 목적지의 주소(URL)나 파일 경로를 지정한다.

- **`target` 속성** : 링크를 클릭했을 때 연결된 문서를 어디에 표시할지 정한다.

  - `_self` (기본값) : 현재 창(탭)에서 연다. 아무것도 안 적으면 이 방식.
  - `_blank` : 완전히 새로운 창/탭에서 연다.
  - `_parent` : 현재 프레임의 부모 프레임에서 연다.
  - `_top` : 최상위 창에서 연다. 겹쳐진 프레임 구조를 다 깨고 전체 화면으로 표시.

- **경로 지정 방식**

  - **절대 경로** : 인터넷 상의 고유한 전체 주소. (예: `https://www.google.com`)
  - **상대 경로** : 지금 내 파일 위치를 기준으로 목적지 파일 위치를 찾는 방식.
    - `./` (점 하나) : 현재 파일이 있는 폴더. (예: `./about.html`)
    - `../` (점 두개) : 현재 폴더보다 한 단계 위(부모) 폴더로 이동. (예: `../images/photo.jpg`)

```html
<a href="https://www.wikipedia.org" target="_self">위키백과 열기 (현재 창에서 이동)</a>

<br><br>

<a href="https://www.wikipedia.org" target="_blank">위키백과 열기 (새 창에서 이동)</a>
```

### | 멀티미디어 삽입 태그 (`<img>`, `<audio>`, `<video>`) |

- 웹 페이지를 시각적·청각적으로 풍요롭게 만드는 태그들. `<img>`는 끝나는 태그가 없는 단독 태그, `<video>`/`<audio>`는 쌍으로 이루어진 태그다.

| 속성 | 대상 태그 | 설명 |
| --- | --- | --- |
| `src` | `<img>`/`<video>`/`<audio>` | 표시할 파일의 경로 |
| `alt` | `<img>` | 이미지를 못 불러왔을 때 나오는 대체 텍스트 (웹 접근성용) |
| `width` / `height` | `<img>` | 이미지 크기를 픽셀(px) 단위로 제한 |
| `controls` | `<video>`/`<audio>` | 재생·일시정지·볼륨 조절 바를 화면에 표시 |
| `autoplay` | `<video>`/`<audio>` | 페이지 로드 즉시 자동 재생 |
| `muted` | `<video>`/`<audio>` | 소리 없이 재생 |
| `loop` | `<video>`/`<audio>` | 재생 완료 시 처음부터 무한 반복 |
| `poster` | `<video>` 전용 | 영상 로드 전 보여줄 썸네일 이미지 |

- **주의** : 최신 브라우저는 사용자가 원치 않는 소음을 막기 위해, `muted`가 같이 선언돼야만 `autoplay`가 정상 작동하도록 제한한다. (즉, 자동재생 시키려면 `autoplay muted`를 세트로 써야 함)

```html
<img src="https://picsum.photos/300/200" alt="실습용 샘플 이미지" width="300" height="200">

<video src="https://www.w3schools.com/html/mov_bbb.mp4"
       controls
       autoplay
       muted
       loop
       poster="https://picsum.photos/400/225"
       width="400">
    최신 브라우저를 이용해 주세요.
</video>
```

### | 사용자 입력 서식, 폼 태그 (`<form>`, `<input>`) |

- `<form>` 태그는 사용자가 입력한 데이터를 모아서 서버로 전송하는 "신청서" 역할을 한다. 로그인, 회원가입, 검색창처럼 사용자가 뭔가를 입력하는 모든 공간에 쓰인다.

##### | `<form>` 속성 — action, method, target |

| 속성명 | 설명 | 입력 값 예시 |
| --- | --- | --- |
| `action` | 입력받은 데이터를 처리할 서버 주소(URL). 실습 단계에선 임시로 `#`을 주로 씀 | `/signup`, `#` |
| `method` | 데이터 전송 방식 | `get` (조회용) / `post` (생성·수정·삭제용) |
| `target` | 응답 화면을 어느 창에 띄울지 (`<a>`의 target과 동일) | `_self`, `_blank` 등 |

- **GET vs POST를 "보안"으로 구분하면 안 되는 이유** : "POST는 주소창에 데이터가 안 보이니까 안전하다"는 건 흔한 오해다. 암호화 안 된 HTTP 통신에서는 POST의 본문(Body) 데이터도 패킷 분석 프로그램으로 쉽게 가로챌 수 있다. 진짜 보안은 전송 방식이 아니라 **HTTPS 암호화 통신**으로 실현된다. GET과 POST를 구분하는 진짜 기준은 "서버 상태를 바꾸는가(Write, POST) vs 단순 조회만 하는가(Read, GET)"다.

```html
<form action="#" method="post">
</form>
```

##### | 데이터를 전송하는 열쇠 — `name`과 `value` |

- **`name`** : 서버로 전송되는 데이터 상자의 "이름(Key)". `name`이 없는 입력 태그는 전송할 때 통째로 유실된다.

- **`value`** : 그 데이터 상자에 담기는 "실제 내용물(Value)".

- **입력 유형별 value 작동 방식이 다르다:**
  - **직접 입력형** (`text`, `password`, `textarea` 등) : 사용자가 타이핑한 텍스트가 자동으로 value가 됨. 기본값을 미리 넣고 싶을 때만 `value="기본텍스트"`를 씀.
  - **선택형** (`radio`, `checkbox`, `<option>` 등) : 사용자가 클릭만 하므로, 태그 안에 `value="값"`을 개발자가 직접 미리 적어둬야 함. 안 적어두면 서버는 "클릭됐다"는 것만 알 뿐 "남성"인지 "여성"인지는 모름.

##### | 헷갈리는 `id`와 `name`의 차이 |

| 구분 | `name` 속성 | `id` 속성 |
| --- | --- | --- |
| 핵심 목적 | 웹 서버로 데이터를 전송할 때 구별하기 위함 | 브라우저 내부에서 특정 요소를 식별하기 위함 |
| 중복 허용 | 동일한 name을 여러 태그에 지정 가능 (라디오 버튼 그룹 등) | 한 페이지 내에서 유일해야 함 (중복 불가) |
| 주요 사용처 | 서버(Back-end) 데이터 처리 | CSS 디자인, JavaScript 제어, `<label>` 연결 |

##### | `<label>`과 입력 요소 연결하는 두 가지 방법 |

- 목적 : 입력창 옆에 이름표를 붙여서, 이름표를 클릭해도 입력창에 포커스가 가도록 만들어 모바일 터치·웹 접근성을 높인다.

- **방법 1 (권장)** : `<label>`의 `for` 속성값과 입력 태그의 `id` 속성값을 똑같이 맞춰서 연결.
```html
<label for="userName">이름: </label>
<input type="text" id="userName" name="userName" placeholder="이름을 입력하세요">
```

- **방법 2** : 입력 태그를 `<label>`로 직접 감싸서 연결 (별도 속성 매핑 없이 자동으로 묶임).
```html
<label>
    <input type="checkbox" id="agree" name="agree" value="y"> 약관 및 개인정보 처리에 동의합니다.
</label>
```

##### | 라디오(radio) vs 체크박스(checkbox) |

| 구분 | `<input type="radio">` | `<input type="checkbox">` |
| --- | --- | --- |
| 선택 개수 | 여러 선택지 중 **딱 하나만** | 여러 선택지 중 **복수 선택** 가능 |
| 그룹 묶는 법 | 같은 `name`으로 묶으면 한 그룹으로 인식 → 중복 선택 방지 | 같은 `name`으로 묶으면 같은 범주로 관리 |
| 서버 전송 | 선택된 단 하나의 value만 전송 | 선택된 여러 value가 배열(Array) 형태로 전송 |

```html
<p>
    <span>성별: </span>
    <input type="radio" id="male" name="gender" value="m">
    <label for="male">남성</label>

    <input type="radio" id="female" name="gender" value="f">
    <label for="female">여성</label>
</p>

<p>
    <span>관심 취미(중복 가능): </span>
    <input type="checkbox" id="hobby1" name="hobby" value="sports">
    <label for="hobby1">운동</label>

    <input type="checkbox" id="hobby2" name="hobby" value="reading">
    <label for="hobby2">독서</label>
</p>
```

##### | 목록 선택(`<select>`, `<option>`)과 여러 줄 입력(`<textarea>`) |

- **`<select>` & `<option>`** : 드롭다운 형태로 목록을 펼쳐 선택하게 함. 기본 선택값은 `<option>` 안에 `selected` 속성으로 지정. `<select>`에 `name`을, 각 `<option>`에 전송될 `value`를 지정한다.

- **`<textarea>`** : 여러 줄의 긴 글을 입력받음. `cols`(가로 폭)와 `rows`(줄 높이)로 크기를 지정. 사용자가 직접 타이핑하므로 별도 `value` 속성 없이 태그 사이 글이 그대로 전달된다.

```html
<p>
    <label for="emailDomain">이메일 계정: </label>
    <input type="text" name="emailId" placeholder="이메일 주소"> @
    <select id="emailDomain" name="emailDomain">
        <option value="naver.com">naver.com</option>
        <option value="gmail.com" selected>gmail.com</option>
        <option value="daum.net">daum.net</option>
    </select>
</p>

<p>
    <label for="intro">자기소개: </label><br>
    <textarea id="intro" name="intro" rows="4" cols="40" placeholder="자유롭게 나를 표현해 보세요."></textarea>
</p>
```

### | 오늘 실습 과제 정리 |

##### | 1강 실습 — 텍스트 태그 |

- **필수 1 : 자기소개서 마크업** — `chapter01-1/introduction.html` 생성, HTML 필수 구조 4가지를 갖추고 `<title>`을 "나를 소개합니다."로 지정한 뒤, 핵심 주제는 `<h1>`, 본문은 `<p>`로 마크업했다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>나를 소개합니다.</title>
</head>
<body>
    <h1>안녕하세요, 저는 김민지입니다</h1>
    <p>저는 SQL과 HTML을 공부하며 웹 개발의 기초를 다지고 있는 학습자입니다. 매일 배운 내용을 TIL로 정리하며 꾸준히 실력을 쌓아가고 있습니다.</p>
</body>
</html>
```

- 결과 화면 : 브라우저 탭 제목에 "나를 소개합니다."가 표시되고, 화면 맨 위에 큰 글씨(`<h1>`)로 인사말이 나온 뒤, 그 아래 문단(`<p>`)으로 소개 글이 줄바꿈과 여백을 두고 출력됨.

- **필수 2 : 네이버 뉴스 기사 구조화** — 뉴스 기사 하나를 골라서 대제목엔 `<h1>`, 부제목엔 `<h2>`, 본문은 `<p>`로 감싸고, 줄바꿈이 필요한 곳엔 `<br>`, 흐름이 바뀌는 곳엔 `<hr>`을 추가했다.

```html
<h1>기사 대제목이 들어가는 자리</h1>
<h2>기사 부제목 / 소제목</h2>
<p>
    기사 본문 첫 문단입니다.<br>
    문장 중간에 강제로 줄을 바꾸고 싶을 때 br 태그를 사용합니다.
</p>
<hr>
<p>내용의 흐름이 바뀌는 다음 문단입니다.</p>
```

- 결과 화면 : `<h1>`이 가장 크게, `<h2>`가 그보다 작게 표시되면서 제목 간 위계가 눈에 보이고, `<br>`을 넣은 자리에서만 줄이 바뀌고, `<hr>`이 있는 자리에는 가로 구분선이 그어져서 문단 사이가 시각적으로 나뉨.

- **심화 1 : 도서 서평 페이지** — 서평 본문에서 중요한 단어는 `<strong>`, 강조할 부분은 `<em>`, 특정 색만 바꿀 부분은 `<span>`, 이벤트 마감일처럼 눈에 띄어야 할 정보는 `<mark>`, 밑줄 강조는 `<u>`를 적용했다.

```html
<h1>서평 : 「데이터베이스 첫걸음」</h1>
<p>
    이 책은 <strong>비전공자도 이해할 수 있는 쉬운 설명</strong>이 가장 큰 장점이다.
    저자는 <em>실무에서 실제로 겪은 사례</em>를 예로 들어 개념을 풀어낸다.
    <span style="color: purple;">특히 4장의 정규화 부분</span>이 인상 깊었다.
</p>
<p>
    <mark>이벤트 마감 : 9월 30일까지</mark> 구매하면 전자책을 함께 받을 수 있다.
    자세한 내용은 <u>출판사 공지사항</u>에서 확인 가능하다.
</p>
```

- 결과 화면 : "비전공자도 이해할 수 있는 쉬운 설명"만 굵게, "실무에서 실제로 겪은 사례"만 기울임체로, "4장의 정규화 부분"만 보라색 글자로, "이벤트 마감 : 9월 30일까지"는 노란 형광펜이 칠해진 것처럼, "출판사 공지사항"은 밑줄이 그어진 채로 각각 표시됨.

##### | 2강 실습 — 링크/미디어/폼 |

- **필수 1 : 포토 갤러리** — 큰 제목(`<h1>` "포토 갤러리") → 소개할 사이트 이름(`<h2>`) → `<a>` 태그 안에 `<img>`를 넣어서, 사진을 클릭하면 그 사이트로 이동하도록 구현했다.

```html
<h1>포토 갤러리</h1>

<h2>위키백과</h2>
<a href="https://www.wikipedia.org" target="_blank">
    <img src="https://picsum.photos/300/200" alt="위키백과 썸네일" width="300" height="200">
</a>
```

- 결과 화면 : 사진에 마우스를 올리면 링크임을 알리는 손가락 커서로 바뀌고, 사진을 클릭하면 새 탭(`target="_blank"`)으로 위키백과 사이트가 열림. `<img>`를 `<a>` 태그 안에 넣었기 때문에 글자가 아니라 사진 전체가 클릭 영역이 됨.

- **필수 2 : 로그인 폼** — `<form>` 안에 텍스트 타입 아이디 입력창, password 타입 비밀번호 입력창을 각각 `<label>`과 연결해서 배치하고, 맨 아래에 `submit` 버튼을 추가했다.

```html
<form action="#" method="post">
    <p>
        <label for="loginId">아이디: </label>
        <input type="text" id="loginId" name="loginId" placeholder="아이디를 입력하세요">
    </p>
    <p>
        <label for="loginPw">비밀번호: </label>
        <input type="password" id="loginPw" name="loginPw" placeholder="비밀번호를 입력하세요">
    </p>
    <p>
        <button type="submit">로그인</button>
    </p>
</form>
```

- 결과 화면 : "아이디" 라벨 옆에 일반 텍스트 입력창, "비밀번호" 라벨 옆에는 글자를 입력해도 `●●●●`처럼 가려서 보여주는 입력창이 각각 한 줄씩 나오고, 맨 아래 "로그인" 버튼을 누르면 폼이 제출됨.

- **심화 1 : 설문조사 페이지** — 제목 아래에 성별/학년처럼 하나만 고르는 `radio` 영역과, 관심사처럼 여러 개 고르는 `checkbox` 영역을 만들고, 각 항목에 `<label>`을 정확히 매칭한 뒤 제출 버튼으로 마무리했다.

```html
<h1>취향 설문조사</h1>

<form action="#" method="post">
    <p>
        <span>성별: </span>
        <input type="radio" id="male" name="gender" value="m">
        <label for="male">남성</label>

        <input type="radio" id="female" name="gender" value="f">
        <label for="female">여성</label>
    </p>

    <p>
        <span>관심 분야(중복 가능): </span>
        <input type="checkbox" id="interest1" name="interest" value="sql">
        <label for="interest1">SQL</label>

        <input type="checkbox" id="interest2" name="interest" value="html">
        <label for="interest2">HTML</label>

        <input type="checkbox" id="interest3" name="interest" value="ml">
        <label for="interest3">머신러닝</label>
    </p>

    <p>
        <button type="submit">제출하기</button>
    </p>
</form>
```

- **여기서 진짜 중요한 포인트 — `name` 속성이 "같은 그룹인지 아닌지"를 결정한다.**

  - 위 코드에서 남성/여성 라디오 버튼 두 개는 `name="gender"`로 **똑같이** 맞춰져 있다. 이렇게 `name`을 같게 묶어야 브라우저가 "이 둘은 같은 질문(성별)에 대한 선택지구나"라고 인식해서, 하나를 클릭하면 다른 하나는 자동으로 선택 해제된다. **만약 `name`을 서로 다르게 줬다면, 남성과 여성을 동시에 둘 다 체크할 수 있게 돼버린다** — 원래 라디오 버튼이 의도한 "딱 하나만 선택"이라는 동작 자체가 깨지는 것.

  - 체크박스(SQL/HTML/머신러닝)도 마찬가지로 `name="interest"`로 셋 다 통일했다. 이건 라디오처럼 "하나만 선택"을 강제하려는 게 아니라, **"이 셋은 같은 질문(관심 분야)에 속한 선택지들이다"라고 서버에 알려주기 위해서**다. 그래야 사용자가 SQL과 HTML을 동시에 체크했을 때, 서버가 `interest = ["sql", "html"]`처럼 하나의 묶음(배열)으로 받을 수 있다.

  - 반면 `value`는 각 항목마다 **다르게** 줘야 한다. `value`가 없거나 다 같으면, 서버는 "관심 분야가 선택되긴 했는데 정확히 뭘 선택했는지" 구분할 수 없다.

  - 정리하면 : **`name`은 "같은 질문 그룹으로 묶는 열쇠"**, **`value`는 "그 그룹 안에서 어떤 항목을 선택했는지 구분하는 값"** — 이 둘의 역할을 헷갈리면 라디오/체크박스가 의도한 대로 동작하지 않는다.

- 결과 화면 : 성별 라디오 버튼은 남성/여성 중 하나를 클릭하면 다른 하나가 자동으로 풀리고, 관심 분야 체크박스는 여러 개를 동시에 체크된 상태로 둘 수 있음. "제출하기" 버튼을 누르면 폼 데이터가 전송됨.

- 세 실습 모두 공통으로 : **"코드를 실행한 화면을 캡처해서 작성한 코드와 함께 제출"**하는 게 검증 방법이었다. (ChatGPT 사용 금지 — 직접 태그를 찾아보면서 짜는 연습이 목적)

### | 회고 — 오늘 알게 된 점 |

- 네이버 페이지에서 "검사(Inspect)"로 요소를 클릭해서 개발자 도구(F12)의 Elements 탭을 보면, 선택한 태그 옆에 `==$0`이라는 표시가 붙는 걸 봤다. 이게 HTML 문법인 줄 알았는데, 알고 보니 **크롬 개발자 도구가 자동으로 붙여주는 표시**였다.

- `$0`은 "지금 Elements 탭에서 마지막으로 선택한 요소"를 가리키는 크롬의 특수 변수다. `==$0`은 "이 태그가 바로 그 $0이다"라고 알려주는 것.

- 신기했던 점은, Console 탭으로 가서 `$0`이라고 치면 방금 선택했던 그 요소를 콘솔에서 바로 조작해볼 수 있다는 거였다. 예를 들어 `$0.style.color = "red";`처럼 코드로 바로 실험해볼 수 있음. ( `$1`, `$2`처럼 최근 선택했던 요소 5개까지도 기억해둔다고 함 )

- 오늘 배운 HTML 태그들을 실제 서비스(네이버) 화면에서 개발자 도구로 뜯어보면서 확인해보는 습관을 들이면, 태그가 실제로 어떻게 쓰이는지 감이 더 잘 잡힐 것 같다.
