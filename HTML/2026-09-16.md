### | CSS 스타일 우선순위 — 5단계로 다시 정리 |

- 어제는 "인라인 > ID > 클래스 > 태그" 정도로 정리했는데, 오늘 `!important`까지 포함해서 전체 우선순위를 다시 정리하면:

1. `!important`
2. 인라인 스타일 (`style="..."`)
3. ID 선택자 (`#아이디`)
4. 클래스 선택자 (`.클래스`)
5. 태그 선택자 (`태그명`)

- 동일한 우선순위끼리 충돌하면, **CSS 파일을 불러온 순서**에 따라 갈린다 — 일반적으로 **더 나중에 불러온 스타일이 우선**한다.

- 범위로 외우면 쉽다 : **범위가 넓을수록 우선순위는 낮고, 범위가 좁을수록(더 구체적일수록) 우선순위는 높다.** 전체 선택자(`*`)가 제일 넓어서 제일 약하고, `style` 속성이 제일 좁아서(딱 그 요소 하나만 겨냥) 제일 강하다.

### | 속성 선택자(Attribute Selector) — 속성값으로 콕 집어 선택하기 |

| 문법 | 의미 |
| --- | --- |
| `[속성명]` | 지정된 속성이 **있기만 하면** 선택 |
| `[속성명="값"]` | 속성의 값이 정확히 **일치**하는 요소 선택 |
| `[속성명^="값"]` | 속성값이 그 값으로 **시작**하는 요소 선택 |
| `[속성명$="값"]` | 속성값이 그 값으로 **끝**나는 요소 선택 |
| `[속성명*="값"]` | 속성값에 그 값이 **포함**된 요소 선택 |

```css
/* href 속성이 존재하는 a 태그만 */
a[href] { color: blue; }

/* type이 정확히 text인 input만 */
input[type="text"] { border: 1px solid gray; }

/* href가 https로 시작하는 링크만 (외부 링크 표시 등에 활용) */
a[href^="https"] { color: green; }

/* href가 .pdf로 끝나는 링크만 (파일 다운로드 링크 표시 등) */
a[href$=".pdf"] { color: red; }
```

- 보통 단독으로 쓰기보다, `태그[속성]`처럼 다른 선택자랑 조합해서 "이 태그 중에서도 이 속성을 가진 것만" 좁혀 쓰는 경우가 많다.

### | 그룹 선택자 — 반복을 줄이는 가장 간단한 방법 |

- 여러 선택자에 **똑같은 스타일**을 적용하고 싶을 때, 컴마(`,`)로 나열하면 한 번에 묶을 수 있다.

```css
/* 반복해서 쓰면 */
h1 { color: navy; }
h2 { color: navy; }
p  { color: navy; }

/* 그룹 선택자로 줄이면 */
h1, h2, p { color: navy; }
```

- 개발자는 같은 코드를 반복해서 쓰는 걸 제일 싫어하니까, 스타일이 겹치는 태그들은 그룹으로 묶어서 관리하는 게 기본 습관이다.

### | 가상 클래스 선택자 — `:nth-child()` 공식 제대로 이해하기 |

- `:nth-child(숫자)`는 그 순번의 자식 하나만 딱 집지만, `:nth-child(수식)`은 **공식에 맞는 자식들을 반복적으로** 골라낼 수 있다. `n`에 0, 1, 2, 3...을 순서대로 대입해서 나온 값들이 선택된다.

| 공식 | `n`을 0,1,2...로 대입하면 | 결과 |
| --- | --- | --- |
| `2n+1` | 1, 3, 5, 7... | **홀수 번째** |
| `2n` | 0(무효), 2, 4, 6... | **짝수 번째** |
| `3n+1` | 1, 4, 7, 10... | **3개마다 1번씩** (1번째부터) |

```css
/* 표에서 짝수 행에만 배경색 (지브라 스트라이프) */
tr:nth-child(2n) { background-color: #f5f5f5; }

/* 목록에서 홀수 번째만 강조 */
li:nth-child(2n+1) { font-weight: bold; }
```

##### | `:first-of-type` 계열과 `:first-child` 계열의 차이 (복습) |

- `:first-child` / `:last-child` / `:nth-child` : **태그 종류와 상관없이** 순서만 본다.
- `:first-of-type` / `:last-of-type` / `:nth-of-type` / `:only-of-type` : **같은 태그 유형끼리만** 순서를 센다. (`:only-of-type`은 형제 중 같은 태그가 자기 하나뿐일 때만 선택)

##### | 상태 선택자 추가 — `:read-only`, 그리고 `:blur`는 존재하지 않는다 |

- `:read-only` : 사용자가 값을 수정할 수 없는 읽기 전용 입력창 상태.

- **`:blur`라는 가상 클래스는 CSS에 없다.** "포커스가 빠졌을 때"를 스타일링하고 싶으면, 반대로 접근해야 한다 — 어차피 포커스가 없는 게 "기본 상태"이므로, **평소 스타일은 그냥 기본으로 적어두고, `:focus`일 때만 다르게 덮어쓰는 방식**을 쓴다. 굳이 "포커스가 아닌 상태"를 콕 집어 쓰고 싶다면 `:not(:focus)`를 쓰면 된다.

```css
/* 기본 상태 (blur 상태나 마찬가지) */
input { border: 1px solid gray; }

/* 포커스 됐을 때만 예외적으로 스타일 변경 */
input:focus { border: 2px solid blue; }

/* 굳이 "포커스 아닐 때"를 쓰고 싶다면 */
input:not(:focus) { opacity: 0.7; }
```

### | `box-sizing` 다시 보기 — border-box일 때 정확히 뭐가 줄어드는가 |

- `content-box`(기본값) : `width`/`height`가 **콘텐츠 영역 기준**. 패딩·테두리가 추가되면 박스 전체 크기가 그만큼 더 커진다.

- `border-box` : `width`/`height`가 **테두리까지 포함한 전체 크기 기준**. 패딩이나 테두리 두께를 늘리면, 전체 크기는 고정된 채로 **콘텐츠 영역이 그만큼 줄어드는 식**으로 계산된다. 즉 패딩/테두리를 키우면 "바깥은 그대로, 안쪽 내용 공간만 좁아진다."

### | margin / padding 단축 표기법 — 값 개수에 따라 순서가 다르다 |

| 값 개수 | 문법 | 의미 |
| --- | --- | --- |
| 1개 | `margin: 값;` | 상하좌우 **전부 동일** |
| 2개 | `margin: 상하 좌우;` | 위아래 값, 좌우 값 |
| 3개 | `margin: 상 좌우 하;` | 위, 좌우, 아래 |
| 4개 | `margin: 상 우 하 좌;` | **시계 방향**(위→오른쪽→아래→왼쪽) |

- 방향을 개별로 지정하고 싶으면 `margin-top`, `margin-bottom`, `margin-left`, `margin-right`처럼 따로 쓸 수도 있다. `padding`도 문법이 완전히 동일하다.

- **인라인 요소에서 margin의 예외** : block 요소는 상하좌우 margin이 자유롭지만, inline 요소는 **좌우 margin만 적용되고 위아래 margin은 무시된다.** (09-15 노트에서 다룬 인라인 요소 제약과 같은 맥락)

##### | `margin: 0 auto;` — 가운데 정렬이 되는 원리 |

```css
.box {
  width: 300px;
  margin: 0 auto;   /* 상하 0, 좌우는 auto(자동 균등 배분) */
}
```

- `auto`는 "남는 공간을 브라우저가 알아서 계산해서 채워라"는 뜻이라서, 좌우에 `auto`를 주면 **남는 여백을 정확히 절반씩 나눠 가지면서 가운데로 밀린다.** 단, 이 방식은 **`width`가 정해져 있는 블록 요소**에서만 통한다.

##### | `margin: auto` 말고 다른 가운데 정렬 방법들 |

| 방법 | 코드 | 특징 |
| --- | --- | --- |
| `margin: 0 auto;` | 블록 요소에 `width` + `margin: 0 auto` | 가장 고전적인 방식. **가로만** 가운데 정렬됨 |
| `text-align: center;` | 부모에 지정 | 안의 텍스트나 인라인/인라인블록 요소를 가운데 정렬 |
| Flexbox | `display: flex; justify-content: center; align-items: center;` | 가로·세로 **동시에** 가운데 정렬 가능, 요즘 제일 많이 씀 |
| Grid | `display: grid; place-items: center;` | Flexbox보다 더 짧은 코드로 가로·세로 동시 정렬 |
| position + transform | `position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%);` | 부모 기준 완전 중앙에 절대 배치할 때 사용 |

### | `display` 속성 총정리 |

| 값 | 효과 |
| --- | --- |
| `block` | 새 줄에서 시작, 너비 100% |
| `inline` | 줄바꿈 없이 나란히, 콘텐츠 크기만큼만 |
| `inline-block` | 나란히 배치되면서도 너비·높이·상하 margin 자유롭게 지정 가능 |
| `none` | 화면에서 완전히 감춤 (공간도 사라짐) |

- `visibility: hidden;`은 `display: none;`과 다르게 **공간은 그대로 유지**한 채 안 보이게만 한다. (`visibility: visible;`이 기본값)

### | Flexbox — 1차원(가로 또는 세로) 정렬의 표준 |

- 지금까지 배운 `position`은 요소 하나하나를 개별 좌표로 배치하는 방식이었다면, **Flexbox는 "여러 자식 요소들을 한 줄로 정렬"하는 걸 훨씬 쉽게 만들어주는 도구**다. 네비게이션 메뉴, 카드 목록처럼 "여러 개를 나란히 배치"하는 레이아웃에 특히 많이 쓴다.

##### | 기본 설정 |

```css
.container {
  display: flex;   /* 부모 요소에 설정 → 이 안의 자식들이 flex 아이템이 됨 */
}
```

- `display: flex;`는 **부모 요소**에 설정하고, 그 안의 **자식 요소들**이 자동으로 "flex 아이템"이 되어 정렬 규칙의 영향을 받는다.

##### | `flex-direction` — 정렬 방향 |

| 값 | 방향 |
| --- | --- |
| `row` (기본값) | 왼쪽 → 오른쪽 (가로) |
| `row-reverse` | 오른쪽 → 왼쪽 |
| `column` | 위 → 아래 (세로) |
| `column-reverse` | 아래 → 위 |

##### | `justify-content` — 주축(main axis) 방향 정렬 |

| 값 | 효과 |
| --- | --- |
| `flex-start` (기본값) | 시작 지점(왼쪽)으로 정렬 |
| `flex-end` | 끝 지점(오른쪽)으로 정렬 |
| `center` | 가운데로 정렬 |
| `space-between` | 양 끝 요소는 가장자리에 붙이고, 나머지 요소 사이 간격을 균등하게 배분 |
| `space-around` | 각 요소 좌우에 균등한 여백을 둘러싸듯 배치 |
| `space-evenly` | 요소 사이 간격뿐 아니라 양 끝 여백까지 전부 균등하게 배분 |

- **`space-between` 실전 예시** : 웹사이트 상단 헤더에서 왼쪽엔 메뉴바, 가운데엔 로고, 오른쪽엔 장바구니·로그인 아이콘이 있는 흔한 구조가 바로 이 속성으로 만들어진다 — 양 끝 요소를 가장자리에 붙이고, 그 사이 요소들 간격을 알아서 균등하게 벌려준다.

##### | `align-items` — 교차축(cross axis) 방향 정렬 |

| 값 | 효과 |
| --- | --- |
| `stretch` (기본값) | 부모 요소의 크기에 맞춰 자식을 늘림 |
| `flex-start` | 교차축 시작 쪽(보통 위)으로 배치 |
| `flex-end` | 교차축 끝 쪽(보통 아래)으로 배치 |
| `center` | 교차축 가운데로 배치 |

```css
.navbar {
  display: flex;
  justify-content: space-between;  /* 가로: 메뉴 - 로고 - 아이콘 양끝 정렬 */
  align-items: center;             /* 세로: 높이 중앙에 딱 맞춰 정렬 */
}
```

- 정리하면 : **`justify-content`는 "주된 정렬 방향"(가로 배치면 가로), `align-items`는 "그 반대 방향(세로)"을 담당한다.** `flex-direction`이 `row`일 때 기준으로 외워두면 헷갈리지 않는다.

Q3. 다음 CSS 코드가 적용될 때, HTML 구조가 아래와 같다고 가정하면 빨간색으로 스타일이 적용되는 요소는 ?

```css
.parent > p { color: red; }
```

```html
<div class="parent">
  <p>A문단</p>
  <div><p>B문단</p></div>
</div>
```

[ 보기 ]

a. A문단만 빨간색이 된다

b. B문단만 빨간색이 된다

c. A문단과 B문단 모두 빨간색이 된다

d. 둘 다 빨간색이 되지 않는다

내 제출 답안 : b. (오답 ❌)

[ 정답 ] a. A문단만 빨간색이 된다

-> 자식 선택자(`>`)는 부모 바로 한 단계 아래에 있는 요소만 선택하므로, `parent`의 직계 자식인 A문단만 선택된다. B문단은 `parent`의 손자(자식의 자식)이므로 선택되지 않는다. 만약 하위(자손) 선택자(`.parent p`, 공백)였다면 B문단도 선택됐을 것이다.

Q5. 콜론 두 개(`::`)를 사용하며, HTML 문서에 실제로 존재하지 않는 가상의 요소를 CSS를 통해 동적으로 삽입할 때 사용하는 문법을 무엇이라고 하나요 ?

내 제출 답안 : (제출 안 함) (오답 ❌)

[ 정답 ] 가상 요소

-> 가상 요소(Pseudo-element)는 `::before`, `::after`처럼 콜론 2개를 사용하며, `content` 속성과 함께 텍스트나 디자인 공간을 동적으로 추가한다. 반면 가상 클래스는 콜론 1개(`:`)를 사용하며 요소의 상태나 조건에 스타일을 부여한다는 점에서 차이가 있다.
