# PART 1. 타입스크립트의 등장 배경

### | 자바스크립트의 한계 |

- 지금까지 배운 자바스크립트는 데이터를 자유롭고 유연하게 다룰 수 있어서 편리했다. 하지만 변수나 함수에 어떤 형태의 값이 들어올지 미리 약속하지 않기 때문에, 여러 사람이 함께 시스템을 만들 때 의도하지 않은 버그가 발생하기 쉽다.

| 문제점 | 설명 |
| --- | --- |
| 에러 검출의 지연 | 코드를 실행하기 전에는 에러를 잡을 수 없어, 실제 서비스 작동 중(런타임)에 버그가 발생하기 쉽다 |
| 협업의 어려움 | 함수에 어떤 데이터를 넘겨야 하는지 명확한 규격이 없어 오해가 발생한다 |

- **런타임 오류(Runtime Error)**란 사용자가 프로그램을 실제로 실행하여 사용하는 과정 도중에 발생하는 오류를 말한다. 코드를 저장하는 즉시 자동으로 고쳐지는 것도 아니고, 편집기가 실행 전에 미리 띄워주는 경고와도 다르다 — 실제로 돌아가는 중에 터지는 에러라는 게 핵심이다.

### | TypeScript — AltJS의 대표주자 |

- **타입스크립트**는 마이크로소프트가 개발한 오픈소스 언어로, 자바스크립트에 정적 타입 기능을 더한 언어다. 자바스크립트를 확장하는 형태로 설계되어 있으며, 모던 프론트엔드 개발의 표준으로 자리 잡은 대표적인 **AltJS**다.
- **AltJS(Alternative JavaScript)**란 자바스크립트의 단점을 해결하고자 등장한 '대안 언어'들을 통칭한다. 브라우저는 자바스크립트만 이해할 수 있으므로, AltJS로 만든 코드는 실행 전에 자바스크립트로 변환하는 과정을 거친다.

### | 타입스크립트가 대세가 된 이유 |

| 특징 | 설명 |
| --- | --- |
| 높은 개발 생산성 | 컴파일 시점에 에러를 빠르게 발견하여 코드의 안정성을 향상 |
| 완벽한 상위 호환성(Superset) | 자바스크립트의 문법을 그대로 포함하고 확장한 형태 |
| 낮은 도입 비용 | 기존 자바스크립트 코드를 그대로 가져와도 작동하므로 부드러운 전환이 가능 |

# PART 2. 자바스크립트와 타입스크립트의 차이 — 트랜스파일

### | 트랜스파일(Transpile) vs 컴파일(Compile) |

- 타입스크립트 코드는 빌드 도구를 통해 최종적으로 자바스크립트로 변환되어 실행된다. 웹 브라우저는 자바스크립트만 읽을 수 있기 때문에, 타입스크립트라는 독립된 소스코드를 자바스크립트로 바꾸어 주는 특별한 변환 단계(**트랜스파일러**, Transpiler)가 필요하다.

| 구분 | 설명 |
| --- | --- |
| 트랜스파일(Transpile) | 하나의 프로그래밍 언어로 작성된 소스코드를 비슷한 수준의 다른 프로그래밍 언어로 변환(Source-to-Source)하는 작업 |
| 컴파일(Compile) | 사람이 읽는 텍스트 코드를 컴퓨터가 직접 처리하는 0과 1 기반의 '기계어'로 바꾸는 작업 |

- 컴파일이 사람 코드를 기계어로 바꾸는 광범위한 작업이라면, 타입스크립트는 기계어가 아닌 '자바스크립트 코드'로 변환되므로 명확히는 **트랜스파일**에 해당한다.
- 최종 결과물은 순수한 자바스크립트 형태로 치환되어 브라우저에서 실행되므로, 언어가 하나 추가됐다고 해서 작동 속도가 느려지거나 구동 성능이 달라지지 않는다.

### | 코드 구조 비교 (상위 호환성 확인) |

- 자바스크립트 코드를 작성할 때는 `script.js`처럼 `.js` 확장자를 썼다면, 타입스크립트 코드를 작성할 때는 `.ts` 확장자(예: `index.ts`)를 쓴다. 자바스크립트 코드는 타입스크립트 파일(`.ts`) 안에서도 수정 없이 그대로 읽히고 작동한다 — 이게 "상위 호환"이라는 말의 실체다.

```javascript
// JavaScript — 어떤 형태의 값이 들어올지 변수나 인수만 보고는 예측하기 어렵다
function sayHello(firstName) {
  console.log('Hello ' + firstName);
}
let firstName = 'Hana';
sayHello(firstName); // 실행 결과: Hello Hana
```

```typescript
// TypeScript — firstName 뒤에 ': string'을 붙여 문자열만 받도록 선언
function sayHello(firstName: string) {
  console.log('Hello ' + firstName);
}
let firstName: string = 'Hana'; // 변수에도 문자열 타입을 명시
sayHello(firstName); // 안전하게 데이터가 전달되어 실행됨
```

- 이 구조적 변환과 타입 검사는 타입스크립트 전용 트랜스파일러 도구인 **tsc(TypeScript Compiler)**가 담당한다. `.ts` 파일로 엄격하게 코드를 짜면, tsc가 에러를 검사한 뒤 브라우저가 읽을 수 있는 `.js` 파일로 번역해준다. (지금 단계에서는 tsc를 직접 수동 설치·설정하지 않는다. `tsconfig.json` 같은 정교한 설정은 교육과정 마지막 단계인 '10장. TypeScript 프로젝트 품질 관리'에서 다룬다.)

### | 타입스크립트의 주요 확장 기능 |

| 기능 | 설명 |
| --- | --- |
| 타입 정의 및 안정성 | 데이터의 종류를 고정하고 빈 값(`null`, `undefined`)으로 인해 프로그램이 멈추는 현상을 방지 |
| 고도화된 설계 지원 | 구조적 규격을 정의하는 인터페이스(Interface), 복잡한 데이터 모델을 위한 제네릭(Generic) 등을 지원 |
| 온라인 테스트 환경 | 설치 없이 바로 시험해 볼 수 있는 공식 TS Playground 제공 |
| 프레임워크 자동 변환 | Next.js 등 실제 웹 애플리케이션 개발 단계에서는 빌드 도구가 변환 과정을 자동 처리 |

### | 장단점 |

| 장점 | 단점 |
| --- | --- |
| 컴파일 시점의 빠른 에러 발견, 대규모 개발에 적합한 높은 모듈성, 최신 자바스크립트 사양 선제 도입 | 프로젝트 규모가 커질수록 변환(컴파일) 시간 소요, 사전 학습 필요 |

# PART 3. 개발 환경 구축 — nvm으로 독립 환경 분리하고 tslab 설치하기

### | 왜 새 Node.js 버전을 또 까는가 |

- 지금 컴퓨터에는 Node.js 20 버전 기반의 자바스크립트 전용 주피터 커널(`ijavascript`)이 이미 구동되고 있다. 여기에 기존 설정을 그대로 두면서 타입스크립트 실습 환경을 추가로 올리려면, **nvm**으로 Node.js 24 버전을 독립적으로 구축하고 그 위에 타입스크립트 전용 커널(**tslab**)을 설치해야 한다.
- 한 컴퓨터 안에서 여러 환경 설정이 충돌하면, 이전에 잘 작동하던 코드까지 실행되지 않는 오류가 생길 수 있다. Node.js 24는 이번 타입스크립트 과정뿐 아니라 추후 React/Next.js의 최신 서버 사이드 렌더링(SSR) 빌드 환경과도 호환되므로, 미리 올려두면 환경 충돌 없이 확장성을 갖출 수 있다.

### | 설치 순서 |

```bash
# 1단계: Node.js 24 버전 다운로드 (nvm으로 시스템 충돌 방지)
nvm install 24

# 2단계: 현재 터미널의 기본 실행 버전을 24로 전환
nvm use 24

# 3단계: tslab 전역 설치 — 주피터 파일 안에서 TS 문법을 실시간으로 검사·실행해줄 변환기
npm install -g tslab

# 4단계: 설치된 tslab을 VS Code Jupyter 확장이 커널로 인식하도록 시스템에 등록
uv run --with jupyter tslab install
```

### | 첫 TypeScript 코드 실행하기 |

- 주피터 파일 내부에서는 각 코드 구역(셀)이 독립적으로 실행되므로 부분 테스트가 편리하다. `chapter01` 폴더를 만들고 `01.ipynb`로 저장한 뒤, 에디터 우측 상단 [커널 선택]에서 **TypeScript (tslab)**을 지정하고 실행한다.

```typescript
// 변수를 만들 때 어떤 종류의 데이터(타입)를 담을지 명시적으로 선언한다.
let studentName: string = "홍길동";
let attendanceScore: number = 95;

console.log(`학생 이름: ${studentName}`);
console.log(`출석 점수: ${attendanceScore}점`);

// 약속과 다른 종류의 데이터를 강제로 넣으려 하면 실행 전에 차단된다.
//attendanceScore = "결석 처리"; // 오류: 숫자형 변수에 문자열을 넣을 수 없음
```

- 주석을 해제하면 코드에 빨간 줄로 경고가 뜬다 — 실행도 해보기 전에 에디터 단계에서 바로 잡아주는 게 타입스크립트의 핵심 가치다.
- 커널 선택 메뉴에서 **TypeScript (tslab)**가 제대로 지정돼 있는지는, 실행 버튼을 눌러도 반응이 없을 때 가장 먼저 확인해야 하는 항목이다.

# PART 4. 원시 타입, 배열, 튜플

### | 원시 타입(Primitive Type)이란 |

- 더 이상 세부적으로 분해할 수 없는 데이터의 최소 단위를 의미하며, 하나의 변수에 단 하나의 값만 할당되는 형태다. `boolean`, `number`, `string`, `null`, `undefined`가 독립적인 원시 타입에 속하고, 여러 데이터를 구조화해 관리하는 `Array`·`Tuple`은 그 상위 자료형에 속한다.

### | string / number / boolean |

```typescript
let menuName: string = "아이스 아메리카노"; // 글자 데이터를 담는 주머니 선언
let menuPrice: number = 4500;             // 숫자 데이터를 담는 주머니 선언
let isIceDrink: boolean = true;            // 참/거짓 논리값을 담는 주머니 선언

console.log(`메뉴명: ${menuName}`);
console.log(`가격: ${menuPrice}원`);
console.log(`아이스 여부: ${isIceDrink}`);
```

| 타입 | 설명 |
| --- | --- |
| `string` | 텍스트 데이터. 작은따옴표(`'`), 큰따옴표(`"`), 백틱(`` ` ``)으로 감싸서 선언 |
| `number` | 정수, 소수점 이하 수 등 모든 종류의 숫자 데이터 |
| `boolean` | `true`/`false` 중 하나만 가질 수 있는 참/거짓 상태 |

### | null과 undefined |

```typescript
let discountCoupon: string | null = null;  // 현재는 사용 가능한 쿠폰이 없음을 "의도적으로" 명시
let serverResponse: undefined = undefined; // 데이터가 채워지지 않은 초기 상태

console.log(`쿠폰 상태: ${discountCoupon}`);
console.log(`응답 상태: ${serverResponse}`);
```

| 타입 | 설명 |
| --- | --- |
| `null` | 값이 없음을 **명시적으로** 나타내기 위해 의도적으로 할당하는 상태 |
| `undefined` | 변수를 선언한 후 값이 할당되지 않았을 때 시스템이 부여하는 **기본** 상태 |

### | 배열(Array) 타입 정의하기 |

- 데이터 타입이 동일한 복수의 요소를 순차적으로 나열해 관리하는 선형 자료구조다.

```typescript
let orderPrices: number[] = [4500, 5000, 5500];          // 대괄호 표기법 (Type[])
let drinkMenus: Array<string> = ["라떼", "모카", "민트초코"]; // 제네릭 표기법 (Array<Type>)

orderPrices.push(6000); // 같은 타입끼리는 정상적으로 추가 가능

console.log("가격 리스트:", orderPrices);
console.log("메뉴 리스트:", drinkMenus);
```

| 표기법 | 설명 |
| --- | --- |
| 대괄호 표기법 `Type[]` | 변수 타입 식별자 뒤에 `[]`를 붙여 해당 타입 요소로 구성된 배열임을 명시 |
| 제네릭 표기법 `Array<Type>` | 전역 객체 `Array`에 제네릭 문법을 사용해 내부 요소의 타입을 정의 |

### | 튜플(Tuple) — 길이와 순서까지 고정된 배열 |

- 배열 형식을 취하지만, 포함될 요소의 총 개수(길이)와 각 인덱스에 위치할 데이터 타입을 명확히 제한하는 구조다.

```typescript
// 인덱스 0번에는 number, 인덱스 1번에는 string 타입을 가지는 2개 길이의 튜플 선언
let userProfile: [number, string] = [1004, "김회원"];

// 타입을 위반하거나 길이를 벗어나면 컴파일 오류가 발생한다.
// userProfile = ["김회원", 1004]; // 컴파일 에러: 인덱스 0번은 number 타입이어야 함

console.log(`회원번호: ${userProfile[0]}`);
console.log(`회원이름: ${userProfile[1]}`);
```

- 각 인덱스마다 정해진 타입이 일치해야 하고, 지정된 길이를 벗어나는 할당도 막힌다. 리액트에서 컴포넌트 상태 값과 그 상태를 바꾸는 함수를 정해진 순서로 반환하는 구조(`useState`)가 바로 이 튜플 구조를 기반으로 한다.

# PART 5. 특수 타입 — any, unknown, never

### | any — 타입 검사 자체를 꺼버리는 타입 |

```typescript
let flexibleValue: any = "정산 완료";
flexibleValue = 10000; // 숫자를 대입해도 컴파일 에러가 발생하지 않는다
flexibleValue = true;  // 불리언을 대입해도 정상 허용

// 존재하지 않는 메서드를 호출해도 컴파일 시점엔 에러를 감지하지 못한다
flexibleValue.calculateTotalScores();
```

- 모든 종류의 데이터를 대입할 수 있지만, 컴파일러가 타입 오류를 감지하지 않으므로 실행 시점(런타임)에 오류가 발생할 수 있다 — 사실상 자바스크립트처럼 쓰게 되는 셈이라 안전성이 낮다.

### | unknown — 검증 전엔 손도 못 대게 막는 타입 |

```typescript
let rawResponse: unknown;

// typeof 연산자를 활용한 원시 타입 좁히기
rawResponse = "  TypeScript  ";
if (typeof rawResponse === "string") {
    // 이 블록 안에서는 rawResponse가 string으로 확정되어 문자열 메서드를 쓸 수 있다
    console.log("문자열 처리:", rawResponse.trim());
}

// Array.isArray()를 활용한 배열 타입 좁히기
rawResponse = [10, 20, 30];
if (Array.isArray(rawResponse)) {
    const doubled = rawResponse.map((num: number) => num * 2);
    console.log("배열 처리 결과:", doubled);
}
```

- `any`와 동일하게 모든 종류의 데이터를 대입할 수 있지만, 정체를 확인하기 전에는 사용을 제한하는 안전한 타입이다. 외부 API 응답처럼 형식을 미리 알 수 없는 데이터를 다룰 때, 컴파일 시점의 안정성을 보장하기 위해 쓴다.
- **타입 좁히기(Type Narrowing)**란 조건문을 통해 컴파일러에게 특정 변수의 타입을 명확히 입증해서, 그 블록 안에서 안전하게 데이터에 접근할 수 있도록 허용하는 과정이다.

| 대상 데이터 | 검증 방식 | 설명 |
| --- | --- | --- |
| 원시 타입 | `typeof` 연산자 | `string`, `number`, `boolean` 등 기본 타입 판별 |
| 배열 구조 | `Array.isArray()` | 데이터가 배열 형식인지 검증 |
| 객체·커스텀 타입 | 사용자 정의 타입 가드 | `is` 키워드로 객체 내부 속성 구조를 직접 검증 |

### | any보다 unknown을 써야 하는 이유 |

| 비교 항목 | any 타입 | unknown 타입 |
| --- | --- | --- |
| 값의 할당 | 모든 타입의 값을 대입할 수 있음 | 모든 타입의 값을 대입할 수 있음 |
| 속성·메서드 접근 | 타입 검사 없이 즉시 접근 가능 | 타입 좁히기 전에는 접근 불가능 (컴파일 에러) |
| 안전성 수준 | 낮음 (자바스크립트와 동일하게 오류 위험 노출) | 높음 (컴파일러가 사전 검증을 강제) |

- `any`를 쓰면 타입스크립트의 정적 분석 기능이 무력화되어, 오타나 잘못된 메서드 호출을 컴파일 시점에 잡아낼 수 없다. 정체를 알 수 없는 데이터는 일단 `unknown`으로 선언한 뒤 타입 좁히기로 구체적인 타입을 찾아내는 게 올바른 설계 방향이다.

### | never — 값을 아예 가질 수 없는 타입 |

```typescript
function triggerSevereError(message: string): never {
    throw new Error(message); // 값을 반환하며 종료되지 않고 예외를 발생시킨다
}

function processInfiniteLoop(): never {
    while (true) {
        console.log("프로세스 실행 중"); // 조건이 계속 참이라 종료 지점에 도달하지 않는다
    }
}
```

- 값을 가질 수 없으며, 함수의 실행이 정상적으로 종료되지 않음을 의미하는 타입이다. 의도적으로 예외를 던지거나 무한 루프를 실행하는, 반환값 자체가 존재하지 않는 함수에 지정한다.

### | 타입 계층 구조 |

- **최상위 타입(Top Type)**: `unknown`은 시스템의 모든 데이터 타입을 포함할 수 있는 상위 계층의 타입이다.
- **최하위 타입(Bottom Type)**: `never`는 어떤 값도 포함하지 않는 하위 계층의 타입이다.

# PART 6. 타입 추론과 타입 단언

### | 타입 추론(Type Inference) |

- 타입을 직접 명시하지 않아도, 대입된 초기값을 기준으로 컴파일러가 타입을 자동 지정하는 메커니즘이다. 변수를 선언하는 동시에 값을 대입하면 컴파일러가 데이터 형식을 분석해 타입을 고정하고, 이후에는 다른 타입의 데이터를 대입할 수 없다.

```typescript
let regularPrice = 45000;    // 숫자가 대입됐으므로 number 타입으로 추론
let accountId = "user_7789"; // 문자열이 대입됐으므로 string 타입으로 추론

regularPrice = "품절상태"; // 컴파일 에러: 'string' 형식을 'number' 형식에 할당할 수 없음
```

```typescript
let accumulatedScore = 250;  // number로 추론
let isLevelCleared = false;  // boolean으로 추론

accumulatedScore = 320;      // 같은 타입이므로 정상 할당
isLevelCleared = true;       // 같은 타입이므로 정상 할당

// accumulatedScore = "게임종료"; // 에러: 'string' 형식을 'number' 형식에 할당할 수 없음
```

### | 타입 단언(Type Assertion) — as 키워드 |

- 컴파일러가 유추하는 타입보다 개발자가 데이터의 타입을 더 명확히 알고 있을 때, 컴파일러에게 특정 타입으로 간주하라고 직접 지시하는 구문이다. **형 변환(Type Casting)과 달리 실제 런타임 데이터를 바꾸지 않으며, 오직 컴파일 시점의 타입 검사만 재정의한다.**

```typescript
let unknownData: unknown = "TypeScript 5.0";
// 컴파일러는 unknownData의 속성을 모르지만, 개발자가 string임을 확신하여 단언
let strLength: number = (unknownData as string).length;
console.log("문자열 길이:", strLength);
```

```typescript
// JSON·API 응답처럼 내부 구조를 컴파일러가 모르는 데이터에 단언을 적용하는 예
interface UserProfile {
    id: number;
    name: string;
    role: string;
}

const rawJsonData = '{"id": 101, "name": "김스파르타", "role": "admin"}';
const user = JSON.parse(rawJsonData) as UserProfile; // JSON.parse 결과를 UserProfile로 단언

console.log("사용자 ID:", user.id);
console.log("사용자 이름:", user.name);
console.log("권한:", user.role);
```

### | 타입 단언을 쓸 때 주의할 점 |

```typescript
let rawNumber: unknown = 12345;

// 실제 값은 숫자지만 개발자가 string으로 잘못 단언 (컴파일 타임엔 감지 못 함)
let wrongAssertedStr = rawNumber as string;

// 실행 시점에 toUpperCase 함수가 없어 런타임 에러 발생!
console.log(wrongAssertedStr.toUpperCase()); // TypeError: wrongAssertedStr.toUpperCase is not a function
```

- 타입 단언은 컴파일러의 타입 검사기를 강제로 우회하는 기능이며, 자바스크립트로 변환될 때 삭제된다. 실제 데이터가 숫자인데 `as string`으로 단언해도 런타임에 숫자가 문자열로 바뀌지는 않는다 — 단언은 "컴파일러를 설득하는 말"일 뿐, 데이터 자체를 바꾸는 명령이 아니다. 그래서 외부 데이터의 형식을 100% 확신할 수 있는 상황에서만 제한적으로 써야 한다.

내 제출 답안 : d. 인터페이스와 타입 별칭은 기능상 완전히 동일하여 구분할 필요가 없다 (오답 ❌)
