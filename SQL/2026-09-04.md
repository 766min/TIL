## 공부한 내용 | SQL - 데이터 조회하기 (SELECT, WHERE, CASE WHEN, ORDER BY)

- 데이터베이스에는 수많은 데이터가 저장되어 있지만, 필요한 데이터만 골라서 보려면 SQL 쿼리를 작성해야 한다.

- SELECT와 FROM으로 원하는 열을 고르고, WHERE로 조건을 지정하고, ORDER BY로 결과를 정렬하는 흐름을 익히면 데이터 조회의 기본기는 모두 갖추게 된다.

### | SQL 기본 구조 : SELECT, FROM

- SELECT문은 테이블에서 원하는 열(Column)을 선택해 데이터를 조회할 때 사용한다.

- FROM은 데이터를 가져올 테이블 이름을 지정한다.

- 아스테리크(`*`)를 사용하면 모든 열을 한번에 가져올 수 있다.

- 쿼리 마지막은 세미콜론(`;`)으로 끝내며, 여러 쿼리를 작성할 때 특정 쿼리만 실행하려면 커서를 해당 위치에 두고 Ctrl+Enter를 누르면 된다.

```sql
-- 모든 열 조회
SELECT *
FROM 테이블이름;

-- 특정 열만 조회
SELECT 열이름, 열이름
FROM 테이블이름;
```

- `SELECT *`를 쓰면 편한데, 실무에서도 많이 사용할까 ?

  - 실무에서는 `SELECT *`보다 필요한 열만 명시하는 방식을 권장한다. 이유는 세가지다.

    1. 불필요한 데이터를 모두 가져와 성능이 저하될 수 있다.
    2. 테이블 구조가 변경되면 예상치 못한 열이 포함될 수 있다.
    3. 코드 가독성이 떨어져 유지보수가 어렵다.

  - 학습 단계에서는 `SELECT *`가 편리하지만, 필요한 열만 명시하는 습관을 들이는게 좋다.

##### | SELECT, FROM, WHERE는 전부 DML일까 ? — DQL이라는 분류도 있음

- **SELECT는 명령어(Command)** 고, DML 안에 포함되어 정리했다. 근데 어떤 교재에서는 SELECT만 따로 떼서 **DQL(Data Query Language, 데이터 질의어)**이라는 별도 카테고리로 분류하기도 한다.

- 근데 **DQL 카테고리에 속하는 명령어는 SELECT 딱 하나뿐** 이다.

| 카테고리 | 소속 명령어 |
| --- | --- |
| DDL | CREATE, ALTER, DROP |
| DML | INSERT, UPDATE, DELETE |
| DQL | SELECT (이거 하나) |

- `FROM`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`는 DQL에 속한 "또 다른 명령어들"이 아니라, **SELECT라는 명령어 하나를 완성하기 위해 붙는 부속 문법(절, Clause)**이다. CREATE, INSERT처럼 독립적으로 쓸 수 있는게 아니라, 반드시 SELECT(또는 UPDATE, DELETE) 뒤에 붙어서 그 명령어를 구체화해주는 조각일 뿐이다.

-> 정리하면 : **"DQL = SELECT"**이고, FROM~ORDER BY는 그 SELECT 하나를 이루는 구성요소들이다.

### | 중복 제거 : DISTINCT

- 열 값에 중복이 있을 때, `DISTINCT`를 사용하면 고유한 값만 남겨서 조회할 수 있다.

- 예를 들어 요일 열에 '월요일'이 여러번 반복된다면, DISTINCT를 쓰면 '월요일'을 한번만 보여준다.

```sql
-- 중복 없이 특정 열 조회
SELECT DISTINCT 열이름
FROM 테이블이름;
```

### | SQL 조건문 : WHERE

- 테이블의 모든 데이터가 아니라, 특정 조건을 만족하는 행만 조회하고 싶을 때 WHERE절을 사용한다.

- WHERE는 FROM 뒤에 작성하며, 조건식이 참(TRUE)인 행만 결과에 포함된다.

```sql
-- WHERE절로 조건 지정
SELECT *
FROM 테이블이름
WHERE 조건;

-- 예시: 성별이 F인 데이터만 조회
SELECT *
FROM basic.theglory
WHERE 성별 = 'F';
```

- WHERE절에서 여러 조건을 동시에 사용할 수 있을까 ?

  - `AND`와 `OR` 연산자로 여러 조건을 조합할 수 있다. AND는 두 조건을 모두 만족하는 경우, OR는 둘 중 하나라도 만족하는 경우를 조회한다.

  - SQL은 `AND`를 `OR`보다 먼저 계산한다(수학에서 곱셈을 덧셈보다 먼저 계산하는 것과 비슷함). 그래서 AND와 OR을 섞어 쓸 때는 **우선순위를 명확히 하기 위해 괄호`()`를 꼭 써야 한다.**

```sql
-- 괄호 없이 쓰면 위험한 예
SELECT *
FROM basic.theglory
WHERE 직업 = '가수' OR 직업 = '배우' AND 나이 < 30;
```
  - 사람이 읽기엔 "가수거나 배우인데, 나이가 30 미만"처럼 보이지만, SQL은 AND를 먼저 계산해버려서 실제로는 "가수다" `OR` ("배우이면서 나이가 30 미만이다")로 해석된다. 그래서 30세 이상인 가수까지 전부 걸려버리는 의도치 않은 결과가 나온다.

```sql
-- 괄호로 우선순위를 명확히 정해준 올바른 예
SELECT *
FROM basic.theglory
WHERE (직업 = '가수' OR 직업 = '배우')
  AND 나이 < 30;
```
  - 이렇게 괄호로 묶어야 "가수 또는 배우인 사람들 중에서, 나이가 30 미만인 사람"이라는 원래 의도대로 정확히 계산된다.

  - ⚠️ 참고 : 아래처럼 **AND만 쭉 나열된 경우**는 계산 순서가 결과에 영향을 안 주기 때문에(어느 순서로 계산해도 "전부 다 만족해야 함"은 똑같음), 괄호는 우선순위를 바꾸는게 아니라 그냥 "이 조건 하나는 여기부터 여기까지야"라고 보기 쉽게 나눠주는 가독성용 표시일 뿐이다.

```sql
SELECT *
FROM basic.theglory
WHERE 날짜 IS NOT NULL
  AND (성별 != 'M')
  AND (직업 IN ('아나운서', '승무원', '화가'))
  AND (나이 BETWEEN 30 AND 40);
```

### | SQL 조건문 : CASE WHEN

- `CASE WHEN`은 조건에 따라 서로 다른 결과값을 반환하는 조건부 표현식이다.

- 프로그래밍의 if-else와 유사한 개념으로, SELECT절에서 새로운 열을 만들 때 주로 활용한다.

- WHEN 조건은 여러개 추가할 수 있으며, 모든 조건을 만족하지 않으면 ELSE 값이 반환된다.

```sql
SELECT CASE WHEN 조건식1 THEN 결과1
            WHEN 조건식2 THEN 결과2
            ELSE 결과3
       END AS 새로운열이름
FROM 테이블명;

-- 예시: 역할 구분 열 추가
SELECT *,
       CASE WHEN 이름 IN ('문동은', '주여정') THEN '선'
            ELSE '악'
       END AS 역할구분
FROM basic.theglory;
```

- CASE WHEN 절의 작동 순서 : 가장 상단에 위치하는 WHEN을 우선으로 하여 참과 거짓을 구분하고, 그 다음 WHEN절을 순서대로 수행하고, 마지막으로 ELSE절을 수행한다.

##### | WHERE랑 CASE WHEN은 뭐가 다를까 — "행을 없애는 것" vs "값을 바꿔서 보여주는 것"

| 구분 | WHERE | CASE WHEN |
| --- | --- | --- |
| 하는 일 | 조건에 안 맞는 행을 아예 결과에서 빼버림(필터링) | 조건에 따라 값을 다르게 보여줌(라벨링/변환) |
| 결과 행 개수 | 조건에 안 맞으면 줄어듦 | 조건과 상관없이 원래 행 개수 그대로 |
| 쓰이는 위치 | SELECT문 어디서든 (FROM 뒤) | 보통 SELECT절 안에서 새 컬럼 만들 때 |

- 예 : books 표에 `id=1(18000원)`, `id=2(80원)` 두 행이 있다고 하면

```sql
-- WHERE : 조건에 안 맞는 행은 아예 사라짐
SELECT * FROM books WHERE price < 100;
-- 결과 : id=2 한 줄만 남음 (id=1은 결과에서 통째로 없어짐)
```

```sql
-- CASE WHEN : 모든 행이 남아있고, 값만 다르게 표시됨
SELECT title, price,
       CASE WHEN price < 100 THEN '저가' ELSE '고가' END AS price_grade
FROM books;
-- 결과 : id=1, id=2 둘 다 그대로 남고, price_grade 값만 각각 '고가'/'저가'로 다르게 붙음
```

- 비유 : **WHERE** = "이 조건에 안 맞는 사람은 아예 입장 금지"(문지기), **CASE WHEN** = "일단 다 들여보내는데 조건에 따라 이름표만 다르게 붙여줌"(이름표 붙이는 사람)

### | 조건문을 지원하는 연산자

- SQL 조건문은 비교 연산자, 논리 연산자, 범위 연산자 등 다양한 연산자를 지원한다.

| 연산자 | 의미 | 예시 |
| --- | --- | --- |
| `>`, `<` | N이 10 초과, N이 10 미만 | N<10, N>10 |
| `>=`, `<=` | N이 10 이상, N이 10 이하 | N<=10, N>=10 |
| `=` | N이 10인 값 | N=10 |
| `!=` | N이 10이 아닌 값 | N!=10 |
| `LIKE` | 해당 문자열을 포함하는 값 (앞뒤 % 활용) | LIKE('%과자%') |
| `AND` | A와 B 조건 모두 만족 | A AND B |
| `OR` | A 또는 B 조건 하나라도 만족 | A OR B |
| `NOT`, `!` | A가 아닌 값 | NOT A, !A |
| `BETWEEN` | 10 이상 20 이하 | A BETWEEN 10 AND 20 |
| `IN` | B 목록에 A가 포함된 값 (괄호 필수) | A IN (B) |
| `NOT IN` | B 목록에 A가 포함되지 않은 값 | A NOT IN (B) |
| `IS NULL` | A가 비어있는 값 | A IS NULL |
| `IS NOT NULL` | A가 비어있지 않은 값 | A IS NOT NULL |

- `IN (값1, 값2, ...)`은 사실 `OR` 여러개를 짧게 줄여쓴 문법이다. `직업 IN ('아나운서', '승무원')`은 `직업 = '아나운서' OR 직업 = '승무원'`과 완전히 같은 뜻. 콤마는 "그리고(AND)"가 아니라 "~이거나(OR)"를 나열하는 구분자다.

- 혼동하기 쉬운 `IN`과 `LIKE`의 차이

- 가정 : customers 표의 name 컬럼에 아래 값들이 저장되어 있다고 했을 때

| id | name |
| --- | --- |
| 1 | 전소현 |
| 2 | 전소현안녕 |
| 3 | 바이전소현 |

- 이 값들에 각각 `LIKE ('%전소현%')`와 `IN ('전소현')`을 적용해보면 결과가 다르게 나온다.

| name 컬럼의 값 | `WHERE name LIKE ('%전소현%')` | `WHERE name IN ('전소현')` |
| --- | --- | --- |
| '전소현안녕' | 집계됨 ('전소현'이라는 글자가 포함되어 있으니까) | 집계안됨 (완전히 똑같은 값이 아니니까) |
| '바이전소현' | 집계됨 ('전소현'이라는 글자가 포함되어 있으니까) | 집계안됨 (완전히 똑같은 값이 아니니까) |

  - LIKE는 '전소현'이라는 문자열 전후로 어떤 값이 와도 집계되지만(부분 일치), IN은 정확하게 문자열이 '전소현'인 경우만 집계된다(완전 일치).

- 위 연산자들은 동시에 사용이 가능하다. "날짜 데이터가 비어있지 않고, 성별이 남자가 아니고, 직업이 아나운서 또는 승무원 또는 화가이고, 나이가 30세에서 40세 사이"라는 조건을 SQL로 옮기면

```sql
SELECT *
FROM basic.theglory
WHERE 날짜 IS NOT NULL
  AND (성별 != 'M')
  AND (직업 IN ('아나운서', '승무원', '화가'))
  AND (나이 BETWEEN 30 AND 40) -- 30 이상, 40 이하
```
  - 연산의 우선순위를 명시하기 위해 각 조건에 괄호`()`를 작성하여 우선적으로 연산하고, 조건들을 모두 만족해야 하므로 AND 연산자로 묶어준다.

### | 결과값 정렬 : ORDER BY

- `ORDER BY`는 조회 결과를 특정 열(Column) 기준으로 정렬할 때 사용한다.

- SQL 구문 중 가장 마지막에 실행되며, 오름차순(`ASC`)과 내림차순(`DESC`)을 지정할 수 있다. 기본값은 오름차순(ASC)으로 생략 가능하다.

```sql
-- 나이 기준 오름차순 정렬 (기본값)
SELECT *
FROM basic.theglory -- 스키마.테이블
ORDER BY 나이;

-- 나이 기준 내림차순 정렬
SELECT *
FROM basic.theglory -- 스키마.테이블
ORDER BY 나이 DESC;

-- 다중 정렬: 날짜 내림차순 → 나이 오름차순
SELECT 날짜, 이름, 성별, 나이, 직업
FROM basic.theglory -- 스키마.테이블
ORDER BY 1 DESC, 4 ASC;
```

- 위 예시의 `ORDER BY 1 DESC, 4 ASC`에서 `1`, `4`는 컬럼 이름이 아니라 **SELECT에 나열한 컬럼의 순서 번호(위치)**를 가리킨다. `SELECT 날짜, 이름, 성별, 나이, 직업`이니까 1번째는 날짜, 4번째는 나이 → 즉 `ORDER BY 날짜 DESC, 나이 ASC`와 완전히 같은 뜻이다.

  - 다만 SELECT의 컬럼 순서가 나중에 바뀌면 번호가 가리키는 대상도 같이 바뀌어버려 헷갈리기 쉬우므로, 실무에서는 번호 대신 컬럼 이름을 직접 쓰는게 안전하다.

- ORDER BY에서 여러 열을 지정하면 어떤 순서로 정렬될까 ?

  - ORDER BY 바로 뒤에 오는 열이 최우선 정렬 기준이 된다. 앞 열 값이 같은 경우에만 다음 열 기준이 적용된다.

  - 예를 들어 `ORDER BY 날짜 DESC, 나이 ASC`는 날짜를 먼저 내림차순으로 정렬하고, 날짜가 같은 행들 사이에서만 나이를 오름차순으로 정렬한다.

  - 정렬 우선순위를 직관적으로 표현하기 위해 열 번호보다는 열 이름을 직접 쓰는걸 권장한다.

### | SQL 작성할 때 주의할 점 ①

- 따옴표 규칙

| 부호 | 기능 |
| --- | --- |
| `' '` (작은 따옴표) | 문자열을 나타낼 때 사용 (일반적으로 가장 많이 사용) |
| `" "` (큰 따옴표) | 마찬가지로 문자열을 나타낼 때 사용되나, DB마다 그 쓰임이 다름 |
| `` ` ` `` (백틱) | MySQL에서만 사용되며, 예약어(SELECT처럼 이미 쓰임이 정해진 단어)를 마치 문자열처럼 인식하여 사용하고 싶을때 사용 |

- `IF` 구문 vs `CASE WHEN` 비교

| 구분 | IF | CASE WHEN |
| --- | --- | --- |
| 사용가능 범위 | PostgreSQL 제외 사용 가능 | 모든 SQL에서 사용가능 |
| 목적 | 프로그래밍 로직 제어(Python에서 더 많이 사용) | SQL 조건부 연산 |
| 다중조건의 처리 | IF문 여러개 사용(가독성 하락) | 여러개의 WHEN 사용(가독성 높음) |

- 타입 변환(CAST) 참고표

| cast type | 타입변환 결과값 |
| --- | --- |
| BYTEA | 값을 binary로 변환 |
| CHAR | 값을 문자열로 변환 |
| DATE | 값을 yyyy-mm-dd의 date로 변환 |
| TIMESTAMP | 값을 yyyy-mm-dd hh:mm:ss의 datetime으로 변환 |
| TIME | 값을 hh:mm:ss의 time으로 변환 |
| DECIMAL | 값을 최대자릿수(M), 소수점 이하 자릿수(D)로 지정하여 decimal로 변환 |
| BIGINT | 값을 부호 있는 64비트 정수로 변환 |

### | 실습 문제

1. customers 테이블에서 고객 이름(first_name, last_name)과 이메일(email)을 조회하세요.
```sql
SELECT first_name, last_name, email
FROM customers;
```

### | 이번 강의 핵심 정리

1. SELECT와 FROM으로 원하는 열과 테이블을 지정해 데이터를 조회한다.
2. DISTINCT는 중복 값을 제거하고 고유한 값만 반환한다.
3. WHERE절로 조건을 지정해 필요한 행만 필터링할 수 있다.
4. CASE WHEN은 조건에 따라 다른 결과값을 부여하며, 위에서부터 순서대로 조건을 평가한다.
5. IN은 정확한 값 일치, LIKE는 패턴 포함, BETWEEN은 범위 조건에 사용한다.
6. ORDER BY는 결과를 오름차순(ASC) 또는 내림차순(DESC)으로 정렬하며, 여러 열을 순서대로 지정할 수 있다.

Q2. `WHERE name LIKE ('%전소현%')`와 `WHERE name IN ('전소현')`의 차이를 바르게 설명한 것은 ?

A. LIKE는 '전소현'이라는 문자열이 포함되기만 하면(부분 일치) 집계되지만, IN은 정확히 '전소현'이라는 값과 완전히 일치할 때만 집계된다.

-> 예를 들어 '전소현안녕', '바이전소현'은 LIKE('%전소현%') 조건에는 걸리지만, IN('전소현') 조건에는 걸리지 않는다.

Q3. CASE WHEN 절에서 여러 WHEN 조건을 작성했을 때, 값 판단 순서로 옳은 것은 ?

[ 보기 ]

a. 모든 WHEN을 동시에 검사한 뒤 가장 마지막으로 일치한 조건을 적용한다

b. 맨 위의 WHEN부터 순서대로 검사하다가 처음 만족하는 조건에서 멈춘다

c. ELSE를 먼저 검사한 뒤 WHEN을 검사한다

d. 무작위 순서로 WHEN을 검사한다

A. b.

-> CASE WHEN은 가장 상단에 위치한 WHEN부터 순서대로 참/거짓을 판단하며, 조건을 만족하는 WHEN을 만나면 그 결과를 반환하고 이후 조건은 검사하지 않는다. 아무 조건도 만족하지 않으면 마지막에 ELSE 값이 반환된다.

Q5. `ORDER BY 날짜 DESC, 나이 ASC`라고 작성했을 때 정렬되는 방식으로 옳은 것은 ?

Q1. 기본키(PK)와 외래키(FK)의 특징을 설명한 것으로 옳지 않은 것은 ?

[ 보기 ]

a. PK는 테이블 내에서 중복 값이 존재할 수 없고 NULL 값을 가질 수 없다

b. FK는 다른 테이블의 PK를 참조하는 열이다

c. 하나의 테이블에는 FK가 여러 개 존재할 수 있다

d. 하나의 테이블에는 PK가 여러 개 독립적으로 존재할 수 있다

내 제출 답안 : d. (정답 ✅)

-> PK는 테이블당 하나만 존재하며, 여러 열을 조합해 복합키로 구성할 수는 있지만 여러 개의 독립된 PK가 존재하는 것은 아니다. 나머지 선지는 PK, FK의 규칙과 일치한다.

Q2. FK가 참조하는 값이 반드시 참조 대상 테이블의 PK에 존재해야 한다는 규칙을 무엇이라고 하나요 ?

내 제출 답안 : 참조무결성 (정답 ✅)

-> 참조 무결성은 FK가 참조하는 값이 반드시 참조 대상 테이블의 PK에 존재해야 한다는 규칙으로, 존재하지 않는 값을 참조하는 데이터는 저장될 수 없게 하여 데이터 간 관계를 유효하게 유지한다.
